# 2026-10-21 — v0.4.0: 남은 결함 봉합 (이어서)

[2026-10-20](2026-10-20.md) 에 이어 남은 결함을 고친다. 결함 묶음마다 E2E 로 확인하고 dev 에 머지한 뒤 멈춰서
보고한다.

## 변환기 구조 결함 묶음 (`fix/converter-structure`)

증상:

- C3 — Notion 에서 목록 항목 a 아래에 하위 항목 b 와 문단을 두고 받으면(`- a` · `    - b` · `    text`) Obsidian
  이 그 문단을 b 의 글에 이어 그렸다. a 의 문단이 b 안에 보였다.
- N9 — 두 단계 이상 깊은 목록 자식 문단(`\t\ttext`)을 받으면 목록에서 떨어져 앞뒤에 빈 줄이 들어가고 탭이 남았다.
- C4 — 글 없는 콜아웃의 첫 자식이 이미지 · 목록 · 제목 · 코드 · 표 · 빈 블록이면 그 줄을 콜아웃 제목으로
  올렸다(`> [!tip] ![](…)`). 빈 블록은 `<empty-block/>` 태그가 제목에 그대로 남았다. 코드 · 표는 몸통 줄만 한
  단계 깊어져 push 하면 다른 글이 됐다.
- N7 — 목록 · 콜아웃 안 동영상 · 소리 · 파일 · PDF(`\t<video src>`)를 받으면 들여쓰기를 잃고 목록 밖 문단이
  됐다. 콜아웃 안 목록의 동영상은 push 때 `</callout>` 밖으로 나갔다.
- C5 — 인용 · 문단 · 임베드 아래 자식을 빈 줄 뒤 네 칸으로 쓴 노트(옛 pull 이 쓴 모양)는 Obsidian 이 들여쓴 코드
  상자로 그린다. pull 은 이 로컬 표기를 「보낼 꼴이 같다」며 그대로 남겼다.
- C2(S-23) — 일반 인용 안 코드(`> ```js` · `> x` · `> ````)를 push 하면 Notion 에 코드가 없고 글이 펜스 기호인
  인용 블록들이 생겼다.

원인:

- C3 — Obsidian 은 더 깊은 항목 바로 뒤의 얕은 줄을 그 항목 글의 이어지는 줄로 읽는다(2026-10-21 Obsidian
  1.13.7 실측). 빈 줄만 이어 붙이기를 끊는다 — `%%…%%` · `<!-- -->` 줄은 끊지 못한다.
- N9 — BlockSpacer 의 목록 자식 정규식이 탭 하나만 알았다.
- C4 — 콜아웃 첫 줄을 늘 제목으로 봤다. Notion 은 첫 줄이 맨 문단일 때만 콜아웃의 글로 읽는다.
- N7 — `convertMediaTags` 정규식이 줄머리 공백까지 삼켰다.
- C5 — 받은 글과 로컬 글을 「보낼 꼴」(`sentForm`)로만 견줬다. Notion 은 빈 줄을 버리고 깊이만 보므로 네 칸
  자식과 두 칸 자식이 같은 꼴이 된다. Obsidian 이 다르게 그리는 것은 견주지 않았다.
- C2 — Notion 은 인용의 `>` 한 줄을 인용 블록 하나로 읽는다(2026-10-04 실측).

수정:

- C3 — BlockSpacer 가 더 깊은 항목 · 그 자식 글 바로 뒤의 얕은 글 앞에 빈 줄을 넣는다(`continuesListParagraph`).
  빈 줄 때문에 그 목록은 느슨한 목록(`<p>`)으로 그려진다 — 빈 줄 말고는 끊는 방법이 없다.
- N9 — 목록 자식 정규식이 탭 여럿을 받는다.
- C4 — 콜아웃 첫 줄이 맨 문단이 아니면(`startsWithParagraph`, `nfmToBlocks` 와 같은 판정) 제목을 비우고 몸통
  줄로 둔다. 코드 · 표가 첫 자식이어도 제목 있는 콜아웃과 같은 모양이 된다.
- N7 — 미디어 정규식이 줄머리 공백을 건드리지 않는다. 이미지 · 임베드와 같다.
- C5 — pull 이 로컬 표기를 남길지 견줄 때 Obsidian 이 다르게 읽는 줄도 견준다 — 들여쓴 코드로 그리는 줄
  (`indentedCodeLineMask`)과 앞 항목 글에 이어 붙는 줄. 둘이 다르면 받은 글을 쓴다. push 는 바꾸지 않았다 —
  네 칸 자식을 코드로 보내면 Notion 의 자식이 코드로 바뀐다.
- C2 — push 가 일반 인용 안 닫힌 펜스를 앞 인용 줄의 자식으로 꺼낸다(`quotedCodeToChildren`). 모양은 pull 이
  인용의 자식을 쓰는 꼴(빈 줄 뒤 두 칸)과 같아 pull 이 로컬의 `> ```` 표기를 남긴다. 인용이 코드로 시작하면 빈
  인용 줄을 부모로 둔다. 콜아웃 · 중첩 인용 · 닫히지 않은 펜스는 그대로다.
- ADR-023 의 「블록 경로의 martian 은 `$ x $` 를 수식으로 읽는다」 줄을 고쳤다 — 블록 방식도 같은 NFM 을 만든다
  (ADR-035).

검증:

  시험 9개는 모듈이 없어 파일째). 나머지 2개는 바꾸지 말아야 할 모양을 지키는 시험이다.
- 변이 29개를 모두 잡았다. 처음 살아남은 1개(탭 폭을 글자 수로 세기)는 시험을 더해 잡았다. 인용 코드 마스크를

## push 의 링크 묶음 (`fix/push-links`)

증상:

- N6 — Markdown API 경로에서 볼트의 북마크 링크가 그 페이지에 없는 블록을 가리키면 그 노트의 push 가 통째로
  실패했다. 볼트 노트를 복사해 새 노트로 올릴 때, 받은 노트를 다른 루트로 올릴 때(C14 E2E 에서 발견), 다른
  노트의 북마크 줄을 붙여 넣고 올릴 때다. 커스텀 이모지(`<unknown_mention>`)가 있는 노트를 새 페이지로 올려도
  같았다.
- N8 — 첫 push 에서 같은 push 의 뒤에 만들어지는 노트로 가는 `[[위키링크]]` 가 멘션 대신 `[[B]]` 글로 올라갔고,
  그 노트를 고치기 전까지 그대로였다. 서로를 가리키는 두 노트는 차례와 무관하게 하나가 늘 글이었다.

원인:

- N6 — 북마크 · 바로가기 같은 블록은 볼트에 링크와 보존 마커로 남고, push 는 마커를 받은 자리 태그
  (`<unknown url="…/p/<페이지>#<블록>"/>`)로 되돌려 Notion 이 그 블록을 남기게 한다. Notion 은 이 태그로 블록을
  새로 만들지 못한다 — 그 페이지에 없는 블록을 가리키면 본문 전체를 거절한다. 2026-10-21 실측:

  | 보낸 것                                 | Notion 의 답                                                          |
  | --------------------------------------- | --------------------------------------------------------------------- |
  | 같은 페이지의 블록 태그로 본문 교체     | 적용 · 블록 그대로                                                    |
  | 다른 페이지의 블록 태그로 새 페이지     | `Cannot create database reference: Block … does not exist`            |
  | 다른 페이지 · 없는 · 지운 블록으로 교체 | `The update page tool cannot safely create new <unknown .../> blocks` |
  | `<unknown_mention>` 으로 새 페이지      | `Unsupported unknown mention`                                         |

- N8 — push 는 노트를 하나씩 올리며 위키링크를 그때 상태 DB 에 있는 페이지로만 멘션으로 바꾼다. 뒤에 만드는 노트는
  아직 없다. pull 은 모두 받은 뒤 링크를 다시 보는 패스(`notion-link-pass`)가 있었지만 push 에는 없었다.

수정:

- N6 — 보낼 본문의 자리 태그 가운데 그 페이지에 없는 블록의 것을 볼트에 보이는 모양으로 바꾼다
  (`converter/unknown-tag-fallback.ts`). 북마크는 볼트 링크의 주소 · 캡션으로 `<bookmark url="…">캡션</bookmark>` 을
  보낸다 — 실측에서 진짜 북마크 블록이 되고, 목록 · 토글 · 콜아웃 안에서는 그 자식이 된다. 캡션은 마크다운으로
  읽히므로 `\` 로 escape 한다(`_i_` 는 기울임이 됐다). 원래 주소를 모르는 북마크 · 다른 블록은 보이는 링크로,
  멘션은 볼트에 보이는 것이 없으므로 뺀다.
  - 새 페이지는 블록이 하나도 없으므로 만들기 전에 모든 태그를 바꾼다.
  - 본문 교체는 먼저 그대로 보낸다. 거절되면 이미 지금 본문을 받아 자식 태그를 되돌리는 길(`replacePageBody`)에서
    지금 본문에 있는 태그만 남기고 나머지를 바꿔 한 번 더 보낸다. 블록은 ID 로 맞춘다. 대부분의 노트는 추가 요청이
    없다.
- N8 — push 를 마친 뒤 링크 패스(`sync/push-link-pass.ts`)가 풀지 못한 위키링크(보존 마커 `wikilink`)의 대상이 지금
  풀리는 노트를 다시 보낸다. 예전에 글로 올라간 노트도 대상이 생긴 push 에서 고쳐진다. 다시 보내면 마커가 새로
  적혀 같은 노트를 또 고르지 않는다. 범위를 좁힌 push 의 범위 밖 · 제외한 노트, 올리지 않은 로컬 수정이 있는
  노트(이번 push 에서 실패한 노트 포함)는 다시 보내지 않는다.

검증:

- 게이트 통과 — 시험 3,880 → 3,902. 더한 시험 22개 가운데 17개가 수정 전 코드에서 실패했다(새 모듈 시험 11개는
  모듈이 없어 파일째, 배선 4개, 본문 교체 2개). 나머지 5개는 바꾸지 말아야 할 동작(범위 밖 · 제외 · 실패한 노트 ·
  풀리지 않는 링크 · 있는 태그만 있을 때 사유 그대로)을 지킨다.
- 변이 16개를 모두 잡았다. 처음 살아남은 1개(풀리지 않는 링크만 있는 노트를 매번 다시 보냄)는 시험을 더해 잡았다.
- 실 Notion(탐침 `__p3_push`) CLI 왕복, Markdown API:

| 동작                                                                         | 결과                                                                |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 다른 페이지의 북마크를 담은 새 노트 · 커스텀 이모지 노트 · A↔B 위키링크 push | 5 생성 · 실패 0 — 북마크 블록(주소 · 캡션) · A 와 B 둘 다 멘션      |
| 올린 노트에 다른 페이지의 북마크 줄을 붙여 push                              | 갱신 · 실패 0 — 새 북마크 블록                                      |
| 목록 · 콜아웃 안 없는 북마크(캡션에 `*` · `[]` · 백틱)                       | 항목 · 콜아웃의 자식 북마크, 캡션 글자 그대로                       |
| C(`[[D]]`)를 올린 뒤 D 를 만드는 push                                        | 1 생성 · 1 갱신 — C 가 멘션이 됨                                    |
| 빈 볼트로 pull                                                               | 북마크는 새 블록을 가리키는 링크 · 마커, 위키링크는 `[[A]]` `[[B]]` |
| 다시 pull · push (두 볼트)                                                   | 바뀐 노트 0                                                         |

찾은 것 (고치지 않음):

- 다시 보낸 북마크는 새 블록이 된다. 볼트 노트의 마커는 옛 블록을 가리킨 채 남고, 그 노트를 다시 올리면 북마크를
  또 새로 만든다(내용은 같다). 그 페이지를 다음에 받을 때 새 블록으로 바뀐다.
- 캡션 안 `[` `]` 를 escape 하지 않은 북마크 줄(사람이 손으로 쓴 것)은 Obsidian 에서도 링크가 아니다 — push 는
  마커만 빼고 그 줄을 글로 보낸다.

## DB 행 받기 묶음 (`fix/row-pull`)

증상:

- B4 — 받은 행의 빈 속성(글 · 선택 · 날짜 · 숫자)이 `메모: null` 로 적혔다. 행마다 빈 칸 수만큼 `null` 줄이
  남았다. 빈 목록(다중 선택 · 사람 · 관계)은 적지 않아 같은 빈 값이 두 모양이었다.
- B5 — 행을 받아 쓴 뒤 파일 수정 시각 · 크기를 상태 DB 에 적지 않았다. 다음 변경 확인이 받은 행을 모두 다시 읽어
  해시를 쟀다.
- B13 — 행 노트는 기간을 두 키(`기간` · `기간_end`)로 적는데 `.base` 보기에 끝 열이 없어 Obsidian 표에서 끝 날짜가
  보이지 않았다.
- B10 — 같은 이름의 새 페이지 둘 가운데 누가 자연 이름(`노트.md`)을 얻고 누가 ID 조각(`노트 (40013b18).md`)을

## Notion 의 글 모양 (`fix/notion-text-forms`)

먼저 잰 것(탐침 `__p7_text`, 2026-10-21):

- markdown API 는 인라인 수식을 ``$`y`$`` 로, 글의 `$` 는 `\$` 로 준다 — `\$a\$` · `a\$b\$c` · `\$\$a\^2\$\$`.
- Obsidian 1.13.7 읽기 보기: `$a$` · `a$b$c` · `x $a$b` · `$$a^2$$ 글` 은 수식, `$a$1` · `$ x $` · `$x $` · `$5 와 $10` 은 글,
  `\$a\$` 는 글 `$a$`. Notion 보다 넓게 수식으로 읽는다(Notion 은 `a$b$c` 를 글로 둔다).

증상:

- C13: Notion 의 글 `$a$` · `글 $x+1$` 가 볼트에서 수식으로 보였다. 그 노트를 고쳐 push 하면 Notion 에서도 수식이 된다.
  코드 블록 안의 `\$x\$` 는 `$x$` 로 바뀌었다.

원인:

- `convertNotionMath` 가 `\$…\$` 를 「이스케이프된 인라인 수식」 으로 보고 `$…$` 로 풀었다(2026-05-16 `2aee865`). 실제
  수식은 ``$`…`$`` 로 오므로 이 규칙은 글만 바꿨고, 코드 펜스도 가리지 않았다.

수정:

- 그 규칙을 걷어내고 `unescapeSafeLiteralDollars` 로 바꿨다. 줄마다, 글 `$` 를 풀었을 때 글 `$` 가 낀 Obsidian 수식 짝이 생길
  수 있으면 그 줄의 글 `$` 를 `\$` 로 둔다. 짝이 생길 수 없는 줄(`가격 $5 와 $10`)은 사람이 쓴 모양으로 푼다. 코드 펜스 ·
  인라인 코드 안은 건드리지 않는다. Notion 의 짝 규칙은 Obsidian 보다 좁아 같은 판정이 push 도 지킨다.

검증:

- 게이트 통과 — 시험 3,949 → 3,971. 수정 전 실패 6(변환 5 · 왕복 1).
- 변이 5개 모두 잡음(붙은 `$$` · 글 없는 짝 건너뛰기 · 닫는 `$` 뒤 숫자 · 인라인 코드 건너뛰기 · 풀기 끔).
- CLI: 빈 볼트로 pull → `\$a\$` · `가격은 $5 와 $10 이다` · `글 \$x+1\$ 그리고 $y$` · `a\$b\$c`. 격리 Obsidian 1.13.7 에서 그
  노트가 Notion 의 글과 같게 보이고 `y` 만 수식. 로컬에서 한 줄 더해 push → Notion 문단은 모두 글 그대로(`y` 만 수식) ·
  다시 pull · push 0. 탐침은 휴지통으로 옮겼다.

찾은 것 (고치지 않음 — API 한계, 문서로 남긴다):

- `> [!faq]-` · `[!tldr]` 같은 별칭 · 접힘은 Notion 에 담을 곳이 없다. 같은 볼트에서는 받은 뒤에도 그대로지만(로컬 표기
  유지, 메모리 하니스로 확인), 다른 볼트로 처음 받으면 아이콘이 같은 기본 종류(`[!question]`)가 된다.
- 봇 멘션은 markdown API 가 내보내지 않는다(2026-10-12 실측) — 받은 노트에 없고, 그 노트를 push 하면 Notion 에서도
  사라진다.
- 토글 안 여러 줄 수식의 블록 → NFM → 블록 왕복 차이는 제품 경로가 아니다(ADR-034).

## 받아 둔 노트 다시 그리기 (`feature/pull-rerender`)

증상:

- B14: 변환기가 나아져도 이미 받아 둔 노트는 그 페이지가 Notion 에서 바뀔 때까지 옛 모양이었다 — Notion 블록을 가리키는
  `🔖 Bookmark` 링크(실볼트 166개 · 54노트, 2026-10-04), 코드 상자로 보이는 옛 4칸 자식. `pull --force` 도 훑는 범위만 넓힐
  뿐 바뀌지 않은 페이지는 다시 그리지 않는다.
- 다시 그려 봐도 옛 북마크 링크가 남았다 — 로컬 표기 유지(`local-form.ts`)가 push 가 버리는 링크를 «같은 것» 으로 보아 로컬
  링크를 지켰다. 같은 까닭으로 Notion 에서 북마크 캡션을 바꿔도 받은 노트의 링크는 그대로였다.

수정:

- `pull({ rerender: true })` · `nobsi pull --rerender` · 플러그인 명령 「Pull from Notion (받아 둔 노트 다시 그리기)」.
  상태가 synced 인 페이지 · 폴더 노트 · DB 행 가운데 볼트에서 고치지 않은 것을 받을 차례에 더한다(`rerender-targets.ts`).
  쓸지는 받는 쪽(`pullUpdate`)이 내용으로 정한다. `--dry-run` 과는 함께 쓸 수 없다 — 다시 그려 봐야 바뀌는지 안다.
- 로컬 표기 유지는 북마크 링크 글자도 견준다(`bookmarkLinks`) — 링크의 이름 · 주소는 Notion 이 정한다. 이번에 블록을 읽지
  못했으면 볼트에 이미 있는 그 북마크의 링크를 쓴다(`keepReadBookmarkLinks`).
- 받아 봤지만 쓰지 않은 항목은 진행 알림에 `unchanged` 를 싣고 CLI 는 줄을 찍지 않는다 — 다시 그리기는 받아 둔 노트를
  모두 받아 보므로 바뀌지 않은 노트마다 「updated」 줄이 찍혔다.

검증:

- 게이트 통과 — 시험 3,971 → 3,988. 수정 전 실패 6 · 변이 10개 모두 잡음(같은 동작인 변이 둘은 조건을 걷어냈다).
- CLI(탐침 `__p8_rerender`, 북마크 둘): 블록 읽기를 막고 받아 옛 모양 재현 → 보통 pull 은 그대로 · `--rerender` 가 새 링크
  둘로 다시 그림(요청: 페이지 1 · markdown 1 · 블록 2 · search 2) · 다시 `--rerender` 는 진행 줄 없이 바뀐 것 0 · push · pull 0 ·
  Notion 북마크 블록 그대로. Notion 에서 캡션을 바꾸고 보통 pull → 새 캡션. 블록 읽기를 막고 문단만 바뀐 페이지를 받으면 볼트의
  링크 그대로 · 문단은 받음. `--rerender --dry-run` 은 오류. 격리 Obsidian 1.13.7 에 새 명령이 등록된 것을 확인(실행은 안 함).
  탐침은 휴지통으로 옮겼다.

찾은 것 (고치지 않음):

- 같은 통합 토큰으로 같은 분 안에 Notion 을 고치면 pull 이 자기 쓰기로 보고 받지 않는다 — ADR-017 의 알려진 한계. 탐침에서
  스크립트로 고친 문단이 그랬다(분을 넘겨 다시 고치면 받음). 사람이 고친 것은 편집자가 달라 받는다.

## 받기 렌더 하나로 (`refactor/pull-render`)

- B9: 새로 받기(`createPulledPage`)와 다시 받기(`renderRemotePage`)가 속성 · 제목 주입 · 미디어 · 변환을 따로 들고 있었다. 한쪽에만
  고친 것이 다른 쪽에 없었다 — DB 모드에서 Notion 이 정하는 키(F-08)는 다시 받기에만 있었다. `renderPageNote` 하나로 모았다.

  잡는다. 실 Notion 탐침 `__p8b_render`(제목 `질문: 왜?` · 자식 페이지 · 콜아웃 · 토글 · 목록 · 코드 · 수식 · 북마크)를 리팩터 전 빌드와
  뒤 빌드로 각각 빈 볼트에 받아 `diff -r` 이 같고, 뒤 빌드의 다시 그리기는 바뀐 것 0. 탐침은 휴지통으로 옮겼다.

## 플러그인 설정 · 동작 (`fix/plugin-settings-actions`)

- 증상
  - D1: 설정의 루트 페이지 칸에 Notion 주소를 붙여 넣으면 그 주소를 그대로 ID 로 써 연결이 Notion 검증 오류로 끝났다. CLI `init` 도 같았다.
  - D2: 동기화 방향이 «Pull만» 이면 Push 단추 · 항목 올리기 단추가 눌리기만 하고 아무 일도 없었다(«Push만» 이면 Pull 쪽).
  - D3: 변경 목록을 다시 읽다 실패하면 그 오류를 버리고 옛 목록을 그대로 보였다.
  - D4: 플러그인이 받아 쓴 노트의 볼트 이벤트가 자동 동기화를 한 번 더 불렀다.
  - D5: 플러그인 상태 DB 가 스키마 SQL 을 손으로 베껴 처음 두 스키마의 CHECK 제약이 빠져 있었다.
  - D6: 상태 DB 를 임시 파일 → 이름 바꾸기로 쓰면서 폴더를 디스크에 내리지 않았다.
- 원인: D1 은 입력을 ID 로 읽는 곳이 없었다. D2 는 방향 판정이 명령에만 있고 화면은 몰랐다. D4 는 볼트 이벤트가 누가 쓴 것인지 몰랐다
  (Obsidian 1.13.7 실측 — `create` · `modify` · `rename` · `delete` 이벤트는 API 호출 안에서 바로 불린다).
- 수정
  - 주소나 ID 에서 페이지 ID 를 읽는 `notionIdFromInput` 하나를 설정 · 연결 · CLI 가 같이 쓴다. `?p=`(열어 둔 페이지)가 앞선다.
    설정 칸 설명이 읽은 ID 또는 «못 찾음» 경고를 보인다.
  - 방향 판정 `directionBlock` 을 명령과 변경 패널이 같이 쓴다 — 막힌 단추는 꺼지고 까닭을 제목으로 보인다.
  - 목록 읽기 실패는 오류 상태로 보이고, 다음에 읽히면 걷는다. 작업이 끝난 뒤의 실패는 알림만 하고 작업의 결과 상태를 지킨다.
  - 동기화용 볼트 어댑터가 쓰는 동안의 경로를 기억하고 그 이벤트는 자동 동기화를 부르지 않는다. 보기(표 · 편집기)가 쓰는 어댑터는 따로라 사용자 편집은 여전히 부른다.
  - 코어의 `STATE_DB_MIGRATIONS` 목록을 두 드라이버가 같이 돈다. 이미 만든 플러그인 DB 에 빠진 CHECK 는 덧대지 않는다.
  - 이름 바꾸기 뒤 폴더를 열어 `fsync` — 폴더를 못 열면 넘어간다.
- 검증
  - 게이트 통과 — 시험 3,990 → 4,020. 손 변이 19개 모두 잡음.
  - 격리 Obsidian 1.13.7(탐침 루트 아래 `__qa_probe_…diffui__`): 설정 칸에 주소를 넣으면 ID 로 적히고 못 읽는 주소는 경고 ·
    «Pull만» 에서 Push 단추와 항목 올리기 45개가 꺼짐 · 새 페이지를 받은 뒤 자동 동기화 호출 0(옛 빌드 1) · 사용자 편집 뒤 1.
- 찾은 것 (고치지 않음)
  - 받기가 하는 이름 바꾸기도 `recordLocalRename` 을 부른다 — 해가 있는지 보지 않았다.
  - 이미 만든 플러그인 DB 의 빠진 CHECK 제약은 그대로다.
