## 4. 결함5 — 본문 `---` 시작 시 frontmatter 유실 (#49) ⭐

fresh-user E2E pull(247개 복잡 페이지) 중 발견한 **무손실 위반(I2)**.

### 근본 원인

gray-matter `matter.stringify(string, data)`는 첫 인자가 문자열이면 내부에서
`matter(file)`로 본문을 재파싱한다. Notion divider 등으로 본문이 `---`로 시작하면
그 `---…---` 블록을 frontmatter로 오인해 YAML 파싱하다 throw:

```
[FrontmatterGenerator] Post-processor failed: YAMLException: unidentified alias "*돌아보기**"
[FrontmatterGenerator] Post-processor failed: YAMLException: end of the stream ... [🔗 Embed](...)
```

`pipeline.ts`의 try/catch가 throw를 삼켜 post-processor 전체가 스킵 → **그 파일의
속성이 통째로 누락**되는 조용한 데이터 유실.

### 수정

`packages/core/src/utils/frontmatter.ts`에 `stringifyFrontmatter()` 헬퍼 추가 —
`matter.stringify({ content }, data)` 객체 형태로 호출해 재파싱 자체를 차단. 동일
패턴 호출처 3곳 전부 교체:

| 파일                                 | 상태                 |
| ------------------------------------ | -------------------- |
| `frontmatter-generator.ts`           | 실제 버그            |
| `view/entry-editor.ts`               | 동일 잠재버그        |
| `pre-processors/properties-table.ts` | 안전했으나 패턴 통일 |

회귀 테스트 1건 추가. 커밋 5e2b8e8(feature/db-base-fidelity).

### rank21 — 직속 행 선택 (`selectDbRowFiles` 단일 유틸 추출)

`collectEntries`(뷰)와 `pushDatabase`(sync) 둘 다 `path.startsWith(prefix)` 로 DB 행을 골랐다.
DB 행은 `localFolder/<name>.md` 로 **평탄**하게 기록되지만, 하위 폴더(`localFolder/SubDB/...`)는
**별도 child_database** 거나 자식 페이지 본문이다. 단순 prefix 매칭은 이 중첩 .md 를 부모 DB
행으로 **오포함** → 뷰에 카드로 새고, push 시 부모 DB 로 잘못 밀린다.
이미 `selectStaleDbArtifacts` 가 쓰던 "직속만(`rel` 에 `/` 없음)" 규칙을 **하나의 공유 유틸**
`selectDbRowFiles` 로 추출해 두 호출처에 배선(중복 헬퍼 금지 — 엔터프라이즈 일관성).

### rank22 — 커버 multivalue degrade (`coerceCover`)

Notion `files` 속성을 갤러리 커버로 쓰면 property-mapper 가 단일 파일은 스칼라 URL,
복수 파일은 **URL 배열**로 직렬화한다(데이터 보존). 그런데 카드 `<img src>` 는 스칼라만 받아,
배열이 그대로 흐르면 `src="url1,url2"` 로 **깨진다**. 과거 `const cover = fm.cover as string`
캐스팅은 배열을 문자열로 단언한 **런타임 거짓말**이었다. `coerceCover` 로 배열 → 첫 렌더 가능
URL 로 degrade(Notion 도 다중 파일은 첫 파일을 씀) → `DBEntry.cover: string` 타입을 런타임 보증.

### rank22b — title·icon 스칼라 강제 (`coerceString`)

rank21/rank22 와 같은 계열의 형제 버그를 완전성 스윕(`startsWith` 경로필터 / `fm.* as` 캐스팅
전수 검색)에서 추가 발견. `parseEntry` 의 `fm.title as string` 캐스팅은 **거짓말**이었다 —
따옴표 없는 숫자 제목(`title: 2026`)은 js-yaml 이 **number** 로 파싱하고, 배열·수동 오편집도
가능하다. 이때 `filter-engine.ts:175` 의 `entry.title.toLowerCase()` 가
`toLowerCase is not a function` 으로 **뷰 검색 전체를 크래시**(I9 위반, rank22 커버 깨짐과 동일).
`coerceString` 추가 — number/boolean 문자열화·배열 첫 비공백 문자열 degrade 로 title·icon 의
`string|undefined` 타입을 런타임 보증. (write 경로는 `extractTitle`/`extractIcon` 이 항상 스칼라라
엔진은 배열을 쓰지 않지만, read 보루를 둬 다형 입력을 안전화.)

### 근본 원인 (경험적 프로브로 단정 — 추정 아님)

페이지 모드 pull 의 발견 단계가 `searchAllPages()`(워크스페이스 **전체** 페이지네이션) →
`filterPagesUnderRoot()`(페이지별 ancestry 워크로 root 하위만 필터) 였다. 비용이 **동기화
대상(서브트리) 크기와 무관하게 워크스페이스 전체 페이지 수에 비례**:

- 임시 프로브 실측: `searchAllPages` = **6,187 페이지 / ~93s**, 2-파일 볼트 단일 pull = **~148s**.
- `deleteSync=true` 는 증분 fast-path 를 못 쓴다(in_trash/archived 가 search 에 안 잡혀 삭제
  감지 불가 → 전체 스캔 강제). I10 테스트는 pull 을 2회 호출 ≈ **296s > 180s 타임아웃** → hang.

### 수정 — 서브트리 한정 발견 (`getChildPagesRecursive`)

- `orchestrator.ts`: 발견을 `getChildPagesRecursive(rootPageId)`(BFS 서브트리 순회)로 교체.
  비용이 **실제 동기화 대상에만 비례**. search 가 못 보는 archive/in_trash 는 자연히 제외돼
  orphan(삭제) 판정도 동일하게 성립. 폴더 판정용 `_childParentIds` 는 발견된 각 페이지의

- `filterPagesUnderRoot()`(~84줄)·`searchAllPages()`(client.ts) **삭제** — 순 **-110줄**.
  dedup 안전망(`detectRemoteChanges` 의 `seenRemoteIds`)·orphan 감지 블록은 불변.
- 오프라인 테스트 4파일(`orchestrator.test`·`pull-search-dedup`·`foldernote-classification`·
  `incremental-deletion-churn`)을 `searchAllPages` 목 → `getChildPagesRecursive` 목으로

- `as string` / `as Array<…>` 캐스팅은 변환·뷰 레이어의 반복 풋건 — Notion 신 모델이
  돌려주는 다형(배열/스칼라/`{}`)을 은폐한다. 경계에서 런타임 가드(`Array.isArray`,
  `coerceCover`)로 타입을 **실제로** 보증하는 패턴을 표준으로 삼는다.
- 오포함 버그(rank21)는 "이미 코드베이스에 정답 규칙(`selectStaleDbArtifacts`)이 있는데
  다른 호출처가 안 쓴" 일관성 결함 — 신규 헬퍼가 아니라 **기존 규칙 추출·공유**가 정답.
- 무손실 검증은 실데이터 대량 corpus가 필수 — try/catch로 삼킨 조용한 유실은
  단위 테스트로 안 잡히고 fresh-user E2E 콘솔 스캔에서만 드러났다.
- "빈 객체 `{}`" 풋건(결함7·10)은 한 가족 — Notion 신 모델은 빈 배열형 값을 `{}` 로
  돌려줄 수 있고 `as Array<…>` 캐스트가 이를 은폐한다. 배열 추출은 반드시 `Array.isArray`
  런타임 가드를 통과시킨다.
- `/goal` 완료 선언은 실명령 재실행 + 도달성 분류 사용자 승인 전까지 금지(Stop-hook).
