## 조사 중 찾은 것

- **HTML 블록이 한 시간 뒤 끊기는 링크로만 남았다.** Notion 이 호스팅한 `.html` 은 읽으면 `embed` 이고 URL 이 서명
  URL 이다. 예전 pull 은 바깥 embed 와 같이 `[🔗 Embed](URL)` 로 남겨 내용이 볼트에 없었다
- **첫 고침이 실 E2E 에서 안 먹었다.** pull 은 변환(`notionBodyToObsidian`)이 받기(`downloadAllFiles`)보다 먼저다. 받기만
  고쳐서는 변환이 이미 링크로 바꾼 뒤였다 — 변환에서 `[🌐 …](URL)` 로 옮겨 받기가 집게 했다
- `archived` 는 다음 API 버전(2026-03-11)에서 빠진다. 2025-09-03 에서 `in_trash` 를 받는 것을 실측했다
- 고른 간격(350ms · 동시 3, 초당 약 2.86)은 분당 180 · data source 조회 초당 약 3 둘 다 안쪽이다 — 바꾸지 않았다

## 조사 중 찾은 것

- **5 의 링크가 실 Notion 에서 깨졌다.** 블록을 모르는 서명 URL 은 페이지 주소만 갖는데, pull 후처리의 Notion 링크 복원
  (`link-restore`)이 그것을 `[[↗ Notion 에서 열기 · 1MB]]` 로 바꿨다. 그 노트를 push 하면 Notion 에 새 문단이 생겼다. 단위
  시험은 블록 주소(`#…`)가 붙은 꼴만 봐서 놓쳤다 — 후처리를 지나는 시험을 더했다
- pull 의 순서: Markdown API 변환 → 받기(`downloadAllFiles`) → **후처리 파이프라인**. 받기가 더한 글자는 후처리를 지난다
- 상한을 1KB 까지 낮출 수 있어 5KB 파일이 「1MB」 로 적혔다 — 1MB 아래는 KB
- 읽기 전용 속성: 사본에 볼트의 값이 남아 다음 pull 이 «우리가 쓴 그대로» 로 보고 받지 않았다. push 뒤 그 행을
  `markRemoteUnverified` 로 표시해 다음 pull 이 비교하게 했다

## 조사 중 찾은 것

- **Notion API 실측(2026-10-28)** — search · data source 조회는 휴지통을 돌려주지 않고 `in_trash` 거르개는 400 이다.
  자식을 휴지통에 넣어도 부모의 `last_edited_time` 은 그대로다. 부모를 넣으면 하위가 함께 들어간다
- **API 로 블록을 지우면 페이지 `last_edited_time` 이 바뀌지 않는다**(고치기 · 더하기는 바뀐다). 수정 시각으로 찾는
  증분 · 전체 대조 모두 볼 수 없다 — Notion API 한계. 사람이 Notion 화면에서 지울 때도 같은지는 확인하지 못했다
- **읽기 전용 경고가 약속을 지키지 못했다(10).** P1 은 그 행을 «다시 볼 것» 으로 표시했지만, 보낸 것이 없어 행도 DB 도
  그대로라 증분 pull 이 DB 를 통째로 건너뛰었다. `pull --force` 만 되돌렸다. 메모리 하네스의 search 가 `since` 를
  무시하고 다 돌려줘 시험이 놓쳤다 — 시험 안에서 실제처럼 거르게 했다(하네스를 고치면 19개가 깨진다 — 수정 시각이
  기기 시계와 따로 간다)
- **빈 줄이 늘었다(11).** 로컬 표기를 되살릴 때 지운 문단과 그 앞 빈 줄을 한 줄씩 따로 넣어 봐, 보낼 꼴을 바꾸지 않는
  빈 줄만 남았다. 위키링크와 무관하게 글 문단에서도 난다
- 같은 분 안에 같은 통합 토큰으로 push 하고 Notion 을 고치면 동기화기는 자기 쓰기로 본다(N-05) — 실 E2E 를 짤 때 1분 띄운다
