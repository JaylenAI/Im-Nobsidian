## "Git 처럼 되는가" — 아니다

push 는 이미 해시 증분이다. 느린 것은 pull 이고, 원인은 한 곳이다 — 원격 무변경이어도
매 pull 이 발견 DB 166개를 전부 `queryAllDatabasePages` 로 다시 읽고 `.base` 를 다시
만든다(`orchestrator.ts:1197` 루프). 페이지 쪽 감지는 이미 search 정렬 + 워터마크 증분이다.

DB 행도 페이지라서 같은 search 결과에 나온다. 그러니 search 한 번으로 "바뀐 행이 속한 DB"
만 골라 pull 하면 된다. search 가 못 보는 것(휴지통 · 인덱스 지연으로 빠진 새 페이지)은
주기적 전체 대조로 잡는다 — S-08 이 바로 그 빈틈이었다.

## S-01 · S-02 — 행은 행으로 보낸다

원인은 한 곳이었다. 행인지를 전역 모드(`parentMode`)로 갈라서, 페이지 모드 볼트가 자동
발견한 DB 의 행(`db-row`)이 페이지 경로로 밀렸다. 페이지 경로는 속성으로 제목만 보내고
나머지 frontmatter 를 본문 첫머리 YAML 블록으로 끼운다.

수정(`fix/db-row-property-push`): 행인지는 레코드가 정하고, 행은 `pushRowUpdate` 로 간다.

| 무엇              | 규칙                                                                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 무엇을 보내나     | 원격이 지난 동기화 뒤 그대로면 지난 동기화 사본과 견줘 바뀐 속성만. 통째로 보내면 로컬이 평문으로만 아는 서식(굵게 · 링크 · 멘션)이 매번 지워진다                                   |
| 원격도 바뀌었으면 | 로컬에서 바꾼 것만 보내고 `notionLastEdited` 를 올리지 않는다 — 올리면 다음 pull 이 원격 변경을 영영 받지 않는다                                                                    |
| 충돌 해소 결과    | 해소가 사본을 먼저 바꾸므로 사본과 견주면 보낼 것이 없다. 원격의 지금 값과 견줘 다른 것을 모두 보내고 본문도 보낸다                                                                 |
| 본문              | 바뀌었을 때만, YAML 없이                                                                                                                                                            |
| 속성 변환         | DB 스키마에 있는 것만. 읽기 전용(수식 · 롤업 · 생성일 등)과 모르는 유형은 보내지 않는다. relation · people 은 하나라도 ID 로 못 바꾸면 통째로 뺀다(일부만 보내면 나머지가 지워진다) |
| 글 속성           | 2,000자 조각 · 100조각 상한. 넘으면 보내지 않는다(요청 전체가 400 이 되어 다른 속성까지 거부된다)                                                                                   |
| 제목              | frontmatter `title`, 없으면 파일 이름 — pull 이 쓰는 제목과 같다                                                                                                                    |
| 원격 행 그리기    | 충돌 · 비교 화면도 pull 과 같은 렌더러. 본문 첫머리의 옛 YAML 블록은 행에서는 버린다                                                                                                |

S-13(gray-matter 캐시)은 이 작업의 단위 시험이 찾았다. 깨진 frontmatter 를 첫 시도에서
거절해도, push 재시도가 같은 글을 다시 읽을 때 캐시가 «frontmatter 없음» 을 돌려줘 행의
속성을 모두 지우는 요청이 나갔다. 행 경로는 캐시를 건너뛰게 했고 나머지 호출은

사용자 볼트 행 925개의 Notion 본문을 읽어 옛 YAML 블록을 찾았다(읽기만): **0개**. 오염은

남는 것:

- 수식 · 롤업 값은 로컬 push 뒤 원격이 다시 바뀌기 전까지 로컬 파일에 옛 값으로 남는다(위
  `점수x2` 가 로컬에서 0.84). push 가 적는 시각이 곧 원격 시각이라 다음 pull 이 그 행을 다시
  받지 않는다.
- files · status 는 비우는 요청을 보내지 않는다. `cover` · `icon` frontmatter 는 보내지 않는다.
- 설정 DB(`notion.databases`)의 행은 아직 옛 경로(`pushDatabaseRow`, 모든 속성)로 간다 — S-04 에서 합친다.
