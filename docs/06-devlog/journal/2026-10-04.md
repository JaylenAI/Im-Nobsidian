## 멘션 (F-01 · F-02)

원인(실측 2026-09-26, 프로브 `QA-H1`): Markdown API 는 사용자 멘션을 이름 없는 태그로
(`<mention-user url="user://…"/>`), 날짜를 시각 · 끝 · 시간대 속성으로
(`<mention-date start="2026-09-26" startTime="09:00" end="2026-09-27" endTime="18:00"
timeZone="Etc/GMT-9"/>`) 내보낸다. pull 은 옛 모양(`<mention-user id>이름</mention-user>` · 닫힌
날짜 태그의 start · end)만 알았다. 사용자 태그는 볼트에 그대로 남아 읽기 보기에서 빈칸이 되고,
날짜는 시각 · 끝 · 시간대를 버린 평문이 됐다. 볼트에 멘션 문법이 없으니 다음 push 가 Notion 의
멘션을 평문으로 바꿨다. 합성 렌더 코퍼스 07 의 짝 날짜 태그(`…></mention-date>`)도 볼트에 그대로
샜다 — 게이트가 `-` 든 태그 이름을 산문으로 세어, 태그가 새어야 산문 보존율이 맞았다.

수정(`fix/mention-roundtrip`):

- **pull.** 사용자 · 날짜 · DB · 데이터 소스 · 에이전트 멘션을 짝 마커
  `%%im-nobsidian:mention-<종류>:<속성>%%보이는 글%%/mention%%` 로 바꾼다(`converter/mention.ts`).
  속성은 받은 순서 그대로 퍼센트 인코딩해 싣는다. 보이는 글은 사용자 `@이름`, 날짜
  `2026-09-26 09:00 → 2026-09-27 18:00 (UTC+9)` — `Etc/GMT-9` 는 부호가 반대인 IANA 이름이라 UTC+9
  로 보인다. 닫힌 태그 · 짝 태그 둘 다 받고, 코드 안은 그대로 둔다.
- **이름.** `NotionClient.getUserNames` 가 `users.retrieve` 로 묻는다. 같은 사람은 한 번만 묻고,
  읽지 못한 사람은 이유를 남기고 `@user` 로 보인다 — 멘션은 id 로 남는다. 페이지와 DB 행이 같은
  길(`sync/page-body.ts` 의 `notionBodyToObsidian`)로 받는다.
- **push.** 마커를 태그로 되살린다. 날짜 글을 고쳤으면 고친 글을 읽어 새 멘션을 만든다 — `->` 도
  화살표, 끝에 시각만 적으면 같은 날 끝, 시각이 없으면 시간대를 버린다. 기간의 한쪽만 시각이거나
  끝이 시작보다 앞서거나 없는 날짜면 글로 보낸다 — 그런 멘션은 본문 교체를 통째로 거절당할 수
  있다. 사용자는 id 로 되살리고 보이는 이름을 안에 싣는다(문서의 형태 · 오프라인 왕복이 같은 글로
  돌아오게). 보이는 글을 지우면 멘션을 지운 것이다.
- **블록 방식 push**(martian)는 멘션을 만들지 못해 마커를 걷고 보이는 글만 보낸다 — 색 · 밑줄
  마커와 같은 강등.
- **렌더 게이트.** 규칙 ④ 가 `<mention-*>` 누수를 잡고, 구조 드리프트에 `<mention-user>` ·
  `<mention-date>` 를 센다. 산문 판정은 `-` 든 태그 이름도 태그로 본다.

알려진 동작 (고치지 않음):

- **push 뒤 로컬 노트.** 고친 글은 그대로, 마커의 속성은 옛 값으로 남는다(r5). 다시 올려도 글을
  다시 읽어 같은 멘션이 되고, 다음 원격 수정 때 Notion 기준으로 다시 그려진다. 사용자 이름을 고친
  글도 그렇다 — 이름은 Notion 이 정한다.
- **이미 받아 둔 노트.** v0.3.x 가 평문으로 받은 멘션은 다시 받기 전까지 평문이다. 그 노트를 고쳐
  올리면 Notion 의 멘션이 평문이 된다(예전과 같다). 릴리스 노트에 적는다.
- **블록 API 로 받는 경로**(Markdown API 로 못 받을 때의 폴백)는 여전히 멘션을 평문으로 받는다.
- 읽기 보기에서 마커가 숨는 것(Obsidian 주석)은 격리 Obsidian 으로 보지 않았다 — Phase 3
  (U-01 렌더러)에서 함께 본다.

## 겹친 서식 · 밑줄 (F-07 · F-06 의 밑줄)

원인: Notion 은 빨강+밑줄을 속성이 둘인 한 태그(`<span color="red" underline="true">`)로 내보낸다.
pull 은 속성이 하나인 span 만 알아 그 태그를 볼트에 그대로 남겼다 — 실볼트 3 노트 7곳. 밑줄은 마커로
받아 읽기 보기에서 밑줄이 보이지 않았고, 사용자가 쓴 `<u>` 는 한 바퀴 돌면 마커가 됐다. 코드 안의
span 도 마커로 바꿔 HTML 예제 코드에 마커 글자가 들어갔다.

수정(`fix/combined-span`):

- **pull.** 속성을 집합으로 받는다. 둘이면 색 마커가 바깥, 밑줄이 안쪽이다. 밑줄은 안이 평문이면
  `<u>`, 마크다운이 있으면 지금처럼 마커다. Live Preview 는 `<u>` 안의 마크다운을 풀지 않는다(1.13.7
  실측) — `<u>**굵게**</u>` 의 `**` 가 글자로 보이고, 강조를 밖으로 꺼낸 `**<u>중요</u>**합니다` 는 조사
  앞에서 굵게가 풀린다. 실볼트 밑줄 108곳 중 96곳이 굵게 · 링크를 품어 마커로 남고, 평문 12곳만 그
  페이지를 다시 받을 때 `<u>` 가 된다.
- **push.** `<u>` 를 밑줄 span 으로 보낸다. 겹친 span 은 한 태그로 펼친다 — Notion 은 span 안의 span 을
  읽지 못해 안쪽 닫는 태그를 글자 `</span>` 로 남긴다(r0). 같은 마커가 겹친 것(빨강 글 안의 `==형광==`)은
  안쪽 짝부터 맞춘다 — 전에는 바깥 여는 마커를 안쪽 닫는 마커와 짝지어 `%%/color%%` 가 글로 남았다
  (실볼트 0건).
- **코드.** 펜스 · 인라인 코드 안의 span · `<u>` · `==` 는 글자 그대로 둔다(pull 과 push 전처리 둘 다).
  가드는 `container-indent.ts` 의 `replaceOutsideCode` 하나다 — 일치의 시작 위치로 판정해 코드를 사이에
  둔 서식(``<u>a `b` c</u>``)도 바꾸고, 펜스 줄을 먼저 갈라 펜스 백틱을 인라인 코드 짝으로 세지 않는다.
- **렌더 게이트 · 감사.** 규칙 ④ 가 `<span color|underline>` 누수를 잡고, 한 줄 규칙은 코드 안을 보지
  않는다. 구조 지표에 글자색 · 밑줄 span 수를 센다. 코퍼스 05 에 겹친 span 과 코드 안 span 을 넣었다.

알려진 동작 (고치지 않음):

- Notion 이 같은 모양으로 담지 못하는 글은 다음 pull 때 Notion 의 모양으로 바뀐다 — 빨강 글 안의 형광은
  세 조각으로, 인라인 코드가 든 `<u>` 는 코드 앞뒤로 나뉜다(r4 · r5). 글과 서식은 그대로다.
- 노랑 배경+밑줄(`==<u>…</u>==`)은 Live Preview 에서 형광이 보이지 않는다 — 형광 장식이 HTML 위젯을
  감싸지 않는다. 읽기 보기는 둘 다 보인다.
- 평문 밑줄 마커(실볼트 12곳)는 그 페이지를 다시 받을 때 `<u>` 로 바뀐다. 릴리스 노트에 적는다.
