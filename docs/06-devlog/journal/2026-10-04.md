## 멘션 (F-01 · F-02)

원인(실측 2026-09-26, 프로브 `QA-H1`): Markdown API 는 사용자 멘션을 이름 없는 태그로
(`<mention-user url="user://…"/>`), 날짜를 시각 · 끝 · 시간대 속성으로
(`<mention-date start="2026-09-26" startTime="09:00" end="2026-09-27" endTime="18:00"
timeZone="Etc/GMT-9"/>`) 내보낸다. pull 은 옛 모양(`<mention-user id>이름</mention-user>` · 닫힌
날짜 태그의 start · end)만 알았다. 사용자 태그는 볼트에 그대로 남아 읽기 보기에서 빈칸이 되고,
날짜는 시각 · 끝 · 시간대를 버린 평문이 됐다. 볼트에 멘션 문법이 없으니 다음 push 가 Notion 의
멘션을 평문으로 바꿨다. 합성 렌더 코퍼스 07 의 짝 날짜 태그(`…></mention-date>`)도 볼트에 그대로
샜다 — 게이트가 `-` 든 태그 이름을 산문으로 세어, 태그가 새어야 산문 보존율이 맞았다.

수정(`fix/mention-roundtrip`):

- **pull.** 사용자 · 날짜 · DB · 데이터 소스 · 에이전트 멘션을 짝 마커
  `%%im-nobsidian:mention-<종류>:<속성>%%보이는 글%%/mention%%` 로 바꾼다(`converter/mention.ts`).
  속성은 받은 순서 그대로 퍼센트 인코딩해 싣는다. 보이는 글은 사용자 `@이름`, 날짜
  `2026-09-26 09:00 → 2026-09-27 18:00 (UTC+9)` — `Etc/GMT-9` 는 부호가 반대인 IANA 이름이라 UTC+9
  로 보인다. 닫힌 태그 · 짝 태그 둘 다 받고, 코드 안은 그대로 둔다.
- **이름.** `NotionClient.getUserNames` 가 `users.retrieve` 로 묻는다. 같은 사람은 한 번만 묻고,
  읽지 못한 사람은 이유를 남기고 `@user` 로 보인다 — 멘션은 id 로 남는다. 페이지와 DB 행이 같은
  길(`sync/page-body.ts` 의 `notionBodyToObsidian`)로 받는다.
- **push.** 마커를 태그로 되살린다. 날짜 글을 고쳤으면 고친 글을 읽어 새 멘션을 만든다 — `->` 도
  화살표, 끝에 시각만 적으면 같은 날 끝, 시각이 없으면 시간대를 버린다. 기간의 한쪽만 시각이거나
  끝이 시작보다 앞서거나 없는 날짜면 글로 보낸다 — 그런 멘션은 본문 교체를 통째로 거절당할 수
  있다. 사용자는 id 로 되살리고 보이는 이름을 안에 싣는다(문서의 형태 · 오프라인 왕복이 같은 글로
  돌아오게). 보이는 글을 지우면 멘션을 지운 것이다.
- **블록 방식 push**(martian)는 멘션을 만들지 못해 마커를 걷고 보이는 글만 보낸다 — 색 · 밑줄
  마커와 같은 강등.
- **렌더 게이트.** 규칙 ④ 가 `<mention-*>` 누수를 잡고, 구조 드리프트에 `<mention-user>` ·
  `<mention-date>` 를 센다. 산문 판정은 `-` 든 태그 이름도 태그로 본다.

## 겹친 서식 · 밑줄 (F-07 · F-06 의 밑줄)

원인: Notion 은 빨강+밑줄을 속성이 둘인 한 태그(`<span color="red" underline="true">`)로 내보낸다.
pull 은 속성이 하나인 span 만 알아 그 태그를 볼트에 그대로 남겼다 — 실볼트 3 노트 7곳. 밑줄은 마커로
받아 읽기 보기에서 밑줄이 보이지 않았고, 사용자가 쓴 `<u>` 는 한 바퀴 돌면 마커가 됐다. 코드 안의
span 도 마커로 바꿔 HTML 예제 코드에 마커 글자가 들어갔다.

수정(`fix/combined-span`):

- **pull.** 속성을 집합으로 받는다. 둘이면 색 마커가 바깥, 밑줄이 안쪽이다. 밑줄은 안이 평문이면
  `<u>`, 마크다운이 있으면 지금처럼 마커다. Live Preview 는 `<u>` 안의 마크다운을 풀지 않는다(1.13.7
  실측) — `<u>**굵게**</u>` 의 `**` 가 글자로 보이고, 강조를 밖으로 꺼낸 `**<u>중요</u>**합니다` 는 조사
  앞에서 굵게가 풀린다. 실볼트 밑줄 108곳 중 96곳이 굵게 · 링크를 품어 마커로 남고, 평문 12곳만 그
  페이지를 다시 받을 때 `<u>` 가 된다.
- **push.** `<u>` 를 밑줄 span 으로 보낸다. 겹친 span 은 한 태그로 펼친다 — Notion 은 span 안의 span 을
  읽지 못해 안쪽 닫는 태그를 글자 `</span>` 로 남긴다(r0). 같은 마커가 겹친 것(빨강 글 안의 `==형광==`)은
  안쪽 짝부터 맞춘다 — 전에는 바깥 여는 마커를 안쪽 닫는 마커와 짝지어 `%%/color%%` 가 글로 남았다
  (실볼트 0건).
- **코드.** 펜스 · 인라인 코드 안의 span · `<u>` · `==` 는 글자 그대로 둔다(pull 과 push 전처리 둘 다).
  가드는 `container-indent.ts` 의 `replaceOutsideCode` 하나다 — 일치의 시작 위치로 판정해 코드를 사이에
  둔 서식(``<u>a `b` c</u>``)도 바꾸고, 펜스 줄을 먼저 갈라 펜스 백틱을 인라인 코드 짝으로 세지 않는다.
- **렌더 게이트 · 감사.** 규칙 ④ 가 `<span color|underline>` 누수를 잡고, 한 줄 규칙은 코드 안을 보지
  않는다. 구조 지표에 글자색 · 밑줄 span 수를 센다. 코퍼스 05 에 겹친 span 과 코드 안 span 을 넣었다.

## 표 속성 · 빈 블록 (F-04)

원인: 파이프 표에는 머리 열 · 페이지 너비 · 열 너비 · 행/셀/열 색을 적을 자리가 없다. pull 이 이 속성을
버려, 그 노트를 올리면 Notion 의 표 속성이 지워졌다. 속성 없는 `<table>` 은 머리 행이 없는 표인데,
한 바퀴 돌면 머리 행 표가 됐다. 빈 블록(`<empty-block/>`)은 빈 줄로 받았다. 빈 줄은 블록 경계일 뿐이라
Obsidian 에 간격이 보이지 않고, push 때 Notion 이 빈 줄을 버려 빈 블록이 사라졌다. 목록 자식 빈 블록은
pull 에서부터 사라졌다.

수정(`fix/table-attrs`):

- **표 pull.** 속성을 셀 머리 마커(`%%im-nobsidian:table-row:color=gray_bg%%`)에 싣는다 — 표 · 열
  속성은 첫 행 셀, 행 속성은 그 행 첫 셀, 셀 속성은 그 셀. 마커가 셀과 함께 움직여 Obsidian 에서 열을
  맞바꾸거나 행을 끼워도 속성이 제자리에 남는다. 속성 없는 `<table>` 은 `header-row=false` 를 적는다.
  머리 행만 켠 표(파이프 표를 받은 Notion 이 만드는 모양)는 마커 없이 둔다.
- **표 push.** 마커가 든 파이프 표만 NFM 표로 되돌린다. 거짓 속성은 적지 않는다 — Notion 도 빠진
  속성을 거짓으로 읽는다. 속성 없는 열은 `<col>` 로 적는다 — `<col/>` 는 Notion 이 건너뛰어 뒤 열의
  속성이 한 칸씩 앞당겨진다(실측 C1 · C2). 블록 방식 push 는 마커를 걷는다(martian 은 머리 행 표만 만든다).
- **빈 블록.** `<br>` 줄로 받고 push 가 빈 블록으로 되돌린다. 주석 마커는 Live Preview 에 회색 글로 보이고
  간격이 생기지 않아 쓰지 않았다. 인용 안에서는 앞뒤에 빈 인용 줄(`>`)을 끼운다 — 콜아웃 안 제목 바로
  뒤의 `> <br>` 이 HTML 블록을 열어, 다음 빈 줄까지 굵게 · 목록이 글자 그대로 보였다(1.13.7 실측).
  목록 자식은 띄우지 않는다 — 빈 줄이 목록 전체를 느슨한 목록으로 바꾼다. 코드 안은 건드리지 않는다.
- **구조.** 태그 속성 도우미를 `converter/nfm-attrs.ts` 로, 마커 페이로드를 `constants/markers.ts` 로 꺼내
  멘션과 같이 쓴다. 표는 `converter/table.ts`, 빈 블록은 `converter/empty-block.ts`.

## 글 뒤에 붙은 표

원인: Notion 은 콜아웃 · 토글 안의 블록을 빈 줄 없이 내보낸다. pull 이 그 표를 앞 줄에 붙여 적어,

## 문단 · 인용의 자식

원인: Notion 은 문단 · 인용(콜아웃 아님)도 자식 블록을 가지며, 품은 줄 뒤에 탭 한 단계 들여써 내보낸다.
BlockSpacer 가 이 탭을 목록 자식처럼 4칸으로 펴고 블록 사이에 빈 줄을 두어, Obsidian 이 빈 줄 뒤 4칸 들여쓴
줄을 들여쓴 코드블록(회색 상자)으로 그렸다 — 자식 목록 · 문단이 글자 그대로 보이고, 자식 코드는 펜스까지
상자에 들어가 코드 줄이 문단으로 보였다(아래 q0). 실볼트 파일 그대로 인용 바로 뒤의 들여쓴 코드블록이
154곳 · 19노트다.

Notion 실측(프로브 페이지 「표 쓰기 형태」 `…9bb7`, 블록 API 로 구조 확인):

- 빈 줄 뒤 2칸 들여쓴 줄은 앞 인용 · 문단 블록의 자식이 된다 — 문단 · 목록, 6칸 손자 목록은 손자로
  (R1~R3). 탭 자식 사이에 빈 줄이 있어도, 4칸이어도 자식이다(R4 · R5). 2칸 자식 뒤의 `>` 줄은 새 인용
  블록이다(R7). 목록 항목 아래 2칸 문단은 항목의 자식이다(R6).
- 코드는 코드 줄이 **모두** 펜스만큼 들여써졌을 때만 그 폭을 뗀다. 펜스와 코드 줄을 같은 2칸으로 들여쓰면
  코드 줄머리 공백 · 탭까지 그대로 들어가고(C1), 펜스 2칸 · 코드 열 0 이면 아무것도 떼지 않는다(C2). 콜아웃 ·
  목록 · 맨 바깥 · 문단 자식 코드도 그대로다(C3~C6). 내보낼 때는 펜스만 탭으로 들여쓰고 코드 줄은 열 0 에 둔다.

## 코드 속 펜스 줄 (F-03 · S-22)

원인: Notion Markdown API 는 코드 속 ``` 로 시작하는 줄에서 코드 블록을 가른다. 내보낼 때는 펜스를 넓히지 않는다.
그래서 마크다운 예시를 담은 코드 블록은 두 방향 모두 깨졌다.

- 올리면 코드 블록 둘 · 문단이 됐다.
- 받으면 코드 속 줄이 Obsidian 에서 블록을 닫아 코드 뒷부분이 본문으로 샜다.
- 실볼트 1,271노트 중 3노트(코드 4개)다.

Notion 실측(프로브 페이지 「표 쓰기 형태」 `…9bb7`):

- **가져오기.** 바깥 펜스를 `` 로 넓혀도, `~~~` 로 바꿔도, 줄을 `\`` 로 막아도 코드 속 ``` 줄에서 가른다.
  - `~~~` 는 코드 블록이 되지 않는다.
  - 백슬래시는 글에 그대로 남는다.
- **내보내기**(블록 API 로 만든 코드 F1 ~ F8)
  - 여는 줄은 ``` + Notion 언어 이름이다.
  - 닫는 줄은 여는 줄과 같은 탭 들여쓰기의 맨 ``` 이다.
  - 코드 줄은 콜아웃 · 목록 안에서도 열 0 이다.
  - 넓은 펜스로 내보내는 일은 없다.
- **블록 API.** `blocks.update` 는 코드 글을 그대로 받고 그대로 돌려준다.

수정(`fix/nested-code-fence`, ADR-029):

- **push.** 가드가 그런 코드를 자리표시 한 줄로 보낸다. 본문을 쓴 뒤 글이 자리표시인 코드 블록을 찾아
  `blocks.update` 로 채운다.
  - 페이지 · 행, 만들기 · 고치기 모두 같다.
  - 채우다 멈추면 지금 원격을 «지난번에 본 원격» 으로 적고 실패로 남긴다. 재시도 · 다음 push 가 다시 보내 채우고,
    그 사이 pull 은 자리표시가 든 본문을 받지도 충돌로 올리지도 않는다.
  - 코드 블록 하나에 담을 수 없을 만큼 긴 코드는 예전처럼 보낸다.
- **pull.** 받은 본문에서 위 규칙으로 코드 범위를 정해 경계 펜스를 넓힌다.
  - 컨테이너 안 코드는 가장 가까운 같은 들여쓰기의 닫는 줄이 닫는다.
  - 맨 위 코드가 모호할 때만 그 페이지의 코드 블록 글을 읽어 맞춘다.
  - 블록 폴백 변환기도 넓은 펜스로 감싼다.
- 행 속성의 rich text 조각 나누기를 `notion/rich-text.ts` 로 옮겨 코드 채우기와 같은 규칙을 쓴다.

## 인용 · 콜아웃 안 코드 가드 (S-26)

원인: 코드 구간을 정하는 구현이 셋이었다.

- `utils/md-regions` 의 `mapOutsideCodeFences` — 텍스트 치환의 공용 가드. 줄머리 공백 뒤의 펜스만 코드로 봤다.
- `scanCodeFences` — 인용 · 목록을 안다. push 의 언어 가드와 pull 의 언어 복원기가 쓴다.
- `converter/container-indent` 의 `codeRanges` — pull 의 Notion 마크다운(탭 들여쓰기) 구조를 본다. 이미 인용을 안다.

- pull: 지운 주석을 `>` 없이 따로 되살려 콜아웃을 끊었다. 이스케이프 정리도 코드 안까지 갔다.

- 목록 표시 줄에서 연 펜스는 항목 글 자리보다 덜 들여쓴 줄에서 항목과 함께 끝난다(CommonMark).

## 코드 속 빈 줄 · 주석 자리 빈 줄 (S-27)

원인:

- 지원하지 않는 블록 제거(`UnsupportedBlockStripper`, order 5)가 지운 뒤 문서 전체에서 `\n{3,}` 를 `\n\n` 으로 줄였다 —
  코드 안까지.
- 주석 제거(order 11)는 그 뒤에 돌아, 주석 줄 자리에 남은 빈 줄이 Notion 빈 블록이 됐다.
- 이미 올린 코드는 Notion 에 줄어든 채 남는다. 원격의 다른 곳이 바뀌어 받으면 그 코드가 로컬 코드를 덮어 빈 줄이
  사라졌다.

수정:

- `collapseBlankLines`(md-regions) — 코드 밖에서만 줄인다. 코드 구간은 `scanCodeFences` 가 정한다.
- `BlankLineCollapser`(push, order 65) — 내용을 지우거나 끼우는 전처리 뒤, 보존 마커 수집(70) 앞에서 한 번 줄인다.
  `UnsupportedBlockStripper` 의 줄이기는 뺐다.
- `CodeLanguageRestorer`(pull) — 받은 코드가 로컬 코드를 옛 push 처럼 줄인 모양이면 로컬의 빈 줄을 되살린다. 원문이
  맨 빈 줄인 자리만 되살린다. 인용의 `>` 줄과 CRLF 노트의 줄은 옛 push 도 줄이지 않았다.
- 왕복 하니스의 `canonicalBody` 도 코드 밖만 줄인다. 코드 속 빈 줄 차이를 이제 잡는다.

## 주석 왕복 (S-29)

원인:

- push 는 주석 글만 지우고, 보존 마커에 앵커(같은 줄의 앞 글 · 앞 줄)를 적었다. pull 은 앵커 줄 다음 줄에 주석을
  따로 끼웠다. 앵커는 «어느 줄 다음» 만 담아, 줄 속 위치 · 콜아웃 깊이 · 목록 구조 · 빈 줄을 잃었다.
- 주석 찾기는 인라인 코드를 몰라 `` `<!-- 이렇게 -->` `` 같은 표기 설명까지 지웠다.
- 콜아웃 속 주석 줄은 글만 지워 `>` 만 남은 줄이 Notion 에서 콜아웃 문단을 갈랐다.

수정 (ADR-030):

- `comments.ts`(converter) — 찾기 · 지우기 · 되살리기.
  - `findComments` — 코드 펜스 · 인라인 코드 · 브랜드 마커 밖에서 찾는다.
  - `cutComments` — Obsidian 이 그리는 모양대로 지운다. 주석만 있는 줄은 줄째(`>` · 들여쓰기 포함), 앞뒤가 모두
    빈 줄이면 빈 줄 하나도. 줄 속 주석은 옆 공백 하나와 함께.
  - `restoreComments` — 받기 직전의 로컬 노트에서 되살린다. 받은 글이 로컬에서 주석을 지운 글과 같으면 로컬
    노트 그대로. 다르면 줄을 맞춰(같은 줄 → 비슷한 줄 → 빈 줄) 주석마다 자리를 정하고, push 가 보낼 글이 받은
    글과 같은 배치를 고른다.
- `CommentRestorer`(pull, order 120 — `BlockSpacer` 뒤) 추가. `CommentStripper` 는 `cutComments` 로.
- `PreserveMarkerInjector` — 로컬 노트가 있으면 comment 마커를 끼우지 않는다. 마커는 로컬 노트가 없을 때의
  폴백이다.
- `line-diff.ts` — `alignLines` · `mapOffset` · `lineSimilarity`. `md-regions.ts` — `nextCodeSpan` 공개, 쓰는 곳이
  없어진 `mapOutsideMarkers` 제거.

이 브랜치 안에서 찾아 고친 것:

- **실측 c2 — 고친 문장 속 주석이 줄 밖으로 빠졌다.** 첫 판은 «모든 자리에 지운 글 그대로» 가 어긋나면 모든 자리를
  이웃에 맞췄다. Notion 은 콜아웃 속 빈 `>` 줄을 내보내지 않아(압축형), 콜아웃 속 문단 사이 주석 하나가 첫
  배치를 어긋나게 했다. 그래서 고친 문장 속 주석까지 줄 밖으로 빠지고, 글 끝 주석은 앞 빈 줄을 잃었다. 이제
  이웃에 맞춘 자리를 하나씩 지운 글 그대로 되돌려 보고, 보낼 글이 같으면 되돌린 채 둔다.
- **무작위 시험 — 주석이 frontmatter 안에 들어갔다.** 원격에서 본문을 모두 지워 받은 글이 끝 줄바꿈 없이 닫는
  `---` 로 끝나면, 본문 자리를 닫는 줄로 셌다. 깨진 YAML 은 글자만 견줘 그 배치를 받아들였다(첫 판에도 있던
  결함 — 시험의 frontmatter 정규식이 놓쳤다). 본문 자리를 frontmatter 뒤로, push 의 눈에 깨진 YAML 을 따로
  가르고 frontmatter 뒤 줄바꿈은 견주지 않는다. 무작위 시험에 «속성이 받은 글과 같다» 를 더했다.
- **무작위 시험 — 본문 머리 주석 뒤 줄의 들여쓰기.** push 는 본문을 다듬은 뒤에 주석을 지워 그 줄의 들여쓰기를
  그대로 보낸다(네 칸이면 코드 블록). push 의 눈이 본문 앞 공백을 통째로 버려 그 차이를 못 봤다. 머리의 빈 줄만
  버린다.

## 주석 속 서식 · frontmatter 값 속 서식 (S-31)

원인:

  제거(11)보다 먼저. `==강조==` · `<u>` 를 바꾸는 서식 마커는 `%%` 로 쓰인다(`%%im-nobsidian:color:yellow_bg%%…`).
- 주석 속 서식을 먼저 마커로 바꾸면, 주석의 `%%` 는 마커를 넘어 짝짓지 않아(D-COMMENT-PAIR) 주석으로 보이지
  않았다. 주석이 통째로 — 메모 글까지 — Notion 에 올라갔다. HTML 주석은 마커를 품을 수 있어 새지 않았다.

## 동명 페이지 경로 시험의 차례 의존 (S-32)

증상: S-29 머지 커밋(`6298efc`)의 CI(Node 24)에서 `pull-path-collision` 시험 하나가 실패했다 — 기대

15번은 모두 통과했다. 바로 다음 커밋(`b90c29c`)의 CI 는 통과했다.

원인:

- 같은 이름의 새 페이지 셋(A · B · C, 앞 8 글자 공유)은 pull 워커 풀에서 함께 경로를 고른다. 누가 먼저
  고르는지는 실제 파일 조회(`exists`)가 끝나는 차례다 — 실행마다 다를 수 있다.
- 시험은 "B · C 중 뒤에 배정된 쪽이 16 글자로 넓어진다" 고 단언했다. A 가 마지막이면 A 가 넓어지므로(제품은
  맞다) 단언이 깨진다. 경로 후보 설명(`pagePathCandidates`)도 "어떤 순서로 처리되든 같은 페이지가 같은 경로로
  수렴한다" 고 적었다 — 고정되는 것은 배정 뒤(상태 DB 의 레코드)다.
- 재현: A 의 본문만 30ms 늦게 돌려주면 매번 CI 와 같은 경로 · 같은 실패가 나온다. 워커를 하나로 두고 원격
  차례를 B, C, A 로 주어도 같다.

수정 (시험 · 주석만, 제품 동작 그대로):

- 기존 시험은 차례와 무관한 것만 본다 — 자연 이름은 하나, 접미사는 자기 ID 의 앞 조각, 조각 길이는 8 · 16.
- 차례마다 시험 3개 추가 — 워커 하나로 차례를 고정해 A · B · C 가 각각 마지막일 때 그 페이지가 자기 ID 16
  글자로 넓어지는지 본다.
- `pagePathCandidates` 설명을 "한 번 배정된 경로는 레코드에 남아 그대로 쓰고, 첫 배정은 처리 차례에
  달렸다" 로 고쳤다.

## 콜아웃 · 토글 안 임베드 (S-28)

증상: push 가 콜아웃 · 토글 안의 이미지 · 첨부 임베드를 컨테이너 밖으로 떼어냈다. 그 뒤 줄은 콜아웃이 아닌 일반
인용이 되고, 이미지뿐인 토글은 비고, 토글 속 칼럼은 마커가 짝을 잃어 사라졌다. 실볼트에서 컨테이너 속 임베드

  바깥으로 냈다. Notion 콜아웃 안에 첨부를 넣을 수단이 없다고 봤기 때문이다.
- 실제로는 컨테이너의 자식 인용을 이미지로 제자리 교체(뒤에 붙이고 자리표시자를 지움)하면 이미지가 그 안에
  들어간다(아래 실측 1).
- 머리 줄의 임베드(`> [!note] ![[표.base|표]]` — 제목이 비고 첫 자식이 DB 인 콜아웃을 받은 모양, 실볼트 52줄)를

실측 (생성 · 본문 교체 두 경로, 컨테이너 `…1a5a`):

1. 콜아웃 안 `> > 📎 …` 는 빈 줄 없이도 앞뒤 줄과 갈려 콜아웃의 자식이 된다. 토글 · 토글 속 칼럼 · 겹친 콜아웃 ·
   제목 없는 콜아웃 · 인용을 품은 콜아웃 안에서도 그 자리의 자식이 됐고, 교체한 이미지가 모두 제자리에 들어갔다.
2. **인용 바로 뒤 글 줄은 이제 이어 붙지 않는다.** 맨 바깥 · 토글(빈 줄 있음 · 없음) · 콜아웃 모두 인용 뒤 글이
   따로 문단이 됐다. `isolate` 주석의 옛 실측(뒷글이 인용에 빨려 들어감)과 다르다 — 끊기는 해가 없어 그대로 둔다.
3. **인용보다 깊이 들여쓴 뒷줄은 그 인용의 자식이 된다.** 탭 · 공백 넷 · 공백 둘 모두, 빈 줄을 사이에 두어도
   같다. 자리표시자 인용이 이미지로 바뀌며 지워질 때 자식도 함께 지워진다. 첫 판은 목록 항목에 딸린 임베드의
   자리표시자를 컨테이너 깊이(들여쓰기 없이)에 두어, 뒤 줄(`\t\t계속`)이 자리표시자의 자식이 됐다 — 항목
   들여쓰기를 지키면 형제가 된다(실측 C2 · T2).
4. **자식 DB 를 컨테이너로 옮기면 Notion 이 그 컨테이너를 페이지 맨 위에 두는 일이 있다.** `replace_content`
   한 번에 맨 바깥 DB 둘을 콜아웃 · 토글로 옮기면(e1) 토글이 맨 위로 갔다. 실험 12번 중 어긋남 5(e1 · E8 ·
   E10 ~ E12 — 컨테이너를 드나들거나 차례가 바뀜), 제자리 7(하나만 옮김 4 · 맨 바깥끼리 1 · 한쪽만 콜아웃으로 1 ·
   컨테이너가 글 사이로만 움직임 1). 어긋난 것은 모두 같은 본문을 한 번 더 보내면 제자리로 갔다. 같은 종류 콜아웃 사이 이동(1회)은 한
   번에 제자리였다 — 어긋나는 조건을 Notion 이 밝히지 않아, 배치가 바뀐 교체는 모두 한 번 더 보낸다.
5. Notion 은 컨테이너 안의 빈 줄을 버린다 — 끊으려고 넣은 빈 줄은 남지 않는다.

## 첨부 자리표시자에 묶인 뒷줄 (S-33)

증상: 임베드 뒤에 그보다 깊이 들여쓴 줄이 오면 push 뒤 Notion 에서 그 줄이 사라졌다. 오류는 없었다 — push 는
created · updated 1, 실패 0 으로 끝났다.

원인:

- push 는 `![[사진.png]]` 를 자리표시자 인용(`> 📎 사진.png %% … %%`)으로 보내고, 업로드가 그 인용 바로 뒤에 이미지를
  넣은 다음 인용을 지운다(`image-handler.ts` 의 `deleteBlock`).
- Notion 은 인용보다 깊이 들여쓴 줄을 — 탭 · 공백 넷 · 공백 둘, 빈 줄을 사이에 두어도 — 그 인용의 자식으로 묶는다.
  인용을 지우면 자식도 함께 지워진다.
- 실볼트 dev 기준 6노트 20곳. 콜아웃 · 토글 안 임베드가 맨 바깥으로 내려간 뒤(S-28) 남은 컨테이너 줄이 자리표시자보다
  깊어진 자리가 대부분이고, 맨 바깥 임베드 뒤 빈 줄 · 네 칸 목록도 있다. S-28 을 고친 브랜치에서도 2곳(맨 바깥 1 ·
  콜아웃 속 목록 항목에 이어 쓴 임베드 뒤 더 깊은 하위 목록 1)이 남는다 — 두 수정이 서로 기댄다.

실측 (프로브 `__s33_raise__` `…5c4b`, 컨테이너 `…1a5a`, 생성 · 본문 교체 두 경로 같음):

1. 자리표시자를 뒷줄 깊이로 들이면 둘이 형제가 되어 함께 앞 블록의 자식으로 간다 — 목록 항목 뒤(공백 넷), 문단
   뒤(공백 넷 · 탭), 뒷줄이 코드 블록, 콜아웃 속 목록의 하위 · 손자 깊이. 코드 블록으로 읽힌 줄은 없다.
2. 붙은 `>` 줄은 각각 다른 인용이다 — 자리표시자 둘 · 자리표시자와 인용 · 들인 자리표시자와 같은 깊이 인용 모두
   형제. 더 깊은 `>` 줄만 자식이 된다(들이면 형제).

수정:

  들인다(`converter/placeholder-indent.ts`). 아래에서 위로 보아 잇단 자리표시자도 함께 들고, 코드 블록 속 줄은 보지
  않는다. 이미지는 뒷줄 바로 앞, 앞 블록의 자식 자리에 놓인다.
- 안전망 — 업로드는 자식이 묶인 자리표시자를 이미지로 바꾸지 않고 남기고 경고 한 줄을 낸다. 들여쓰기로 막지 못한

## 북마크 주소 (F-09)

증상: Notion 북마크가 볼트에 「🔖 Bookmark」 라는 이름의 링크로 보이고, 누르면 북마크한 사이트가 아니라 Notion 의 그
블록이 열렸다. 실볼트 166개 · 54노트(한 노트에 많게는 26개).

원인:

- Markdown API 는 북마크 블록을 주소 · 캡션 없이 `<unknown url="…/p/<페이지>#<블록>" alt="bookmark"/>` 로만
  보낸다(실측 — 맨 바깥 · 토글 안 · 목록 항목 아래 모두 같다). url 의 호스트는 `app.notion.com` 이다.
- pull 은 이 태그로 가시 링크와 보존 마커 한 쌍을 만들었다. 링크의 목적지가 태그의 url, 곧 Notion 의 블록이었다.
  왕복은 마커가 맡아 블록을 잃지는 않았다.

수정:

- pull 이 본문의 북마크 자리 태그를 모아 블록을 하나씩 읽고(`NotionClient.getBookmarks`), 가시 링크의 이름을
  캡션(없으면 주소)으로, 목적지를 북마크의 주소로 바꾼다(`converter/bookmark.ts`). 마커는 그대로라 push 는 받은 태그를
  돌려보내고 Notion 은 원래 블록을 남긴다.
- 캡션은 우리가 넣는 글이라 Notion 의 escape 를 푸는 단계 뒤에 넣는다. 대괄호 · 백틱은 escape 하고, 줄바꿈은 펴고,
  `%%` 는 `%` 로 줄인다 — 링크가 일찍 닫히거나 Obsidian 주석이 뒤따르는 마커를 가리지 않게. push 의 짝 패턴은 이름의
  backslash escape 를 받는다.
- 마커가 바로 뒤따르는 가시 링크는 위키링크로 바꾸지 않는다(`link-restore.ts`) — Notion 주소(`notion.so/<32자리>`)를
  북마크하면 `[[🔖 …]]` 가 되어 누르면 없는 노트가 열렸다(탐침에서 재현).
- 읽지 못한 북마크는 이유를 남기고 예전처럼 Notion 블록 링크로 둔다.
- 요청은 북마크 하나에 한 번(`blocks.retrieve`) 는다. 실볼트 전부를 받으면 166번 — 초당 3 요청 제한에서 계산상 약
  55초다(재지 않았다 — 릴리스 E2E 에서 잰다).

## 표 칸 안 파이프 (F-06)

증상: 칸에 `\|` 가 든 표를 push 하면 Notion 에서 칸이 갈렸다 — `x\|y` 가 `x\` · `y` 두 칸이 되고 뒤 칸이 한 칸씩 밀려 표에
열이 하나 늘었다. 다음 pull 이 그 표를 받아 볼트의 표도 그렇게 바뀐다. 실볼트 1노트 1행.

원인 (탐침 `__f06_pipe__` `…e47a` · `__f06_pipe_code__` `…60a3` 실측):

- Notion 은 파이프 표의 `\|` 를 이스케이프로 읽지 않고 그 자리에서 칸을 가른다. NFM 칸에서는 `\|` 와 날 `|` 둘 다 파이프
  글자다.
- push 는 표 속성 마커가 없는 파이프 표를 그대로 보냈다. 마커가 있는 표는 NFM 표로 갔지만 칸 코드 속 `\|` 를 그대로 보내
  Notion 의 코드에 백슬래시가 남았다 — NFM 칸의 코드는 백슬래시를 글자로 둔다(`` `c\|d` `` → 코드 `c\|d`).

수정 (`converter/table.ts`):

- 칸에 `\|` 가 든 표는 마커가 없어도 NFM 표로 보낸다. 코드 밖 `\|` 는 Notion 이 내보내는 모양 그대로 둔다 — 받은 표를
  다시 보내면 글자까지 같다.
- 코드 속 파이프는 앞 백슬래시 k개를 볼트에 2k+1개로 적고, 보낼 때 k개로 되돌린다. 격리 Obsidian(1.12.4 읽기 보기)
  실측 — 칸의 코드는 백슬래시째 보이고(`` `c\|d` `` → `c\|d`), 짝수 개 백슬래시 뒤의 파이프에서 칸을 가른다. 홀수 개라야
  칸이 지켜진다. push 의 칸 나누기도 같은 홀짝 규칙으로 바꿨다 — 예전엔 바로 앞 백슬래시 하나만 봤다.
- 둘째 커밋(`2327e4a`)은 GFM 규칙을 믿고 코드 속 글자 `\|` 를 `\\|` 로 적었는데, Obsidian 에서 그 행이 잘려(실측)
  `12af232` 로 바로잡았다.

## Obsidian 표기 왕복 — 콜아웃 · `<mark>` · `<details>` · frontmatter · 빈 줄 (F-06 · S-30)

증상 (탐침 `__f06_ofm__` `…bd95` 실측):

- Notion 에서 한 줄만 고쳐 pull 하면 노트 전체가 다시 쓰였다. 접어 둔 콜아웃(`[!faq]-`)이 모두 펼쳐지고, 별칭은 첫
  이름(`[!question]`)으로, `<details>` 는 `[!toggle]-` 콜아웃으로, frontmatter 의 `tags: [a, b]` 는 블록 목록으로 바뀌었다.
  빈 줄 배치 · frontmatter 뒤 간격 · 파일 끝 줄바꿈(표 칸 파이프 절의 「찾은 것」)도 바뀌었다.
- 별칭 콜아웃(`faq` · `tldr` …)은 아이콘 없이 올라가 받으면 `[!note]` 였다. 블록 경로로 받은 `abstract` 는 `example` 로
  돌아왔다.
- `<mark>` 는 Notion 에 글자 그대로 적혀 받으면 `\<mark\>` 였다.
- 실볼트(읽기만) 1,271노트를 「Notion 이 보낸 글을 그대로 돌려준다」고 보고 받아 보면 508노트가 바뀌었다(아래 검증).

원인:

- 콜아웃 접힘 · 별칭, `<details>`, frontmatter 의 목록 모양, 빈 줄 개수는 Notion 에 자리가 없다. pull 은 받은 글을 그대로
  썼다 — 받은 글은 정준형일 수밖에 없다.
- 콜아웃 종류 ↔ 아이콘 표가 넷(Markdown 경로 둘 · 블록 경로 둘)이고 서로 달랐다. 둘이 `abstract` · `example` 의 아이콘을
  거꾸로 적었고, 별칭은 어느 표에도 없었다.
- `<mark>` 를 Notion 의 서식으로 바꾸는 단계가 없었다.

수정:

- 콜아웃 표는 하나다(`converter/callout-types.ts` — 종류 13 · 별칭 14). 네 경로가 모두 이것을 읽는다. 표에 없는 종류는
  아이콘 없이 보내고, 받은 아이콘 없는 콜아웃에는 빈 스타일 마커(`%%im-nobsidian:callout-style:%%`)를 달아 다시 보낼
  때도 아이콘 없이 간다 — 예전엔 `[!note]` 가 📝 를 달고 갔다.
- `<mark>` · `<mark style="…">`(Highlightr)는 `==` 와 같은 노란 배경 마커로 보낸다(`html-annotation.ts`). 코드 속 · 여러
  줄에 걸친 것은 그대로다.
- pull 이 로컬 표기를 되살린다(`converter/local-form.ts`, `LocalFormRestorer` order 130). 받은 글에서 push 가 같은 꼴로
  보내는 자리는 받기 직전의 로컬 노트 글로 둔다.
  - 기준은 「보낼 꼴」(`converter/sent-form.ts`) — 경로 · 본문 · 속성(키 차례는 보지 않음) · 미룬 코드 · 올릴 파일.
    꼴이 같으면 다시 push 해도 Notion 이 그대로라, Notion 에 있는 것은 잃지 않는다.
  - 노트를 블록(빈 줄로 가른 줄 묶음, frontmatter · 코드 펜스는 통째로)으로 나눠 맞추고, 다른 자리를 한꺼번에 · 반씩
    로컬 글로 바꿔 본다. 안 되는 묶음은 블록끼리(수가 같으면) · 앞뒤에서 떼어(다르면) · 줄 단위로 좁힌다. 줄은 비슷한
    줄끼리 짝짓고(`alignNoteLines` — 주석 왕복과 같은 것), 남는 줄은 따로 넣어 본다 — 콜아웃 속 문단 경계(`>`)가 Notion

- Notion 은 NFM 의 빈 줄을 읽지 않는다(탐침 `__f06_blank_a__` · `__f06_blank_b__` 실측 — 문단 · 제목 · 인용 · 목록
  사이와 콜아웃 · 토글 본문의 빈 줄 · 탭뿐인 줄은 있으나 없으나 같은 블록이다. 인용 속 `>` 만 있는 줄은 빈 인용 블록이다).

## 행 속성 모양 (F-08)

증상 (탐침 `__f08_props__` `…3c61` 실측, dev `affb386` 빌드):

- 기간(끝이 있는 날짜)은 `{start, end}` 객체로 적혔다. Obsidian 은 이 값을 알아보지 못해 속성 패널 · Bases 에서 날짜로 쓸
  수 없다.
- 시각은 Notion 이 준 그대로(`2026-10-01T01:00:00.000+00:00`), 생성일 · 수정일은 UTC(`…Z`)로 적혔다. Obsidian 1.12.4 는 초
  · 밀리초 · 오프셋이 붙은 값을 글로 본다(실측: `YYYY-MM-DD` 는 날짜, `YYYY-MM-DDTHH:mm` 는 날짜시각, 그 밖은 글).
- 볼트에서 시간대 없이 적은 시각(`마감: 2026-10-01T10:00`)은 그대로 갔고, Notion 은 이것을 UTC 로 읽었다 — 한국에서는 19:00
  이 됐다.
- 서식 있는 글 속성(굵게 · 링크 · 색 · 멘션 · 수식)을 볼트에서 한 글자 고쳐 push 하면 평문 한 조각이 갔다. 서식 · 링크 ·
  멘션이 모두 지워졌다.
- 행을 다시 받으면 frontmatter 를 받은 속성만으로 새로 썼다. 로컬에만 있는 키(`aliases` · `cssclasses` …)가 지워지고 키 차례
  · 따옴표 · 흐름 목록 · 주석이 바뀌었다.

원인:

- `PropertyMapper.extractValue` 가 날짜를 Notion 모양 그대로 돌려주고 기간은 객체로 돌려줬다.
- push 는 날짜 글자를 꼴만 보고(`DATE_REGEX`) 그대로 보냈다.
- 글 속성 push 는 볼트의 평문으로 새 조각을 만들었다 — 원격 조각을 보지 않았다.
- `FrontmatterGenerator` 가 받은 속성으로 frontmatter 를 통째로 다시 썼다 — 로컬 노트를 보지 않았다.

수정 (`fix/property-format`):

- **시간대.** 새 설정 `conversion.timeZone`(IANA 이름 — 없으면 이 컴퓨터의 시간대, `utils/zoned-time.ts`). pull 은 시각을 이
  시간대의 벽시계 시각 `YYYY-MM-DDTHH:mm`(초가 있으면 초까지)으로 적는다 — 날짜 · 생성일 · 수정일 · 날짜 수식 · 날짜 롤업
  모두. push 는 오프셋 없는 시각에 그 시간대의 오프셋을 붙인다. 서머타임으로 없는 시각 · 두 번 있는 시각은 앞 오프셋을 쓴다.
  IANA 이름이 아니면 설정을 읽을 때 이유를 말하고 멈춘다.
- **기간.** 시작은 그 키, 끝은 짝 키 `<이름>_end` 에 적는다 — 둘 다 Obsidian 날짜(시각) 속성이다. push 는 둘 중 하나만
  바뀌어도 둘을 한 날짜 값으로 보낸다. 시작 없이 끝만 있으면 보내지 않고 알린다. `<이름>_end` 라는 속성이 DB 에 따로 있으면
  짝 키를 쓰지 않고 예전처럼 객체로 적는다.
- **예전 모양.** 예전 버전이 적은 `…+09:00` · `…Z` · `{start, end}` 는 같은 순간이면 같은 값으로 본다
  (`writableValues` — 옛 `pickWritable`). 업그레이드만으로는 push 할 것이 생기지 않는다.
  - 원격이 그대로인 행은 다시 받지 않는다(N-05) — 그대로 두면 Notion 에서 바뀔 때까지 Obsidian 이 그 행의 날짜를 글로
    본다. 그래서 지난 사본에 예전 모양이 남은 행(같은 순간인데 적힌 모양만 다른 날짜 키)은 pull 이 한 번 다시 받아 새
    모양으로 쓴다(`PropertyMapper.hasOutdatedDateForm` · `DatabaseSyncer.outdatedDateForm`). 다시 쓴 행은 사본도 새
    모양이라 다음 pull 은 건너뛴다.
  - 행은 DB 를 조회할 때만 보이므로 업그레이드 뒤 첫 전체 대조(기본 1시간마다 · `pull --force`)에서 바뀐다.
  - 로컬을 고친 행은 고르지 않는다 — 받아도 로컬 편집을 지키느라 쓰지 않으니 pull 마다 원격만 읽는다. 편집을 올린 뒤
    받는다.
  - 값이 다른 키(다시 계산된 수식 · 롤업, 시간대 설정을 바꾼 벽시계 시각)는 모양 탓이 아니라 고르지 않는다.
- **서식 있는 글.** 글 속성 · 제목은 원격 조각 위에 바뀐 글자만 고친다(`notion/rich-text.ts` 의 `patchRichText`). 앞뒤 같은
  글자를 떼어 가운데만 바꾸고, 바뀐 자리를 감싼 조각의 서식 · 링크를 잇는다. 손대지 않은 멘션 · 수식은 그대로 다시 보내고,
  고친 자리에 걸친 멘션은 글로 보낸다. 조각이 100개를 넘으면 예전처럼 평문으로 보낸다.
- **행 frontmatter 합치기.** pull 이 받은 속성을 로컬 frontmatter 에 합친다(`converter/frontmatter-merge.ts`). Notion 이 정하는
  키(`PropertyMapper.ownedKeys` + `title` · `cover` · `icon`)만 받은 값으로 바꾼다.
  - 값이 같으면 로컬 줄을 글자 그대로 둔다. 바뀐 키는 그 자리에서 다시 적는다.
  - Notion 에서 비운 키는 지우고, 그 뒤의 주석 · 빈 줄은 남긴다. 새 키는 받은 차례에서 앞 키 바로 뒤에 넣는다.
  - 키 단위로 나눠 읽을 수 없는 YAML(앵커 · CRLF · `?` 키 · 한 줄에 키 여럿)은 값만 합친다 — 로컬 키와 차례는 지킨다.
  - 합친 글은 다시 읽어 받은 값과 같은지 확인한다. 다르면 값만 합친 글을 쓴다.

결정 Q3 과 다르게 한 것: Q3 은 「속성 원본을 상태 DB 에 둔다」였다. 상태 DB 대신 push 직전에 읽는 원격 행(`getPage`)의 조각을
쓴다. push 는 원격이 바뀌었는지 보려고 이미 행을 읽으므로 요청이 늘지 않고, 상태 DB 의 원본은 그 사이 Notion 에서 바뀐 서식을
