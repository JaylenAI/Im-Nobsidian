## Notion API 실측(Notion-Version 2025-09-03)

- `PATCH /data_sources/{id}` 는 속성 id 키를 받는다 — `{name}` 이름 · `null` 지우기 · `{number:{}}` 타입(rich_text "12" → 12)
- select 옵션을 보내면 늘고 있던 색은 그대로 · 이름으로 formula · date 더하기 · 있는 이름으로 바꾸면 200 + 「X 1」
- 스키마를 바꿔도 행의 `last_edited_time` 은 그대로
- 다중 소스 DB 에 `parent: {database_id}` 로 행 만들기 → 400 「Databases with multiple data sources are not supported in this API
  version」 · `data_source_id` 부모는 된다

## 실 Notion E2E(탐침 `__p3_schema_20261029__` · 로컬 볼트 둘)

- 볼트 이름 바꾸기: 두 소스에서 각각(같은 속성 id · 값 유지 · `.base` 갱신 · 다음 pull · push 0)
- 이름 + 값 같이(행 2개): 맞게 이름 바꾸기 + 값 반영
- 사이드카: pull 이 고친 사이드카를 지킴 → push 가 이름 · 타입 · 옵션 · date · formula 반영 → pull 이 행 키를 바꿈 · 지운 속성 키 빠짐 ·
  제목 지우기 거절
- Notion 에서 바로 더한 수식 열(ds2) → pull 이 행 · `.base` 에 채움 → push 0
- 다중 소스: ds2 행 고치기 · 새 행(첫 소스) → 다음 pull 1(수식 채움) · push 0

## 진행 중 찾고 고친 것

- 이름 + 값을 같은 push 에서 고치면 옛 열이 비워졌다(모든 행이 같은 값이어야 한다는 규칙) — 같은 값 한 행 이상으로 풀었다
- 사이드카의 보기만 고쳐도 pull 이 영영 지킬 뻔했다 — 속성을 고친 사이드카만 지킨다
- 다중 소스 DB 의 새 행이 400 으로 거절됐다(위 실측) — 첫 소스를 부모로
