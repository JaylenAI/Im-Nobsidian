## Phase 4 — NFM 디자인 충실도 (`feature/nfm-design-fidelity`, ADR-008)

### 목표

NFM raw 가 나르는 디자인 정보(컬럼 구조·콜아웃 아이콘/색·토글 색·블록 색)를
pull↔push 왕복에서 보존한다. 기존엔 pull 이 전부 폐기했고, 구 push(`::: callout`
펜스 + 본문 이모지)는 **이모지를 리터럴 본문 텍스트로 Notion 에 박제**했다(실측).

### 작업 내용

- **실측 선행**: 프로브 페이지에 정준형 생성 → raw 정독 — 아이콘은 본문이 아니라
  `<callout icon="⚠️" color="red_bg">` 속성, 블록 색은 줄 끝 `{color="red"}`,
  `width_ratio` 는 NFM create 가 자체 드롭(보존 불가), verbatim replace 는 무손실.
- **pull**: 컬럼 → legacy block 경로와 동일 어휘의 컬럼 마커로 래핑, 콜아웃 icon/color →
  `%%im-nobsidian:callout-style:…%%` 제목 마커, 토글 색 → `toggle-color` 마커,
  블록 색 → `block-color` 마커. 기본 아이콘+무색은 마커 생략(볼트 노이즈 제거).
- **push**: 마커 → 정준형 태그/속성 재조립(`<columns>/<column>` 탭 들여쓰기, `<callout
icon color>`, `<details color>`, `{color="…"}`), 중첩 콜아웃·토글 재귀 변환,
  컨테이너-중첩 컬럼은 평탄화 degrade + 미소비 마커 일괄 strip(누수 안전망).

### 코드 변경 요약

- `converter/enhanced-md-converter.ts`: pull 4종 캡처 + push 4종 재조립 (+228/-38)

### 목표

잔존 결함을 찾아 0 으로 마감 — churn-0(재 pull 무변경)·push no-op 까지 실측.

### Fresh pull 실측 (v0.3.0+P1~P4 빌드, 55분)

- **1182 페이지 created / 0 failed**, 이미지 741 + 파일 86 로컬라이즈,
  링크 586 해소, 인라인 DB 임베드 재작성 299, `.base` 158, attachments 1159
- 디자인 마커 실측: callout-style 532 · block-color 373 · column-list 231 · toggle-color 6
- 태그/legacy 펜스/마커 리터럴 누수 0

### 전수 감사에서 나온 잔존 결함 4건 + 재분류 1건

1. **콜아웃 제목으로 컬럼 마커 흡수** (4파일 실측): 콜아웃이 컬럼을 품으면 innermost
   평탄화 순서상 start 마커가 본문 첫 줄 → 제목으로 흡수, 줄 앵커 strip 을 벗어남.
   이중 중첩은 구조적 탭(`> > \t%%..%%`)도 남음 → quote 줄 인라인 마커 + 마커 앞
   여백 허용으로 strip 확장 (`stripQuotedColumnMarkers`)
2. **URL 아이콘 마커 오염** (인사이드 아웃): 업로드 이미지 아이콘이 만료 서명 URL 로
   마커에 실려 풀마다 churn → http(s) 아이콘은 마커 제외·색만 보존 (ADR-008 보강 —
   이모지/custom emoji URI/내장 아이콘 경로는 계속 왕복)
3. **DB row cover 서명 URL 잔존** (LIFE/WORK): 다운로드는 성공했는데 결과 재매치
   정규식이 `![cover](..)` 형태를 기대 — 실제 결과는 `![[..]]` 위키링크라 항상
   미스매치 → 서명 URL 폴백. `localizeNotionFileUrl`(P3-A) 재사용으로 교체
4. **degrade 로그 반복** (최대 67회/DB): 임베드 재작성마다 사이드카 재생성 →
   동일 바이트면 쓰기·로그 생략 (byte-compare skip)
5. **재분류 — 버그 아님**: `file://{json}` 26파일은 전부 >100MB 강의 영상의 **의도된
   size-cap degrade** (P3 설계 — 원본 링크 유지, 안정 식별자라 churn 없음).
   `advanced.maxFileSizeBytes` 문서화로 마감 (CONFIGURATION.md)
