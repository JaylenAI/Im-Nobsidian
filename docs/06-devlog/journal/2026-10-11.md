기준선 · 결함 목록 · 계획은 [2026-09-27](2026-09-27.md), Phase 2 는 [2026-10-04](2026-10-04.md) 에

1.12.4 이고 앱은 1.13.7 로 갱신돼 있다(9월 28일부터) — U-02 는 1.13.7 에서, U-01 은 갱신 없는 1.12.4

## 보드 그룹 방향 (U-02)

증상:

- Notion 에서 그룹 순서를 「수동」 으로 둔 보드가 있는 DB 를 받으면 `.base` 가 열리지 않는다 —
  「베이스 파일을 읽어들일 수 없음: "groupBy" 는 반드시 "우선순위 보드" 뷰의 object 이어야 함」.
  표 뷰를 포함해 그 파일의 뷰가 모두 안 보인다. 심층 QA 때 실볼트 `.base` 166개 중 `groupBy` 가 있는
  하나가 이 모양이었다.

원인:

- `base-file-generator.ts` 가 그룹 정렬이 오름 · 내림일 때만 `direction` 을 쓰고, 수동이면 줄을 뺐다.
  Bases 는 `direction` 없는 `groupBy` 를 읽지 못한다.

수정 (`fix/base-groupby-direction`):

- 내림차순이 아니면 `ASC` 로 쓴다. Bases 에는 수동 그룹 순서가 없다.
- 원래 값(`groupBy.sort: "manual"`)은 사이드카(`<DB>.notion.json`)에 그대로 있고, 격하 리포트에 「수동 그룹
  순서는 Bases 미지원 — 오름차순으로 격하」 를 한 줄 더한다. 뷰는 pull 전용이라 push 에 영향이 없다.
- `.base` 는 DB 를 통째로 받을 때 다시 만든다 — 실볼트의 그 파일은 그 DB 를 다음에 통째로 받을 때 고쳐진다.

검증:

- 시험 — 기존 「direction 이 없으면 생략한다」 를 뒤집고, 방향 셋(내림 · 오름 · 정렬 없음)과 사이드카 보고
  (수동이면 보고 · 정렬된 그룹은 보고 안 함)를 더했다. 고치기 전 코드에서는 첫 시험이 실패한다.
- 변이 4가지가 모두 잡힌다 — 수동을 비우기 · 방향 뒤집기 · 보고 빼기 · 정렬된 그룹도 보고.
- 게이트(`fe469ca`) — 230 파일 · 3,542 통과 · 12 건너뜀.
- 격리 Obsidian — 같은 뷰 설정(표 + 수동 순서 보드)으로 dev `6254e5c` 와 이 브랜치 `2decafd` 의 생성기를
  돌려 시험 볼트에 넣고 열었다. dev 것은 위 오류, 이 브랜치 것은 표 3개 결과 · 보드가 「낮음」 「높음」
  두 그룹으로 열린다.

찾은 것 (고치지 않음):

- 수동 순서가 오름차순이 되므로 Notion 과 그룹 차례가 다를 수 있다(이 시험에서는 Notion 쪽 차례를 만들지
  않아 견주지 않았다). Bases 의 그룹 차례를 값 목록으로 정하는 방법은 찾지 못했다.

## 디자인 마커 렌더러 (U-01)

증상:

- pull 은 Obsidian 문법이 없는 Notion 서식(글자색 · 밑줄 · 멘션 · 블록 색 · 콜아웃 아이콘/색 · 토글 색 ·
  표 머리 열/행 · 셀 색)을 `%%im-nobsidian:…%%` 마커로 싣는다. 읽기 보기에서는 Obsidian 이 주석을 그리기
  전에 지워 서식이 보이지 않았고, 편집 화면(Live Preview)에서는 마커 글자가 본문에 흐리게 섞여 보였다.
- 옛 후처리기(`registerColorPostProcessor`)는 그려진 글에서 마커를 찾았다 — 마커가 남는 곳은 인라인
  코드 안뿐이라, 사용자가 코드에 적은 마커 모양 글(`A14`)만 빨갛게 칠했다.

원인:

- 칠할 정보가 그려진 DOM 에 없다. 읽기 보기의 후처리기는 마커가 지워진 뒤에 불리고, 편집 화면에는
  마커를 다루는 확장이 없었다.

수정 (`feature/design-renderer`):

- core `design-markers.ts` — 한 줄의 마커를 읽어 숨길 자리 · 칠할 글 구간 · 블록 색 · 콜아웃 스타일 ·
  표 속성을 돌려준다. 인라인 코드 안 · 짝 없는 닫는 토큰은 우리 것이 아니라 건드리지 않는다.
- 읽기 보기 — 후처리기가 섹션 원문 줄(`getSectionInfo`)을 읽어 블록(콜아웃 · 표 · 문단 · 목록 항목)은
  차례로 짝짓고, 글 구간은 원문 조각을 보이는 글로 바꿔 그려진 글에서 차례대로 찾아 감싼다. 짝이 안
  맞으면 칠하지 않는다.
- 편집 화면 — CodeMirror 확장이 커서가 없는 줄의 마커를 숨기고(`**` 처럼) 글 · 줄을 칠한다. 콜아웃 ·
  표 위젯 안은 읽기 보기와 같은 방식으로 칠한다. 원문 모드는 건드리지 않는다.
- 색은 테마 변수(`--color-<색>-rgb`)를 따르고, 테마에 없는 회색 · 갈색만 정한다. 제목 · 인용은 테마가
  자기 색 변수를 써서 그 변수를 덮어쓴다. 토글은 바탕 없는 모양이라 콜아웃 색 대신 블록 색으로 칠한다.
- 콜아웃 색은 1.13 부터 완전한 CSS 색, 그 전은 RGB 세 값이라 `requireApiVersion("1.13.0")` 로 가른다.
  이모지 아이콘은 아이콘 요소의 속성 + CSS 로 덮는다 — 1.12.4 는 후처리기 뒤에 아이콘을 다시 그려, 안을
  바꾸면 지워졌다(실측).

검증:

- 시험 51개 추가 — 마커 읽기 13(pull 변환기 산출물을 그대로 읽는 것 포함) · 보이는 글 15 · 읽기 보기
  17(픽스처는 1.13.7 이 그린 섹션 DOM) · 편집 화면 5(실제 CodeMirror 편집기) · CSS 색 빠짐 1.
- 변이 15가지가 모두 잡힌다. 처음에 살아남은 둘은 고쳤다 — 겹친 짝 정렬의 동점 처리는 생길 수 없는
  경우라 지웠고, 셀 · 행 · 열 색 우선순위는 시험을 더했다.
- 게이트 — 234 파일 · 3,593 통과 · 12 건너뜀.
- 격리 Obsidian — 디자인 노트(A1~A14)를 읽기 보기 · 편집 화면에서 찍었다. 1.13.7(설치본 1.12.4 가
  자동 갱신한 것)과 갱신 없는 1.12.4 두 판에서 콜아웃 색 · 이모지 아이콘 · 토글 색 · 표 · 같은 글 반복 ·
  인라인 코드 그대로를 확인했다. 커서가 닿은 줄은 마커가 드러나고, 원문 모드는 칠하지 않는다.

찾은 것 (고치지 않음):

- 격리 Obsidian 을 1.12.4 로 알고 있었으나 앱은 1.13.7 이었다(프로필에 `obsidian-1.13.7.asar`). 이 일지
  머리를 고쳤다. 심층 QA 문서의 판 표기는 따로 확인하지 않았다.
- 제목의 `data-heading` 속성에 마커 글이 그대로 있다. 제목 링크 · 개요에 보이는지는 확인하지 못했다.
- 콜아웃 안 문단의 블록 색은 칠하지 않는다 — 읽기 보기가 콜아웃 안 블록에는 원문 줄을 주지 않는다.
- Notion 아이콘이 이모지가 아닌 것(내장 아이콘 · 그림)은 Obsidian 기본 아이콘을 둔다.

## 설정 화면 (U-03)

증상:

- 토큰을 볼트 설정 파일(`.obsidian/plugins/im-notion-sync/data.json`)에 글자 그대로 적었다. 볼트를 git
  등으로 나누면 토큰도 함께 나간다.
- 토큰 · 루트 페이지 ID 칸은 글자를 칠 때마다 저장하고 다시 연결했다 — 칠 때마다 상태 DB 를 닫고 열었다.
- 설명이 실제 동작과 달랐다. 「자동 동기화 — 파일 저장 시 자동으로 Notion에 push」 는 실제로는 저장 2초
  뒤 + 주기마다 sync(방향을 따름)이고, 「자동 Pull 주기」 도 sync 주기다. 자동 동기화 켜기 · 간격은 다음
  실행까지 걸리지 않았고, 범위 밖 간격은 말없이 버렸다.
- 동기화 방향이 Pull만이면 Push 단추 · 명령이 0건으로 조용히 끝났다(반대도 같음). 까닭이 보이지 않았다.
- 날짜시각 시간대(`conversion.timeZone`, F-08)를 플러그인에서 정할 수 없었다.

수정 (`feature/settings-status`):

- 토큰은 Obsidian 키체인(SecretStorage, 1.11.4)에 둔다. 설정에는 비밀의 이름만 적고, 고르개는
  `SecretComponent` 다. 예전 설정을 불러오면 토큰을 키체인으로 옮기고 설정 파일에서 지운 뒤 한 번 알린다.
  키체인은 그 기기의 모든 볼트가 함께 써서, 같은 이름에 다른 토큰이 있으면 덮지 않고 번호를 붙인다.
  옮기지 못하면 토큰을 지우지 않고 까닭을 알린다. `minAppVersion` 을 1.12.4 로 올렸다(Q2 결정).
- 연결 설정(토큰 · 루트 페이지 · 방향 · 시간대)은 바로 저장하고, 창을 닫을 때 한 번 다시 연결한다.
  「연결 상태」 줄이 동기화가 막히는 까닭(빈 설정 · 초기화 실패 · 키체인에 토큰 없음)을 보이고, 「다시
  연결」 이 바로 건다. 빈 설정은 무엇이 비었는지 말한다(예전 「설정을 먼저 완료해주세요」).
- 자동 동기화 켜기 · 간격은 바로 건다. 간격은 고르개(1 · 5 · 10 · 15 · 30 · 60분)이고, 목록 밖 예전 값도
  지금 값으로 보인다. 자동 주기는 초기화가 되면 그 안에서 걸고, 연결 설정을 비우면 옛 연결을 닫고 푼다.
- 방향이 막는 Push · Pull(단추 · 명령 · 파일 하나)은 「동기화 방향이 «Pull만» 이라 Push 하지 않습니다」
  로 알린다.
- 시간대 고르개 — 첫 칸은 「이 컴퓨터의 시간대 (…)」(설정 없음), 나머지는 IANA 이름이다. 설명에 이미
  적힌 시각은 고치지 않고 고치지 않은 날짜는 다시 보내지 않는다고 적었다(2026-10-04 에 미룬 것).
- 플러그인의 설정 기본값을 사본으로 둔다 — 설정을 고치면 기본값 객체까지 바뀌었다(시험 사이로 샜다).

검증:

- 시험 17개 추가 · 고침 — 설정 화면 7(칠 때 다시 연결 안 함 · 닫을 때 한 번 · 자동 동기화 즉시 · 간격 ·
  시간대 · 연결 상태) · 플러그인 9(토큰 이전 4 · 키체인에 없음 · 엔진에 토큰과 시간대 · 자동 주기 ·
  방향 알림 · 빈 설정 문구) · core 1(시간대를 바꿔도 고치지 않은 날짜는 안 보내고, 고친 날짜만 새 시간대
  오프셋으로 보냄).
- 변이 22가지가 모두 잡힌다. 처음 살아남은 하나(준비됨일 때 경고색)는 시험을 더했다.
- 게이트 — 234 파일 · 3,603 통과 · 12 건너뜀.
- 격리 Obsidian 1.13.7 — 플러그인을 다시 띄워 토큰이 키체인으로 옮겨지고 설정 파일에 `token` 키가 없는
  것을 봤다. 설정 창에서 루트 페이지 ID 를 한 글자씩 쳐도 다시 연결 0번, 방향 · 시간대를 바꾸고 닫으면
  1번이고 엔진 설정에 `pull` · `America/New_York` 이 들어갔다. 자동 동기화를 켜면 바로 주기가 걸리고 간격
  10분이 바로 저장됐다. Push 명령은 방향 알림을 띄웠다. 없는 비밀 이름으로 다시 연결하면 연결 상태가
  까닭을 경고색으로 보였고, 「연결…」 에서 비밀을 고르고 닫으면 다시 연결됐다. 끝에 처음 설정으로 되돌렸다.
- 격리 Obsidian 1.12.4 — 설정 화면 · 키체인 고르개 · 비밀 고르기 · 연결 상태(가짜 비밀, Notion 에 닿지
  않음)를 확인했다.

찾은 것 (고치지 않음):

- 루트 페이지 ID 칸에 페이지 주소를 통째로 넣으면 그대로 저장된다 — 초기화는 되고 첫 동기화에서 실패한다.
  주소에서 ID 를 뽑지는 않았다.
- 사이드바의 Push · Pull 단추는 방향이 막아도 눌린다(누르면 알림). 단추를 막으려면 사이드바 상태 모양을
  바꿔야 해 하지 않았다.
- 「준비됨」 은 Notion 에 묻지 않는다 — 토큰이 맞는지는 첫 동기화가 안다.
- 플러그인 설정(키체인 · 시간대)을 설명하는 사용자 문서가 없다 — 안내서는 CLI 설정만 다룬다. 릴리스
  문서에서 다룬다.

## 설치와 배포 파일 (U-04 · U-05)

증상:

- 디렉터리 · BRAT 으로 설치하면 첫 실행부터 초기화가 실패했다. Obsidian 은 릴리스에서 세 파일(`main.js` ·
  `manifest.json` · `styles.css`)만 받는데, 플러그인은 네 번째 파일 `sql-wasm.wasm`(SQLite 엔진)을 읽었다.
- 그 파일을 `<볼트>/.obsidian/plugins/…` 에서 찾았다. 설정 폴더 이름을 바꾼 볼트(설정 → 파일 및 링크)에서는
  파일을 넣어 두어도 못 찾았다.
- `manifest.json` · `versions.json` 이 레포 루트에 없었다. Obsidian 앱 · BRAT · 디렉터리는 루트를 읽는다.
- 릴리스 태그가 `vX.Y.Z` 라 Obsidian 이 받는 주소(`releases/download/<버전>/`)가 없었다.
- 디렉터리 검사(`obsidianmd/obsidian-workflows` v1.2.3)가 manifest 설명의 브랜드 이름을 오류로 냈다.

원인:

- 엔진을 따로 내려받는 파일로 둔 것(ADR-006)이 디렉터리의 세 파일 설치와 맞지 않았다.
- 설정 폴더를 `.obsidian` 으로 코드에 적었다.
- 처음부터 플러그인 폴더에만 manifest 를 두었다. 레포의 연구 문서는 루트에 두라고 적었다.

수정 (`fix/plugin-distribution`):

- 엔진을 esbuild 의 binary 로더로 main.js 에 싣고 `wasmBinary` 로 넘긴다. 상태 DB 경로는 볼트 루트에서
  만든다. 플러그인 폴더에서 읽는 파일이 없다(ADR-031). main.js 888KB → 1.79MB.
- `manifest.json` · `versions.json` 을 루트로 옮겼다. 빌드가 루트 manifest 를 플러그인 폴더에 옮겨 둔다.
  설명에서 브랜드 이름을 빼고, 레포를 가리키던 `fundingUrl` 을 뺐다(ADR-032).
- `release.yml` — 세 파일 · 태그와 manifest 버전 · `versions.json[버전]` 과 `minAppVersion` 을 확인한 뒤
