## 블록 방식 push — NFM 을 블록으로 (`fix/block-push-vault-forms`)

증상:

- `preferMarkdownApi: false`(블록 방식)로 push 하면 Markdown API 경로와 다른 페이지가 됐다. 같은 노트를 두 변환에
  넣으니 콜아웃은 글에 `[!tip] 제목` 이 남은 인용이 되고, `[[콜아웃]]` 위키링크는 링크 없는 글이 됐다.
- 5단계 목록은 3단계로 평탄화되고, 150행 표는 100행 이하 표 여럿으로 쪼개졌다.

원인:

- 블록 방식은 볼트 마크다운을 martian 으로 바로 블록으로 바꿨다. Markdown API 경로의 NFM 변환(콜아웃 · 멘션 ·
  마커)을 거치지 않았다. 두 길이 같은 볼트 모양을 따로 구현하고 있었다.

수정 (ADR-035):

- 블록 방식도 Markdown API 경로와 같은 NFM 을 만든다. 그 NFM 을 Notion 의 가져오기와 같은 블록으로
  옮긴다(`nfmToBlocks`). 규칙은 탐침 페이지 20장의 NFM · 블록 트리 짝으로 정했다(`tests/fixtures/nfm/notion-import/`).
- 블록은 깊이 제한 없이 만든다. `NotionClient.appendBlockTree` 가 요청 한도(자식 두 단계 · 배열 100 개 · 블록 1000 개 ·
  500KB) 안으로 나눠 보내고, 넘는 자식은 부모를 만든 뒤 그 아래에 붙인다.
- 북마크는 볼트의 링크 쌍에서 주소 · 캡션을 받아 새로 만든다(`vaultBookmarks`).
- 블록 API 가 거부하는 모양은 바꿔 보낸다 — 칼럼 하나짜리 묶음은 펼치고, 빈 인라인 수식은 글자로 둔다. 색 없는
  목차는 `color: "default"` 로 보낸다(빼면 회색이 된다, 실측).

검증:

- 게이트 통과 — 시험 3,745 → 3,792.
- 픽스처 20장 — 일부러 다르게 만든 8장(`why`)을 빼면 Notion 의 블록 트리와 같다.
- 변이 26개를 모두 잡았다. 처음 돌렸을 때 살아남은 3개(크기 초과 때 깊이 줄이기 · 칼럼의 남은 자식 경로 · 빈 칼럼의
  머리 문단)는 시험을 더해 잡았다.
- 실 Notion(탐침 `__c14_bm_*` 28장) — 만든 블록을 다시 읽어 보낸 것과 견줬다. 25장이 같다. 남은 3장의 차이는
  아이콘 없는 콜아웃의 💡 와 시간 있는 날짜 멘션의 오프셋 표기다(ADR-035 의 한계). 8단계 목록 · 150행 표 · 형제
  230개 · 목록 속 토글 속 표와 탭이 그대로 만들어졌다.
- CLI 왕복(탐침 볼트 4개, 노트 4장: 콜아웃 · 코드 · 목록 · 미디어):

| 동작                                                     | 결과                                                                             |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 블록 방식 push(`__c14_bmvault`) → 다른 볼트로 pull       | 4장 생성 · 그림 1개 업로드                                                       |
| 같은 노트를 Markdown API 로 push(`__c14_mdvault`) → pull | 받은 노트 4장이 블록 방식으로 받은 노트와 같다(북마크 줄 빼고 — 아래 찾은 것 N6) |
| 블록 방식으로 고쳐 push(할 일 · 표 행 · 콜아웃을 더함)   | 옛 블록이 지워지고 새 블록만 남는다 — 중복 없음 · 5단계 목록 그대로              |
| 위키링크 `[[콜아웃]]`                                    | 페이지 멘션으로 만들어진다                                                       |

찾은 것 (고치지 않음):

- N6 — Markdown API 경로에서 볼트의 북마크 링크 쌍이 없는 블록을 가리키면 Notion 이 「Block … does not exist」 로 본문을
  거부해 페이지 push 전체가 실패한다. 블록 방식은 링크 쌍의 주소로 새 북마크를 만들므로 실패하지 않는다.
- `> [!faq]-` 는 왕복하면 `> [!question]` 이 된다(접힘 · 별칭을 잃는다). 블록 방식과 Markdown API 경로가 같다.
- `**b**{color}` 처럼 서식 바로 뒤에 붙은 색 속성은 읽지 않는다(픽스처 inline3). 볼트 → NFM 변환은 이 모양을
  만들지 않는다.
- 블록 → NFM → 블록 왕복에서 토글 안 여러 줄 수식이 같은 트리로 돌아오지 않는다(코퍼스 nfm-page2). NFM 이 식의 첫
  줄만 들여쓰기 때문이다(ADR-034, Notion 의 export 와 같다). 제품 경로는 아니다.
- 새로 만든 페이지가 바로 다음 증분 pull 에 잡히지 않고 그다음 pull 에 들어왔다. search 색인 지연(F20)이다.
