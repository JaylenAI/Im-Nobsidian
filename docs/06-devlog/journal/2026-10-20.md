## 블록 방식 push — NFM 을 블록으로 (`fix/block-push-vault-forms`)

증상:

- `preferMarkdownApi: false`(블록 방식)로 push 하면 Markdown API 경로와 다른 페이지가 됐다. 같은 노트를 두 변환에
  넣으니 콜아웃은 글에 `[!tip] 제목` 이 남은 인용이 되고, `[[콜아웃]]` 위키링크는 링크 없는 글이 됐다.
- 5단계 목록은 3단계로 평탄화되고, 150행 표는 100행 이하 표 여럿으로 쪼개졌다.

원인:

- 블록 방식은 볼트 마크다운을 martian 으로 바로 블록으로 바꿨다. Markdown API 경로의 NFM 변환(콜아웃 · 멘션 ·
  마커)을 거치지 않았다. 두 길이 같은 볼트 모양을 따로 구현하고 있었다.

수정 (ADR-035):

- 블록 방식도 Markdown API 경로와 같은 NFM 을 만든다. 그 NFM 을 Notion 의 가져오기와 같은 블록으로
  옮긴다(`nfmToBlocks`). 규칙은 탐침 페이지 20장의 NFM · 블록 트리 짝으로 정했다(`tests/fixtures/nfm/notion-import/`).
- 블록은 깊이 제한 없이 만든다. `NotionClient.appendBlockTree` 가 요청 한도(자식 두 단계 · 배열 100 개 · 블록 1000 개 ·
  500KB) 안으로 나눠 보내고, 넘는 자식은 부모를 만든 뒤 그 아래에 붙인다.
- 북마크는 볼트의 링크 쌍에서 주소 · 캡션을 받아 새로 만든다(`vaultBookmarks`).
- 블록 API 가 거부하는 모양은 바꿔 보낸다 — 칼럼 하나짜리 묶음은 펼치고, 빈 인라인 수식은 글자로 둔다. 색 없는
  목차는 `color: "default"` 로 보낸다(빼면 회색이 된다, 실측).

검증:

- 게이트 통과 — 시험 3,745 → 3,792.
- 픽스처 20장 — 일부러 다르게 만든 8장(`why`)을 빼면 Notion 의 블록 트리와 같다.
- 변이 26개를 모두 잡았다. 처음 돌렸을 때 살아남은 3개(크기 초과 때 깊이 줄이기 · 칼럼의 남은 자식 경로 · 빈 칼럼의
  머리 문단)는 시험을 더해 잡았다.
- 실 Notion(탐침 `__c14_bm_*` 28장) — 만든 블록을 다시 읽어 보낸 것과 견줬다. 25장이 같다. 남은 3장의 차이는
  아이콘 없는 콜아웃의 💡 와 시간 있는 날짜 멘션의 오프셋 표기다(ADR-035 의 한계). 8단계 목록 · 150행 표 · 형제
  230개 · 목록 속 토글 속 표와 탭이 그대로 만들어졌다.
- CLI 왕복(탐침 볼트 4개, 노트 4장: 콜아웃 · 코드 · 목록 · 미디어):

| 동작                                                     | 결과                                                                             |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 블록 방식 push(`__c14_bmvault`) → 다른 볼트로 pull       | 4장 생성 · 그림 1개 업로드                                                       |
| 같은 노트를 Markdown API 로 push(`__c14_mdvault`) → pull | 받은 노트 4장이 블록 방식으로 받은 노트와 같다(북마크 줄 빼고 — 아래 찾은 것 N6) |
| 블록 방식으로 고쳐 push(할 일 · 표 행 · 콜아웃을 더함)   | 옛 블록이 지워지고 새 블록만 남는다 — 중복 없음 · 5단계 목록 그대로              |
| 위키링크 `[[콜아웃]]`                                    | 페이지 멘션으로 만들어진다                                                       |

찾은 것 (고치지 않음):

- N6 — Markdown API 경로에서 볼트의 북마크 링크 쌍이 없는 블록을 가리키면 Notion 이 「Block … does not exist」 로 본문을
  거부해 페이지 push 전체가 실패한다. 블록 방식은 링크 쌍의 주소로 새 북마크를 만들므로 실패하지 않는다.
- `> [!faq]-` 는 왕복하면 `> [!question]` 이 된다(접힘 · 별칭을 잃는다). 블록 방식과 Markdown API 경로가 같다.
- `**b**{color}` 처럼 서식 바로 뒤에 붙은 색 속성은 읽지 않는다(픽스처 inline3). 볼트 → NFM 변환은 이 모양을
  만들지 않는다.
- 블록 → NFM → 블록 왕복에서 토글 안 여러 줄 수식이 같은 트리로 돌아오지 않는다(코퍼스 nfm-page2). NFM 이 식의 첫
  줄만 들여쓰기 때문이다(ADR-034, Notion 의 export 와 같다). 제품 경로는 아니다.
- 새로 만든 페이지가 바로 다음 증분 pull 에 잡히지 않고 그다음 pull 에 들어왔다. search 색인 지연(F20)이다.

## 변환기 작은 결함 묶음 (`fix/converter-small`)

증상:

- C1 — Notion 에서 색을 입힌 접는 제목(`### 제목 {toggle="true" color="red_bg"}`)을 받으면 속성 글이 제목에 남고
  자식이 접히지 않은 채 흩어졌다.
- N5 — 블록 API 로 받은 노트(폴백 · `preferMarkdownApi: false`)에서 제목 4 가 모르는 블록 태그가 됐다.
- C6 — 이스케이프한 백틱(`` \` ``)도 인라인 코드의 시작으로 봤다. 두 `` \` `` 사이의 `[[위키링크]]` 가 코드로
  여겨져 멘션이 되지 않았다.
- C7 — 사용자 멘션 이름에 `%%%` 가 있으면 `%%` 가 남아 Obsidian 주석이 열렸다.
- C8 — 동영상 이미지 링크(`![캡션](youtube…)`)를 push 하면 Notion 에 마커 글
  (`%% im-nobsidian:embed:type=video… %%`)과 캡션 문단이 올라갔다. 대체 글에 인라인 코드가 들면 링크가 조각나 그림
  블록이 됐다.
- 임베드 4칸 — 목록 항목 아래를 두 칸으로 들여 쓴 노트(`  ![[a.png]]`)를 Notion 에서 고친 뒤 받으면 그 자식 줄이
  네 칸으로 바뀌었다.
- C11 — 렌더 감사 ⑧ 이 펜스 모양 줄의 개수로 짝을 셌다. 코드 속 ` ```bash ` 줄 때문에 짝이 맞아 보여도 새는
  문서와 짝이 안 맞아 보여도 정상인 문서를 틀리게 봤다.
- C12 — `child-tags` 가 펜스를 따로 판정해 코드 속 ` ```bash ` 줄에서 코드를 닫았다. `callout-indent` 의
  `visualWidth` 는 `indentWidth` 와 같은 일을 했다.

원인:

- C1 — 접는 제목 정규식이 `{toggle="true"}` 만 알았다. push 쪽도 색 마커를 토글 속성과 합치지 않았다.
- N5 — `blocksToNfm` 이 `heading_1` ~ `heading_3` 만 알았다.
- C7 — `/%%/g` 를 한 번 바꿔 `%%%` 가 `%` + `%` 로 남았다.
- C8 — 처음 구현 때 넣은 embed 마커를 읽는 곳이 없었다. 이미지 링크를 그대로 보내면 Notion 은 그림 블록을 만든다.
- 임베드 4칸 — 받은 글을 로컬 표기로 되돌릴 때 견주는 「보낼 꼴」(`sentForm`)이 들여쓰기를 글자 그대로 견줬다.
  Notion 은 앞 블록보다 깊은지만 읽으므로 두 칸 · 네 칸 자식은 같은 블록인데 다르다고 봤다.

수정:

- C1 — 색은 일반 제목과 같은 블록 색 마커로 두고 토글 마커를 줄 끝에 둔다. push 는 줄 끝 `{color="…"}` 를
  `{toggle="true" color="…"}` 로 합친다.
- N5 — `heading_4` 를 `####` 로 쓴다(2026-10-20 export 실측: `#### 제목` · 접으면 `{toggle="true"}` + 탭 자식).
- C6 — 앞의 백슬래시가 홀수 개인 백틱은 코드를 열지 않는다(CommonMark). 닫는 백틱은 코드 안이라 보지 않는다.
- C7 — `/%%+/g` 로 한 번에 `%` 로 바꾼다.
- C8 — 동영상 이미지 링크는 볼트의 동영상 표기 `[🎬 캡션](URL)` 로 바꾼다. push 가 `<video src>` 로 보낸다.
  이미지 링크는 펜스 밖 글 전체에서 찾고, 인라인 코드 안에서 시작한 것만 건너뛴다.
- 임베드 4칸 — `sentForm` 이 코드 · 수식 밖 줄의 들여쓰기를 깊이만큼의 탭으로 바꿔 견준다. 폭은 Notion 처럼
  탭 · 공백 하나씩 센다. 코드 · 수식 줄은 그대로 둔다.
- C11 — 펜스를 실제로 짝지어(`openCodeFence` · `closesCodeFence`) 닫히지 않은 펜스만 잡는다.
- C12 — `child-tags` 는 `codeLineMask`, `callout-indent` 는 `indentWidth` 를 쓴다.

검증:

- 게이트 통과 — 시험 3,792 → 3,809. 더한 시험은 수정 전 코드에서 모두 실패했다.
- 변이 13개를 모두 잡았다.
- 실 Notion(탐침 `__p1_vault`, 볼트 둘: Markdown API · 블록 방식) CLI 왕복:

- C7 은 실 Notion 에서 재지 않았다 — 탐침에서 사용자 멘션을 만들지 않는다. 단위 시험으로만 확인했다.

찾은 것 (고치지 않음):

- N7 — 목록 항목 아래 동영상 · 소리 · 파일 · PDF(`\t<video src>`)를 받으면 들여쓰기를 잃고 목록 밖 문단이 된다
  (`convertMediaTags` 정규식이 앞 공백을 삼킨다). 임베드 `<embed>` 는 들여쓰기를 지킨다. 구조 묶음
  (`fix/converter-structure`)에서 고친다.
- N8 — 새 볼트를 처음 push 할 때 `백틱.md` 의 `[[임베드칸]]` 이 멘션이 되지 않고 글로 올라갔다. `백틱.md` 가
  `임베드칸.md` 보다 먼저 만들어졌다. 노트를 고쳐 다시 push 하자 멘션이 됐다 — 고치지 않은 노트는 다시 올라가지 않아
  글로 남는다. 만드는 차례 탓으로 보이나 원인은 확인하지 않았다.
