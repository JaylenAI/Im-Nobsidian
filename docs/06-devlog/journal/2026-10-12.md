# 2026-10-12 — v0.4.0 Phase 4 뒤: 남은 결함 봉합

Phase 4 까지는 [2026-10-11](2026-10-11.md) 에 있다. 여기는 그 뒤에 남은 것 — 미디어 재업로드부터, 지난 일지들의
「찾은 것 (고치지 않음)」 을 다시 가려 아직 열린 결함을 고친다.

## 미디어 재업로드 (`fix/media-reupload`)

증상:

- 본문을 고쳐 push 하면 그 페이지의 미디어를 바뀌지 않은 것까지 모두 다시 올린다. 이미지 3 · 파일 1 인 탐침
  노트의 글 한 줄 push 가 요청 24번(업로드 4 · 블록 붙이기 4 · 자리표시자 지우기 4 …)이었다.
- Notion 의 블록 id · 파일이 매번 바뀐다.
- Notion 에서 올린 캡션 없는 파일을 받아 둔 노트를 push 하면 별칭(받은 이름)이 캡션으로 붙고, 파일 이름이
  볼트에 저장한 이름(`이름-해시.ext`)으로 바뀐다.

원인:

- 본문 push 가 임베드를 자리표시자로 바꿔 본문을 통째로 교체한 뒤 자리표시자를 하나씩 올린다(R1). 교체가 옛
  미디어 블록을 지우므로 ADR-020 의 올린 미디어 기록이 있어도 쓸 데가 없었다.
- pull 이 받은 미디어는 기록하지 않았다.

실측 (탐침 페이지 `__p5_media_a/b/c`):

- 받은 본문의 미디어 줄(`![캡션](서명 URL)` · `<file src="서명 URL">캡션</file>`)을 그대로 실어 교체하면 Notion 이
  그 블록을 둔다 — 블록 id · 파일 id 가 같다. 서명을 떼도, 콜아웃 안으로 옮겨도 같다.
- 캡션은 보낸 글로 바뀐다(바꿈 · 비움 · 빈 캡션에 붙임 모두). 파일 블록의 `name` 은 그대로다.

수정 (ADR-033):

- 본문을 보내기 전에 받은 본문을 한 번 읽고, 기록과 맞는 자리표시자를 Notion 의 그 파일로 바꾼다 — 종류 ·
  경로 · sha256 지문이 같고, 캡션 · URL 을 글자 그대로 실을 수 있을 때만. 나머지는 예전처럼 올린다.
- 올린 미디어 기록에 지문(`fileHash`)을 더했다. 옛 기록은 한 번 더 올리고 그때 적는다.
- pull 이 받은 미디어도 기록에 더한다(`rememberReceivedMedia`).
- 캡션 없이 받은 파일은 캡션을 비운 채 둔다. 다시 받을 때도 그 별칭을 지우지 않는다.
- 모두 그대로 뒀으면 블록을 훑지 않는다 — 보낸 본문에 자리표시자가 없다.

검증:

- 게이트(build · lint · format · typecheck · coverage) 통과 — 시험 3,609 → 3,631(새 시험 22: 그대로 두기 18 ·
  기록 4). 기존 시험 셋은 「다시 올린다」 던 기대를 「두고 바뀐 것만 올린다」 로 고쳤다.
- 변이 18개 중 16개를 잡았다. 남은 둘은 결과가 같은 변이다 — 지문 없는 기록을 줄 세우기에서 빼는 것(뒤에서 지문
  비교로 어차피 떨어진다), 처리한 임베드에 별칭째 대상을 넣는 것(볼트 경로 · 경로만 대상이 같은 일을 한다).

- 받은 노트에서 목록 항목 아래 임베드가 4칸으로 들여 받힌다(`  ![[…]]` → `    ![[…]]`). 이번 수정과 무관한 기존
  pull 모양이다 — 옛 4칸 모양이 남는 것과 함께 릴리스 노트에 적을 거리.
- 플러그인에서 같은 흐름은 따로 재지 않았다 — core 를 그대로 쓴다.

## 지운 페이지 · 받기 전용 · 복원 수 · 복제 사본 (`fix/remote-deletion-guards`)

지난 일지들의 「찾은 것」 가운데 원격 삭제 · 충돌 해결 언저리 다섯을 다시 쟀다(A1 · A2 · B1 · B2 · B3).

증상:

- Notion 에서 지운(휴지통) 페이지의 노트를 고쳐 push 하면 `This page is in the trash. It must be restored before it
can be updated.` 로 실패했다. sync 를 돌릴 때마다 같은 영어 오류였고, status 는 «수정됨» 만 보였다. 사용자가 고를
  길이 없었다(2026-10-12 실측, deleteSync 꺼짐 · 탐침 `__p5_trash`). API 의 `push({ force: true })` 도 같은
  경로를 탄다(B2 — 코드로 확인, 실측하지 않음).
- 받기 전용(`direction: "pull"`)인데 충돌을 로컬 유지 · 병합 · 복제로 풀면 결과를 Notion 에 올렸다(A2).
- 볼트에서 지운 파일을, 그 페이지가 Notion 에서도 바뀐 뒤에 받으면 «업데이트» 로 셌다. 원격이 그대로일 때만
  «복원» 이었다. DB 행도 같았다(B3).
- 「복제」 로 푼 뒤 생긴 `노트.conflict.md` 를 다음 push 가 새 페이지로 올렸다 — 원격 본문이 Notion 에 한 벌 더 생겼다(B1).

원인:

- 원격 삭제를 알아채는 것은 deleteSync 를 켠 pull 의 전체 대조뿐이다. push 는 원격이 있는지 보지 않고 고쳐 보냈다.
- 해소 전파(`propagateResolution`)가 방향을 보지 않았다.
- 복원 수는 «원격 무변경이라 따로 큐에 올린 것» 만 셌다. 이미 원격 변경으로 큐에 오른 페이지 · 행은 빠졌다.
- 변경 감지가 사본 이름을 몰랐다.

A1 은 고칠 것이 없었다. 「deleteSync 를 끄면 원격 삭제 뒤 push 가 새 페이지로 되살린다」 는 기록이었는데, 그 경로
(`decideRemoteDeletion` 의 `deleteFile: false`)는 deleteSync 를 켠 pull 에서만 불린다. 실제로 일어난 것은 위의 영어
오류였고, 그것을 고쳤다.

수정:

- push 가 고치거나 옮기기 전에 원격이 있는지 본다(`livePage`, `remotePresence`) — 휴지통 · 보관 · 없음(404)이면
  충돌로 남기고 무엇을 고를지 말하는 실패를 낸다. 충돌로 남은 노트는 다음 push 가 건드리지 않는다. 충돌 해결은 이미
  있던 «원격 삭제 충돌» 그대로다 — 로컬 유지는 새 페이지로 다시 만들고, 삭제 따르기는 볼트에서 지운다.
- 받기 전용이면 해소 결과를 Notion 에 쓰지 않는다. 대신 원격을 본 것으로 적는다 — 수정 시각과 본문 지문까지
  (`recordRemoteSeen`). 수정 시각만 적으면 다음 pull 이 «로컬 그대로 · 원격 확인 안 됨» 으로 보고 고른 로컬을 원격으로
  덮었다(시험을 쓰다 찾았다). 충돌을 본 뒤 Notion 이 또 바뀌었으면 그 변경은 본 것으로 적지 않는다 — 다음 pull 이 받는다.
- CLI `resolve` 와 플러그인 충돌 창이 받기 전용일 때 «Notion 에 올리지 않는다» 고 말한다.
- 복원 수 — 볼트에서 사라진 추적 파일이면 원격 변경으로 받아도 복원으로 센다. dry-run 도 같다. DB 행도 같다.
- 변경 감지가 추적하지 않는 `*.conflict.md` 를 건너뛴다(`isConflictCopyPath`). 이름을 바꾸면 여느 노트처럼 올린다.

검증:

- 게이트(build · lint · format · typecheck · coverage) 통과 — 시험 3,631 → 3,651(새 시험 20: core 16 · CLI 2 ·
  플러그인 2).
  기존 시험 넷은 mock 볼트가 파일을 읽어 주면서 «없다» 고 답하던 것을 «있다» 로 맞췄다. 하나(원격 변경 + 사라진 파일)는
  기대를 «업데이트 1» 에서 «복원 1» 로 고쳤다.
- 변이 12개를 모두 잡았다 — 원격 확인 빼기 · 충돌 표시 빼기 · 옮기기 확인 빼기 · 방향 무시 · 본 것 적기 늘 · 안 함 · 지운
  노트 다시 만들기 · 복원 수 셋 · 사본 올리기.
- 실 Notion(탐침 볼트 `p5/kd`, deleteSync 꺼짐):

| 동작                                        | 결과                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| 휴지통 페이지의 노트를 고쳐 push            | 실패 1 — 한국어 사유 · 충돌로 남김 · 요청 3(GET 뿐)                     |

찾은 것 (고치지 않음):

- deleteSync 를 끈 채 Notion 에서 지운 페이지는 그 노트를 고치기 전에는 알 길이 없다 — status 도 보이지 않는다. 알아채려면
  추적 페이지마다 조회해야 한다. deleteSync 를 켜면 전체 대조가 잡는다.
- DB 행이 같은 분 안에 바뀐 채 받기 전용으로 풀면, 행의 «본문 밖» 비교가 해소 결과와 원격 속성을 견주어 다음 pull 이 원격으로
  덮을 수 있다. 수정 시각이 가라앉은 뒤(1분+)에는 «그대로» 로 본다. 재지 않았다.

## 블록 폴백 — 멘션 · 북마크 · 임베드 · `$` (`fix/block-fallback`)

Markdown API 로 받지 못한 페이지(또는 `preferMarkdownApi: false`)는 블록 API 로 받는다. 그 길과 블록 방식 push 를
다시 쟀다(A3 · C9 · C10).

증상:

- 블록 API 로 받은 노트의 멘션이 보이는 글이었다 — 사용자 `@이름`, 날짜 `2026-09-26T09:00:00.000+09:00`, 페이지
  `[제목](https://www.notion.so/…)`. 그 노트를 push 하면 Notion 의 멘션이 글 · 링크가 됐다(A3).
- 북마크가 마커 없는 `[캡션](주소)`, 임베드가 마커 없는 링크였다. push 하면 문단 링크가 됐다(C10).
- 블록 방식 push(martian)가 짝이 맞는 `$` 를 모두 수식으로 보냈다 — `가격 $5 와 $10` 이 수식 `5 와 `,
  `$ x $` 도 수식이었다(C9).
- 블록 방식 push 가 보존 마커를 글자 그대로 Notion 에 남겼다 — 코퍼스 10장 중 6장(토글 제목 · 콜아웃 모양 · 표 ·
  임베드 · 멘션 · 자리 태그). 이번에 쟀다.

원인:

- notion-to-md 의 기본 렌더는 멘션을 `plain_text` 로만 낸다. 우리 `formatMention` 은 사용자 변환기를 단 블록
  (토글 · 콜아웃 · 제목 등)에서만 불렸고, 그마저 Markdown API 경로와 다른 모양을 냈다.
- 북마크 · 임베드 변환기가 Markdown API 경로의 «링크 + 마커» 한 쌍을 몰랐다.
- martian(remark-math)의 인라인 수식 규칙이 Notion 과 다르다.
- 블록 방식 push 는 마커를 블록으로 되돌리는 갈래가 몇 가지(토글 · 칼럼 · 목차)뿐이었다.

Notion 의 모양(탐침 `__bf_mentions` · `__bf_dollars` · `__bf_dollars2`, 2026-10-12):

- 블록 API 의 날짜 멘션은 시각이 있으면 늘 오프셋(`+09:00`)이고 `time_zone` 은 null 이다. `Asia/Seoul` 로 만들어도
  그렇다. Markdown API 는 같은 멘션에 `timeZone="Etc/GMT-9"` 를 붙인다(`+00:00` → `UTC`,
  `+05:30` → `Asia/Calcutta`).
- Markdown API 는 봇 멘션을 내보내지 않는다. 사용자는 `<mention-user url="user://<id>"/>`.
- Markdown API 의 북마크 자리 주소는 `https://app.notion.com/p/<페이지>#<블록>` — 토글 안 북마크도 페이지를 싣는다.
- Notion 의 인라인 수식(줄마다): 여는 `$` 는 앞이 글자 · 숫자가 아니고 뒤가 공백이 아니다. 닫는 `$` 는 다음 첫 `$`
  (수식 안의 `\$` 도)로, 앞이 공백이 아니고 뒤가 글자 · 숫자 · `$` 가 아니다. 맞지 않으면 여는 `$` 는 글이고 그 닫는
  `$` 부터 다시 본다. `$a $b$` → `$a ` 글 + 수식 `b`, `$a\$ $c$` → 수식 `a\` + 수식 `c`.

수정:

- 폴백 pull — notion-to-md 를 감싸(`VaultNotionToMarkdown`) 모든 블록의 멘션을 Markdown API 경로와 같은 볼트 글로
  바꾼다(`markMentions`). 사용자 · 날짜는 짝 마커, 페이지 · DB 는 `[[notion:<id>]]` 를 거쳐 제목 위키링크. 날짜의
  시간대는 오프셋에서 다시 짓는다 — 시 단위가 아닌 오프셋은 같은 순간을 UTC 로 적는다. 봇은 글로 둔다.
- 폴백 pull — 북마크 · 임베드를 Markdown API 경로와 같은 링크 · 마커 한 쌍으로 낸다(`bookmarkVaultLink`,
  `embedVaultLink`). 북마크 마커의 페이지 칸은 받는 쪽이 채운다 — 페이지들을 동시에 받으므로 변환기에 적어 둘 수 없다.
- 블록 방식 push — 한 줄짜리 북마크 · 임베드 쌍은 북마크 · 임베드 블록으로 되돌린다. 북마크 주소는 링크 짝 때문에
  인코딩한 괄호를 푼다. 되돌리지 못한 마커는 걷는다(보이는 글은 남는다). 토글 안도 같다.
- 블록 방식 push — Notion 이 수식으로 읽지 않는 `$` 를 `\$` 로 바꿔 보낸다(`escapeLiteralDollars`). 코드 · 블록 수식
  식 줄은 건드리지 않는다.

검증:

- 게이트 통과 — 시험 3,651 → 3,702(새 51: 블록 폴백 49 · pull 경로 1 · 날짜 1). 기존 날짜 멘션 시험의 기대를 짝
  마커로 고쳤다.
- 변이 29개를 모두 잡았다 — `$` 규칙 여덟 · 마커 걷기 셋 · 임베드 · 북마크 캡션 · 토글 안 · 페이지 칸 채우기 ·
  멘션 감싸기 · 자리 주소 · 괄호 · 시간대 다섯 · 봇 · 바꾸지 않은 조각 · pull 위키링크 되돌리기.
- 코퍼스 10장을 블록 방식으로 보냈을 때 남는 마커 0(전에는 6장).
- 실 Notion(탐침 볼트 `bf/vault`, 페이지 `__bf_e2e`):

| 동작                            | 결과                                                                                     |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| 블록 API 로 pull                | 사용자 · 날짜 짝 마커 · 페이지 `[[__bf_target]]` · 북마크 둘 · 임베드 한 쌍              |
| 한 줄 고쳐 Markdown API 로 push | 사용자 · 날짜 · 페이지 멘션 그대로 · 북마크 · 임베드 블록 id 그대로                      |
| 한 줄 고쳐 블록 방식으로 push   | 북마크 · 임베드 블록(새 id) · 주소 `a(b)` 그대로 · 마커 글자 0 · `$a $b$` → `$a ` + 수식 |

찾은 것 (고치지 않음):

- 블록 폴백 pull 이 토글 블록을 통째로 버린다 — notion-to-md 가 토글의 본문을 건너뛰고, 사용자 변환기를 단 블록은
  자식을 따로 넘기지 않는다. dev 에서도 같다. 그 노트를 push 하면 Notion 의 토글과 안의 블록이 지워진다(위 탐침에서
  실제로 지워졌다). 바로 다음 브랜치로 고친다.
- 블록 방식 push 는 멘션 · 위키링크를 글로 보낸다(멘션 마커 걷기는 전부터 그랬다). 따로 고친다.
- 봇 멘션 — Markdown API 가 내보내지 않으므로 폴백도 `@이름` 글로 둔다. push 하면 Notion 에서 글이 된다.
- 폴백 날짜는 `Asia/Seoul` 같은 지역 이름을 잃는다(블록 API 가 주지 않는다) — 순간은 같다.
- Markdown API 경로에서 Notion 의 글 `$a$` 가 볼트에서 수식이 된다. 링크 미리보기 멘션의 폴백 모양은 재지 않았다.

## 블록 폴백 — 블록을 NFM 으로 (`fix/block-fallback-nfm`)

바로 앞 브랜치에서 찾은 토글 유실(A4)을 고치려다, 블록 폴백 pull 전체를 Markdown API 경로와 견줬다.

증상:

- 코퍼스 10장을 두 길로 받으니 10장이 모두 달랐다. 토글을 통째로 버리고, 콜아웃의 자식 · 접는 제목의 표시와
  자식이 빠지고, 글자 색 · 밑줄 · 표 표시 · 칼럼 비율 · 콜아웃 아이콘이 사라졌다. 표 칸의 `|` 가 표를 깨뜨렸다.
- 그 노트를 Markdown API 로 push 하면 빠진 블록이 Notion 에서 지워졌다(탐침에서 토글과 그 안의 북마크).

원인:

- notion-to-md 의 기본 렌더가 토글 · 콜아웃의 자식을 다루지 않고, 우리 변환기는 Markdown API 경로가 만드는
  마커를 일부만 냈다. 두 길이 같은 볼트 모양을 따로 구현하고 있었다.

수정 (ADR-034):

- 블록 트리를 Notion 의 Markdown API export 와 같은 NFM 으로 옮긴다(`blocksToNfm`). 그 NFM 을 Markdown API
  본문과 같은 변환에 넘긴다(`pageBlocksToObsidian`). 코드 글 · 북마크는 트리에서 꺼낸다.
- 블록 트리는 자식까지 읽고 하나라도 읽지 못하면 던진다(`NotionClient.getBlockTree`).
- 규칙은 탐침 13장의 블록 트리 · export 짝으로 정했다(`tests/fixtures/nfm/`, 사용자 id · 이름은 가짜).

검증:

- 게이트 통과 — 시험 3,702 → 3,744(새 42: 짝 13장 · 규칙 23 · 블록 트리 · 폴백 변환 등).
- 짝 13장 — 블록 API 가 주지 않는 것을 빼면 옮긴 NFM 이 export 와 글자까지 같다.
- 변이 50개 중 49개를 잡았다. 남은 하나(굵게 · 기울임 차례)는 결과가 같은 변이다.
- 실 Notion 에서 두 길로 받은 노트 — 코퍼스 10장 중 7장 · 탐침 2장 중 1장이 글자까지 같다. 나머지 차이는 아래
  「옮기지 못하는 것」과 Markdown API 경로의 잘린 블록 채움(아래 찾은 것)뿐이다.
- 실 Notion(탐침 볼트 `bf/vault`, 페이지 `__bf_e2e` 에 토글 · 콜아웃 · 접는 제목 · 색 · 표 · 칼럼을 덧붙임):

| 동작                                              | 결과                                                                                           |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 원격에서 한 줄 고침 → 블록 API 로 pull            | 토글(+북마크) · 콜아웃 자식 · 접는 제목 · 색 · 표 · 칼럼 비율 그대로                           |
| 같은 변경을 Markdown API 로 pull(다른 볼트)       | 두 노트가 글자까지 같다(`cmp`)                                                                 |
| 블록 API 로 받은 노트를 고쳐 Markdown API 로 push | 블록 id 가 모두 그대로(토글 · 그 안 북마크 포함) · 색 · 밑줄 · 표 `a \| b` · 칼럼 30/70 그대로 |

옮기지 못하는 것 (블록 API 가 주지 않는다):

- 표의 열 너비 · 행 색. 콜아웃 첫 줄 아래에 단 자식(Markdown API 로만 만들 수 있는 모양).
- 정각이 아닌 지역 시간대의 이름(같은 순간을 UTC 로). 인라인 DB 의 data source.

찾은 것 (고치지 않음):

- Markdown API 경로의 잘린 블록 채움 — 다시 받아도 자리 태그뿐인 블록(바로가기 · 경로)의 주소가
  `p/<블록>#<블록>` 으로 바뀐다. Notion 의 export 는 `p/<페이지>#<블록>` 이다.
- Notion 은 받는 페이지의 자식이 아닌 페이지 · DB 의 멘션을 제목 없는 `mention-page` 로 낸다(DB 도). 폴백은
  제목과 종류를 싣는다 — 페이지는 같은 위키링크, DB 는 DB 마커가 된다.
- notion-to-md 의 pull 쪽은 이제 제품 경로에서 쓰이지 않는다. 프로젝트 규칙의 「Notion→MD: notion-to-md」도
  옛 설명이다.
