# 2026-10-26 — v0.11.0(플러그인 경로 패턴 · 이름 바꾸기 · DB 폴더 이동)

v0.10.0 을 내면서 「Notion API 한계가 아닌데 남은 것」 으로 적어 둔 넷을 브랜치 넷으로 개발해 v0.11.0 으로 냈다.
플러그인이 `.im-nobsidian-ignore` 를 따르게 되는 등 동작이 바뀌어 마이너다.

## 네 묶음

| #   | 브랜치                           | 무엇                                                                                              |
| --- | -------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1   | `feature/plugin-path-filters`    | 플러그인 설정 「동기화 범위」 — 연결마다 포함 · 제외 패턴, `.im-nobsidian-ignore`                 |
| 2   | `feature/rename-on-title-change` | `sync.renameOnTitleChange`(ADR-040) · 동기화가 옮기거나 바꾼 노트를 가리키는 링크 고치기          |
| 3   | `feature/remote-moves-status`    | `status --full` 이 다음 pull 의 이동 · 이름 바꾸기를 보임 · 범위 밖 새 원격 페이지는 받지 않음    |
| 4   | `feature/follow-db-folder-moves` | DB 가 든 폴더를 Notion 에서 옮기면 따라감(ADR-041) · 볼트에서 옮기면 `.base` 가 빈 표가 되던 결함 |

## 조사 중 찾은 것

- **볼트에서 DB 폴더를 옮기면 `.base` 보기가 빈 표.** 발견 DB 의 폴더만 고치고 `.base` 의 `file.inFolder` 는 그대로였다.
  ADR-027(바뀐 DB 만 조회) 뒤로는 다시 만들어지지도 않아 계속 옛 폴더를 걸렀다. Notion 쪽 이동과 같은 함수
  (`sync/db-folder-moves.ts`)로 고친다.
- **`DbBaseFiles` 가 처음 읽은 메타를 끝까지 썼다.** 플러그인처럼 오래 사는 오케스트레이터는 이동 뒤 옛 `.base` 경로로
  임베드할 수 있었다. 메타 글이 바뀌면 다시 읽는다.
- **릴리스 뒤 끝 점검** — `file.inFolder("…")` 꼴을 생성기와 폴더 이동이 따로 적고 있었다. 한쪽만 바뀌면 이동이 필터를
  못 찾고 조용히 남는다. 생성기의 `inFolderFilter` · `IN_FOLDER_FILTER_RE` 하나를 읽게 했다(`164e929`).
