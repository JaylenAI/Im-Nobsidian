## 동기화 블록 참조가 든 노트를 새로 올리지 못함 (`fix/push-create-synced-ref`)

증상: 빈 볼트로 받은 실데이터 사본(노트 1,492)을 탐침 루트 아래 새 페이지로 push 하자 만듦 346 · 실패 1,146.
13 노트가 `Failed to parse markdown content: Block not found in record map` 로 실패했고, 13 이 모두 폴더 노트라
그 아래 1,133 노트가 「폴더의 Notion 페이지를 마련하지 못해 만들지 않음」으로 함께 실패했다.

원인: 13 노트 모두 동기화 블록 참조(`synced:start:kind=ref`)를 담았다 — 원본(`kind=orig`)만 든 노트 3개는
성공했다. 탐침 페이지에서 재 보니 Notion 은 참조가 든 markdown 으로 페이지를 **만들지** 못하고, 같은 markdown 으로
본문을 **바꾸는**(`replace_content`) 것은 받아 참조를 그대로 남긴다. 기존 볼트에서 노트를 복제하거나 새 루트로
옮겨 올릴 때 생긴다.

고침: 보낼 markdown 에 참조가 있으면 빈 페이지로 만든 뒤 본문 교체로 채운다 — 맨 앞 H1 되살리기와 같은 자리(교체는
H1 도 남긴다). 교체 뒤 페이지를 다시 받아 수정 시각을 적는다(I5). 메모리 Notion 이 실측대로 만들기를 거절하게 하고
시험 3개(수정 전 2개 실패).

## 하위 페이지 제목의 밑줄이 굵게로 바뀜 (`fix/child-tag-title-underscore`)

증상: push 직후 같은 볼트로 pull 하니 33 노트가 다시 쓰였다. 30 은 제목이 `__p3c_upload__` 꼴인 노트(옛 탐침
페이지)였고, Notion 제목이 굵은 `p3c_upload` 로 바뀌어 pull 이 `title:` 을 적었다.

원인: 폴더 노트 본문을 보낼 때 `[[자식]]` 줄을 Notion 이 준 자식 태그(`<page url="…">__c1__</page>`)로 되돌린다.
Notion 은 제목의 `_` 를 이스케이프하지 않고 돌려주면서, 받은 태그 글은 마크다운으로 읽어 자식 제목을 바꾼다 —
탐침에서 `__c1__` 을 보내면 굵은 `c1`, `\_\_c1\_\_` 을 보내면 `__c1__` 이 남고 다시 받는 태그도 `__c1__` 이다.

고침: 되보내는 페이지 태그의 제목에서 이스케이프 안 된 `_` 를 `\_` 로 보낸다. DB 태그는 재 보지 않아 그대로 둔다.
시험 3개(수정 전 2개 실패).

## 자리표시자 마커의 자동 링크 (`fix/marker-autolink`)

증상: push 직후 pull 이 한 노트의 동영상 임베드를 `![[attachments/…[9.23.13.mov-….mov](<url>)|…]]` 로 바꿔 썼다 —
Obsidian 에서 깨진 임베드다.

원인: 그 `.mov` 는 무료 플랜 5MB 한도로 업로드가 실패해 `> 📎 이름 %% im-nobsidian:local-file:<경로> %%`
자리표시자로 남았다. Notion 이 글 속 `9.23.13.mov`(`.mov` 는 최상위 도메인)를 `[T](http://T)` 자동 링크로 바꿨고,
마커 속 경로 · 별칭까지 링크가 되었다(받은 markdown 실측 — 세 곳 모두 주소가 `http://` + 글자).

고침: `decodeMarkerTarget` 이 글자와 주소가 같은 자동 링크를 걷고 푼다. 이미 Notion 에 올라간 마커도 되살린다.
시험 2개(수정 전 1개 실패).

## 자리표시자 마커 경로의 밑줄 (`fix/marker-underscore`)

증상: 고친 빌드로 전체(1,492 노트)를 올린 뒤 같은 볼트로 받자, 콜아웃 안 `.base` 임베드
`![[__qa_probe_…__/…/x.base|…]]` 가 `![[**qa_probe_…**/…]]` 로 바뀌었다.

원인: 임베드는 `> 📎 이름 %% im-nobsidian:local-file:<경로> %%` 자리표시자로 나간다. 마커는 링크 주소가 아니라
글이라 Notion 이 마크다운으로 읽고, `__qa_probe_…__%2F…` 의 첫 `__…__` 를 굵게로 바꿨다.

고침: `encodeMarkerTarget` 이 `_` 도 `%5F` 로 보낸다. 받을 때는 `decodeURIComponent` 가 되돌리고, 밑줄이 그대로 든
옛 마커도 그대로 받는다. 시험 2개(수정 전 1개 실패).
