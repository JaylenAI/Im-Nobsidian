## 실측

- Notion-Version 2025-09-03: `pages.move` 부모가 `data_source_id` 면 행 · `database_id` 는 400 · 행을 다른 DB 로 옮기면 대상에 열이
  더해짐 · `PATCH /databases/{id}` 의 `parent` 로 DB 이동(id · 행 · 보기 그대로) · 어느 이동도 `last_edited_time` 을 바꾸지 않음
- 행의 부모는 `data_source_id` + `database_id` 를 함께 준다 — 다른 DB 로 옮긴 행은 부모의 `database_id` 로 가른다
- Obsidian 1.12.4 Bases: `file.inFolder("X")` 는 하위 폴더까지, `file.folder == "X"` 는 바로 안만. Obsidian 은 보기를 열거나 고치면
  `.base` 의 머리 주석을 지운다 — 그래서 예전 `.base` 고쳐 쓰기도 보기 기록(`db_base_files`)으로 pull 이 쓴 파일을 가린다

## 실 Notion E2E(탐침 `__p5_moves_20261030__`)

- CLI 볼트: 볼트 쪽 이동 → push → Notion 부모 확인 · Notion 쪽 이동(페이지 → DB · 행 → 밖 · 행 → 다른 DB · DB → 다른 페이지) →
  `pull --force` → 볼트 경로 · 하위 페이지 폴더 · 링크 확인 · 다시 pull · push 0
- 양쪽 이동 둘(페이지 → DB 폴더 vs Notion → 다른 페이지 · 행 → 밖 vs Notion → 다른 DB): 볼트가 먼저 · push 가 Notion 을 볼트 자리로 ·
  dry-run 의 건너뜀 까닭이 실제 pull 과 같음
- 격리 Obsidian 1.12.4 플러그인: Notion 쪽 이동 넷을 pull 한 번에(「이동 5」) · 양쪽 이동(볼트가 먼저 · push 「이동 1」) · `.base`
  보기가 행 셋만 보임(하위 페이지 빠짐, 머리 주석이 지워진 `.base` 포함) · CLI 볼트와 플러그인 볼트 수렴

## E2E 에서 찾아 고친 것

- 🔴 `deleteSync` 를 켠 볼트에서 전체 대조가 DB 안으로 옮긴 페이지 · 행의 하위 페이지를 지움 — 페이지 순회는 행을 보지 못해 범위
  밖으로 옮긴 것으로 봄. 받는 DB 와 그 행을 범위에 넣음
- 다른 DB 로 옮긴 행이 행 파일만 새 폴더로 가고 하위 페이지 폴더 · 링크가 옛 자리에 남음 · 결과에 이동으로 세지 않음
- 양쪽 이동의 dry-run 이 Notion 쪽 이동을 받을 것으로 셈 — dry-run 은 이동 WAL 이 없어 옮겨 적을 이동을 넘김
- `.base` 보기가 행의 하위 페이지를 행으로 보임 — 플러그인 화면에서 「4개 결과」 로 봄 → 고친 뒤 「3개 결과」
- 예전 `.base` 고쳐 쓰기가 Obsidian 이 머리 주석을 지운 파일을 건너뜀 — 보기 기록으로 가림
