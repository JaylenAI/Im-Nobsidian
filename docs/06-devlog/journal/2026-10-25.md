# 2026-10-25 — v0.9.1 · v0.9.2(이슈 #8) · v0.10.0(Notion 쪽 이동 따라가기)

하루에 셋을 냈다. 앞의 둘은 문서 패치와 결함 수정, 마지막은 pull 의 동작이 바뀌는 변경이라 마이너다.

## v0.9.1 — README 공개 항목을 main 에

커뮤니티 디렉터리는 기본 브랜치(main)의 README 를 읽는다. dev 에만 있던 공개 항목(계정 · 네트워크 · 파일 · 텔레메트리 ·
광고 · 결제)을 main 에 올린 문서 패치. 코드는 0.9.0 과 같다.

## v0.9.2 — 이슈 #8

Windows 사용자가 「새 노트를 못 찾고 `paths.include` · `exclude` 가 먹지 않는다」 고 알렸다. 같은 설정을 Linux 에서 먼저
돌려 보니 원인 넷 중 셋이 모든 OS 공통이었다.

| 원인                                                                                             | 범위    |
| ------------------------------------------------------------------------------------------------ | ------- |
| 볼트 목록이 `\` 구분자 — 패턴 · 상태 기록 · `-p` 와 안 맞음                                      | Windows |
| 포함 패턴을 폴더에도 대서 `00 Me/**/*.md` 가 폴더 `00 Me` 를 걸러 냄                             | 모든 OS |
| 동기화하던 폴더를 `exclude` 에 넣으면 그 노트를 지운 노트로 봄(`deleteSync` 면 Notion 삭제 계획) | 모든 OS |
| markdown API 가 코드 밖 `<` · `>` 를 모두 이스케이프 — pull 이 `->` 를 `-\>` 로                  | 모든 OS |

CI 에 `windows-latest` 전체 시험 작업을 붙이고 머지를 막게 했다. npm 0.9.0 과 0.9.2 를 같은 탐침에서 견준 표는
`docs/07-release/RELEASE_NOTES_v0.9.2.md`.

## v0.10.0 — Notion 에서 옮긴 페이지 따라가기 (ADR-039)

`pages.move` 는 `last_edited_time` 을 바꾸지 않는다(09-27 실측). 증분 pull 은 수정 시각으로만 찾으므로 Notion 에서 옮긴
페이지를 영영 보지 못했고 노트는 옛 폴더에 남았다. 전체 대조가 받은 부모를 상태 DB 의 부모와 견주어 새 부모의 폴더로
옮긴다(`sync/remote-moves.ts`).

- 자리 규칙은 새 페이지를 받을 때와 같다 — 두 곳이 따로 적던 것을 `childFolderOf` 하나로 먼저 모았다
- 노트 / 노트 + 옆 자식 폴더 / 폴더 노트 · 폴더 페이지는 폴더째. 한쪽이 실패하면 옮긴 것을 되돌린다
- 볼트에서 옮긴 것을 아직 안 올렸으면 볼트가 먼저 · 같은 이름 · 새 부모 없음 · 제외 · DB 나 연결 폴더를 품은 폴더는 까닭만 남긴다

### 라이브에서 찾은 것

첫 실측에서 노트가 `B/` 가 아니라 볼트 루트로 갔다. push 가 만든 폴더 레코드는 경로가 `X/X.md` 가 아니라 `X` 다.
시험 목이 `X/X.md` 만 만들어 놓쳤다. 받기와 같은 함수를 읽게 고친 뒤 다시 쟀다.

| 다시 `pull --force`                | `churn` 0              | 0                              |
