# 2026-10-23 — 실데이터 E2E 가 찾은 원본 동기화 블록 다시 쓰기

## 🔴 동기화 블록 참조가 원본을 다시 쓰던 것 (`fix/synced-ref-original`)

증상: 실데이터 E2E 로 볼트 사본을 탐침 루트에 올린 뒤, 사용자 실제 워크스페이스에 있는 원본 동기화 블록 넷의
자식이 이 통합이 만든 새 블록으로 바뀌어 있었다(생성 시각 2026-10-22 13:22 · 14:10 · 14:28 · 14:59 — 모두
이 세션의 push 시각). 셋은 글이 E2E 전과 같았고, 하나는 이미지 블록이 `📎 이름 %% im-nobsidian:local-file:… %%`
글로 바뀌어 있었다. 참조하지 않는 원본 하나는 그대로였다. relink 실패 5건 중 4건의 원격 본문 변화도 이것이다 —
실행 중에 우리 쓰기가 원본을 바꿨다.

원인: 참조를 Markdown API 로 보내면 Notion 이 참조 안의 내용으로 원본을 다시 쓴다. 탐침 원본으로 잰 것:

| 보낸 참조                                     | 원본                           |
| --------------------------------------------- | ------------------------------ |
| 같은 글 한 줄                                 | 그대로                         |
| 다른 글                                       | 그 글로 바뀜                   |
| 받은 그대로(콜아웃 · 링크 · 멘션 · 목록)      | 글은 같고 블록 id 가 모두 새것 |
| 빈 참조 · 스스로 닫는 참조                    | 비워짐                         |
| 본문에서 뺀 교체                              | 그대로                         |
| 블록 API 로 `synced_from` 참조 추가           | 그대로                         |
| 다른 페이지가 원본 url 을 단 `<synced_block>` | 그대로(새 원본이 생김)         |

96e61b4(빈 페이지로 만든 뒤 교체)가 새 페이지까지 이 길로 보냈고, 갱신(본문 교체)은 그 전부터 그랬다.

고침: `deferSyncedReferences` 가 NFM 의 참조를 자리표시 문단으로 바꾸고, 본문을 쓴 뒤 `fillSyncedReferences` 가
자리표시 뒤에 참조 블록을 붙이고 자리표시를 지운다(컨테이너 안이면 그 컨테이너에). 참조 안의 첨부는 페이지 끝에
덧붙이지 않는다. 시험 9개(새 시험 8 · 바꾼 시험 1, 수정 전 2개 실패). 게이트 3,998 통과.
