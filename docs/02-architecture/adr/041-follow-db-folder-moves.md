# ADR-041: DB 가 든 폴더도 옮기고 DB 기록 · `.base` 보기를 새 자리로 고친다

> 상태: 승인
> 결정일: 2026-10-26

## 맥락

- ADR-039 · 040 은 Notion 에서 옮기거나 이름을 바꾼 폴더를 볼트에서도 옮긴다. 그런데 폴더 안에 DB 폴더 · `.base` · 행이
  있으면 옮기지 않았다 — 「Obsidian 에서 옮기면 push 가 맞춘다」 고 안내했다
- DB 는 폴더 경로를 세 곳에 품는다. 발견한 DB 의 폴더(`discovered_dbs` 의 `localFolder`) · 기록한 `.base` 경로
  (`db_base_files`, 인라인 DB 자리를 임베드로 바꿀 때 쓴다) · `.base` 의 폴더 필터(`file.inFolder("폴더")`)
- 볼트에서 옮긴 경우(push)에도 `localFolder` 만 고쳤다. 바뀐 DB 만 조회하므로(ADR-027) 그대로인 DB 는 다시 받지 않아,
  `.base` 보기는 옛 폴더를 걸러 **빈 표**가 되고 인라인 DB 임베드는 옛 경로를 가리킨 채 남았다

## 선택지

| 안                                                         | 장점                           | 단점                                                      |
| ---------------------------------------------------------- | ------------------------------ | --------------------------------------------------------- |
| A. 그대로 막는다                                           | 바뀌는 것 없음                 | 폴더를 Notion 에서 정리하면 볼트가 따라가지 않는다        |
| **B. 옮기고 세 곳을 고친다(옮긴 쪽이 볼트든 Notion 이든)** | 다음 DB 받기를 기다리지 않는다 | `.base` 의 필터를 글자로 고친다 — 동기화가 만든 꼴만 안다 |
| C. 옮기고 그 DB 를 다시 받는다                             | `.base` 를 생성기가 다시 쓴다  | DB 마다 조회 · 행 수만큼 요청. 실패하면 틀린 채 남는다    |

## 결정

B. `db-folder-moves.ts` 의 두 함수를 볼트 이동(`LocalPlanner.adoptLocalMoves`)과 Notion 이동(`NoteRelocator.relocate`)이
같이 쓴다.

1. `rewriteDatabaseFolders` — 상태 DB 트랜잭션 안에서 옮긴 폴더 아래의 `discovered_dbs` 폴더 · `db_base_files` 경로를
   새 자리로 적는다. 폴더 자신과 그 아래(중첩)를 모두 본다
2. `retargetBaseFiles` — 볼트의 `.base` 가운데 **동기화가 만든 것**(머리글 `# Auto-generated by Im-Nobsidian`)만 열어
   `file.inFolder("옛 폴더")` 를 새 자리로 고친다. 옮긴 폴더 밖의 `.base`(원본 DB 를 가리키는 연결 보기)도 본다. 사용자가
   만든 `.base` 는 둔다 — 무엇을 거르는지 모른다. 고치지 못해도 옮긴 것을 무르지 않는다(그 DB 를 다음에 받을 때 다시 쓴다)
3. `DbBaseFiles` 는 메타가 바뀌었으면 다시 읽는다 — 플러그인은 같은 오케스트레이터를 계속 쓰므로, 읽어 둔 옛 경로로
   임베드하거나 다른 DB 를 적을 때 옛 경로로 덮어쓰면 안 된다
4. **여전히 옮기지 않는 것** — 폴더 안에 설정 파일로 정한 DB 폴더(`notion.databases`)가 있다(설정은 사용자가 적는다 —
   동기화가 고쳐 적지 않는다) · 다른 연결 폴더가 있다(ADR-038)

## 트레이드오프

- `.base` 의 필터는 생성기가 적는 꼴(`file.inFolder("…")`)만 고친다. 사용자가 그 파일을 고쳐 다른 꼴로 적었으면 남는다 —
  다음에 그 DB 를 받을 때 생성기가 다시 쓴다
- Notion 에서 DB 자체를 다른 페이지로 옮긴 것은 이 결정의 범위가 아니다(DB 의 부모는 전체 대조의 페이지 부모 비교에 들지 않는다)

## 영향

- `note-relocation.ts` 의 막는 까닭에서 「DB 폴더 · `.base` · 행」 이 빠지고 「설정한 DB 폴더」 가 들었다
- ADR-039 의 「DB 를 품은 폴더는 따라가지 않는다」 를 이 결정이 바꾼다
