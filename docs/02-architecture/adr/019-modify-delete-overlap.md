# ADR-019: 수정과 삭제가 겹친 노트는 지우지 않고, 편집이 있는 쪽을 살린다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

한쪽에서 노트를 지우는 사이 다른 쪽에서 고치면, 지우는 쪽이 늘 이겼다. 어느 방향이든 진 편집은 볼트에도 Notion
에도 보이지 않게 됐다.

| 방향                    | 무엇이 일어났나                                                                                                                        | 편집이 남은 곳                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| Notion 삭제 · 로컬 편집 | pull 이 전략을 보지 않고 파일을 지웠다(`applyRemoteDeletion`). local-first 도 같았다. 행도 같다                                        | 없음 — Notion 에 간 적이 없다 |
| 로컬 삭제 · Notion 편집 | push 가 원격을 보지 않고 휴지통으로 보냈다(`pushDelete`). 본문을 바꿀 때는 원격을 보고 거절하는데(N-05, ADR-017) 지울 때만 빠져 있었다 | Notion 휴지통 — 볼트에 없다   |

플러그인은 deleteSync 를 늘 켜고 전략은 manual 이 기본이다. 두 경우 모두 사용자에게 묻지 않았다.

«편집이 있다» 는 이미 가를 수 있다.

- 로컬 — 파일 해시가 지난 동기화의 해시(`contentHash`)와 다르다.
- 원격 — 지난번에 본 뒤로 바뀌었다(`remoteDrift`, ADR-017). 본문은 지문으로, 본문 밖은 지난 사본으로 가른다.

## 결정

### 1. Notion 에서 지운 노트에 올리지 않은 로컬 편집이 있으면 — 전략을 따른다

`applyRemoteDeletion` 한 곳에서 가른다(ADR-018 에서 페이지와 행이 같이 쓰게 모았다). 편집이 없으면 예전처럼 지운다.

| 전략               | 동작                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| remote-first       | 삭제가 이긴다 — 예전처럼 지운다                                                                     |
| local-first        | 로컬이 이긴다 — 파일을 두고 추적만 놓는다. 이어지는 push 가 새 페이지 · 같은 DB 의 새 행으로 만든다 |
| manual · duplicate | 파일과 추적을 두고 **원격 삭제 충돌** 로 남긴다                                                     |

원격 삭제 충돌은 `remoteChange.type === "deleted"` 이고 원격 본문이 없다(`""`). 상태는 `conflict` 라 push 가
건드리지 않고, pull 마다 다시 보고된다. 해소는 둘뿐이다(`applicableChoices`).

| 고름                  | 동작                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------- |
| 로컬 유지(`local`)    | 추적을 놓고 곧바로 새 페이지로 만든다(`pushCreate`). 옛 페이지는 휴지통에 그대로 둔다 |
| 삭제 따르기(`remote`) | 파일과 추적을 지운다                                                                  |

병합 · 복제는 견줄 원격 본문이 없어 거절한다. 전략으로 풀 때 duplicate 는 로컬 유지로, manual 은 거절한다
(`choiceForStrategy`) — 복제는 «둘 다 남긴다» 인데 남길 원격이 없다. 새 페이지를 만들지 못하면 이유를 알리고 파일을
둔다 — 추적이 없으니 다음 push 가 만든다.

CLI `resolve` · `status` 와 플러그인 모달 · 알림은 이 충돌을 «Notion 에서 삭제됨» 으로 보이고, 단추 이름도 그 뜻으로
바꾼다(`로컬 유지 (Notion 에 새 페이지로 다시 만들기)` · `삭제 따르기 (Obsidian 파일도 지우기)`).

### 2. 로컬에서 지운 노트를 Notion 에서 고쳤으면 — 지우지 않는다

`pushDelete` 가 휴지통으로 보내기 전에 원격에 묻는다(`remotePresence`, ADR-018).

| 원격                             | 동작                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 이미 사라짐(휴지통 · 보관 · 404) | 다시 지우지 않고 추적만 놓는다                                                                              |
| 살아 있고 지난번 그대로          | 지운다 — 예전과 같다                                                                                        |
| 살아 있고 바뀜 · 바뀌었는지 모름 | 지우지 않고 이유를 남긴다(`push.failed`, operation `delete`). 이어지는 pull 이 그 편집과 함께 되살려 받는다 |
| 읽지 못함(429 · 5xx · 망)        | 지우지 않고 그 오류를 남긴다 — 읽지 못한 것을 사라진 것으로 보지 않는다                                     |

«바뀜» 은 본문 · 본문 밖(제목 · 속성)을 가리지 않는다. «모름» 은 본문 지문이 없는 페이지(push 로 만들고 한 번도
받지 않은 페이지)가 수정 시각으로 바뀐 것이다 — 바뀌지 않았다고 볼 근거가 없다.

push 가 원격을 덮어써도 되는 경우(`overwritesRemote` — local-first · push 전용 · 한 번도 동기화하지 않은 레코드)는
예전처럼 지운다. 본문 push 가 거절하지 않는 경우와 같다.

## 선택지

### 로컬 유지 — 새 페이지로 만들기 vs 휴지통에서 되살리기

|                                              | 새 페이지(선택)                                            | 되살리기(`in_trash: false`)                                            |
| -------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------- |
| 페이지 ID · 블록 ID                          | 새로 생긴다                                                | 그대로                                                                 |
| Notion 안의 링크 · 멘션 · 관계 · 댓글 · 기록 | 옛 페이지(휴지통)에 남는다                                 | 이어진다                                                               |
| 누군가 일부러 지운 것                        | 휴지통에 그대로 둔다 — 지운 사람이 되돌릴 수 있다          | 되돌린다                                                               |
| 부모까지 휴지통 · 휴지통에서 영구 삭제       | 상관없다                                                   | 되살릴 수 없거나 휴지통 부모 아래로 간다 — 결국 만들기로 돌아가야 한다 |
| 쓰기                                         | 만들기 1회                                                 | 되살리기 + 로컬 본문 올리기                                            |
| 코드 경로                                    | local-first 의 «다음 push 가 만든다» 와 같다(`pushCreate`) | 새 경로                                                                |

새 페이지로 만든다. 지운 쪽의 결정을 되돌리지 않고, 되살릴 수 없는 경우가 없으며, local-first 와 한 길을 쓴다.
대가는 Notion 안의 연결이다 — 옛 페이지를 가리키던 링크 · 멘션 · 관계는 휴지통 페이지를 가리킨다. 사용자가
Notion 휴지통에서 옛 페이지를 되살리면 둘이 된다(볼트는 새 페이지를 추적한다).

### 로컬 삭제 · Notion 편집 — 거절 vs 충돌

로컬 삭제 쪽 충돌(「삭제 · 수정」)을 새로 만들면 사용자가 그 자리에서 고를 수 있다. 하지만 충돌 모델 · 해소
경로 · CLI · 모달이 모두 «로컬 파일이 있다» 를 전제한다. 거절하면 아무것도 사라지지 않고, 이어지는 pull 이
되살린 파일이 «Notion 에서 고쳤다» 를 보여 준다. 그래도 필요 없으면 다시 지운다 — 그때는 원격이 지난번 그대로라
지워진다. 거절을 고른다.

## 비용

- 원격 삭제: deleteSync 일 때 지워진 노트마다 파일 읽기 · 해시 1회. pull 의 요청은 늘지 않는다.
- 충돌 목록(`status` · 해소 목록): 충돌 레코드마다 `pages.retrieve` 1회로 원격이 사라졌는지 먼저 가른다. 해소 목록은
  예전에도 읽었고, 상태 미리보기는 1회가 는다.
- 로컬 삭제: 지운 노트마다 `pages.retrieve` 1회. 원격이 바뀌었으면 본문 지문을 위해 markdown 읽기 1회. 평소
  (지운 노트 없음) 0.

## 결과 · 한계

- 로컬 삭제를 거절하면 이어지는 pull 이 파일을 되살린다 — 사용자의 삭제가 한 번 되돌려진다. 이유는 push 결과
  (`failed`)에 남는다.
- `pull --dry-run` 은 원격 삭제 충돌을 가르지 않고 삭제로 센다 — `feature/sync-status-api` 에서 dry-run 과 함께
  고친다.
- 원격 삭제 충돌에 `push --force` 를 쓰면 휴지통 페이지를 고치려다 실패한다 — 해소(로컬 유지)를 쓴다. 코드로만 봤다.
- pull 전용 방향에서도 «로컬 유지» 는 새 페이지를 만든다(해소가 Notion 에 올리는 기존 동작, N-06). 코드로만 봤다.
- deleteSync 가 꺼져 있으면 원격 삭제는 파일을 늘 두고 추적만 놓는다 — 이 ADR 의 대상이 아니다.
