# ADR-020: 올린 미디어는 캡션이 아니라 Notion 이 저장한 파일 id 로 알아본다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

push 는 노트의 임베드(`![[assets/a.png|설명|300]]`)를 Notion 에 올려 본문 자리에 이미지 · 파일 블록으로 넣는다.
pull 은 그 블록을 다시 받아 임베드로 되돌려야 한다. 되돌리지 못하면 파일을 내려받아 `attachments/` 에 사본을
만들고 임베드를 사본으로 바꾼다 — 노트는 같은 그림을 두 번 갖게 된다.

R1 은 되돌릴 열쇠를 캡션에 실었다. 올린 블록의 캡션에 임베드 대상을 그대로 적고(`assets/a.png|설명|300`), pull 이
캡션으로 볼트의 파일을 찾았다. 그 결과가 S-05 다.

| 무엇이 보였나 · 일어났나                      | 왜                                                                                      |
| --------------------------------------------- | --------------------------------------------------------------------------------------- |
| Notion 캡션에 볼트 경로 · 크기가 보인다       | 캡션이 열쇠라 지울 수 없다. 파일 블록은 캡션이 파일 이름 대신 보여 이름도 가려진다      |
| Notion 에서 캡션을 고치면 사본을 받는다       | 고친 캡션은 볼트 경로가 아니다 — 열쇠가 사라진다                                        |
| 같은 이름의 다른 파일로 바꾸면 옛 파일이 산다 | 캡션(또는 이름)만 보고 볼트 파일로 되돌린다. Notion 에서 바꾼 파일이 노트에 오지 않는다 |

캡션은 사람이 읽고 고치는 자리다. 열쇠는 사람이 건드리지 않는 곳에 있어야 한다.

### 무엇으로 알아볼 수 있나 — 실측

pull 은 본문을 markdown API 로 받는다. 거기서 미디어는 URL 로만 보인다 — 블록 id 는 없다.

| URL 모양                                                                 | 어디서                                 |
| ------------------------------------------------------------------------ | -------------------------------------- |
| `https://prod-files-secure…/<space>/<파일 id>/<이름>?X-Amz-…`            | 이미지(서명 URL, 약 1시간 뒤 만료)     |
| `https://file.notion.so/f/f/<space>/<파일 id>/<이름>?…`                  | 신형 서명 URL                          |
| `file://{"source":"attachment:<파일 id>:<이름>","permissionRecord":{…}}` | 파일 블록(`<file src="…">캡션</file>`) |

서명은 받을 때마다 바뀌지만 **파일 id** 는 그대로다. 파일 id 는 블록 id 와도, 올릴 때 받은 file_upload id 와도
다르다 — 올린 뒤 블록에서 읽어야 한다. E2E r2 에서 확인한 것:

- 블록을 붙인 응답(`blocks.children.append`)에 파일 URL 이 실려 온다 — 따로 조회하지 않아도 된다(다시 조회 0회).
- 캡션만 고치면(`blocks.update`) 파일 id 는 그대로다.
- Notion 에서 파일을 바꾸면 id 가 바뀐다(다시 올릴 때마다 새 id).

## 결정

### 1. 캡션에는 사람이 적은 설명만 싣는다

`captionOfEmbed` — 임베드 대상 `경로|설명|크기` 에서 설명만. 설명이 없으면 캡션은 비어 있다. 파일 블록은 이름
(`name`)을 따로 실어 Notion 이 파일 이름을 보여 준다.

| 노트                           | Notion 캡션 |
| ------------------------------ | ----------- |
| `![[assets/a.png]]`            | (없음)      |
| `![[assets/a.png\|300]]`       | (없음)      |
| `![[assets/a.png\|설명\|300]]` | 설명        |
| `![[계약서.pdf\|계약서 사본]]` | 계약서 사본 |

### 2. 올린 파일의 id 를 페이지마다 적어 둔다

push 가 미디어 블록을 붙이면 응답의 파일 URL 에서 파일 id 를 읽어(`notionFileIdOf`) 임베드 대상과 함께 적는다.
응답에 URL 이 없으면 블록을 한 번 조회한다. 그래도 없으면 알리고 넘어간다 — 다음 pull 이 사본을 받을 수 있다.

```
sync_metadata
  key   = uploaded_media:<페이지 id(대시 없이)>
  value = [{"fileId":"…","target":"assets/a.png|설명|300","localPath":"assets/a.png"}, …]
```

본문 push 는 페이지의 미디어 블록을 모두 새로 만든다. 그래서 적을 때마다 그 페이지의 기록을 **통째로 바꾼다**
— 지난번 파일은 페이지에서 이미 사라졌다. 미디어가 없는 페이지는 줄을 만들지 않는다.

적지 못해도(상태 DB 쓰기 실패) push 는 실패로 돌리지 않는다. 본문은 이미 올라갔다 — 알리고 넘어간다.

### 3. pull 은 내려받기 전에 파일 id 로 되돌린다

`restoreUploadedMedia` 가 받은 본문의 Notion 미디어(이미지 `![…](…)` · 파일 `[📎 …](…)` · 태그
`<file|pdf|video|audio src="…">…</…>`)를 훑는다. 네트워크를 쓰지 않는다.

| 파일 id                                      | 동작                                                              |
| -------------------------------------------- | ----------------------------------------------------------------- |
| 적어 둔 것이고 볼트에 그 파일이 있다         | 적어 둔 임베드로 되돌린다(캡션 반영 — 아래 4)                     |
| 적어 둔 것인데 볼트에서 파일이 사라졌다      | 그대로 둔다 → 사본을 받는다                                       |
| 적어 둔 것이 아니다(바꾼 파일 · 다른 페이지) | R1 캡션(대상 전체)으로 찾아본다. 못 찾으면 그대로 → 사본을 받는다 |

그다음에 예전처럼 `downloadAllImages` · `downloadAllFiles` 가 남은 Notion 미디어를 내려받는다. 되돌린 임베드는
Notion URL 이 아니므로 받지 않는다.

페이지 pull · DB 행 pull · 표시 전용 렌더(diff) 가 같은 순서를 쓴다. 이미지 다운로드를 꺼도 되돌리기는 한다.

### 4. Notion 에서 고친 캡션은 설명으로 받는다

`embedTargetFromCaption(적어 둔 대상, 받은 캡션, 올린 파일 이름)`.

| 받은 캡션                                | 되돌린 임베드                                                  |
| ---------------------------------------- | -------------------------------------------------------------- |
| 적어 둔 설명 · 대상 전체(R1) · 파일 이름 | 적어 둔 대상 그대로                                            |
| 비었다                                   | `경로` (+ `\|크기`)                                            |
| 고쳤다                                   | `경로\|새 설명` — 크기는 원래 설명과 함께 있었을 때만 `\|크기` |

- 파일 이름만 보이면 그대로 둔다. 파일 블록은 캡션 대신 이름을 보일 수 있어 «설명을 지웠다» 와 가를 수 없다 —
  지우지 않는 쪽을 고른다.
- 크기만 있던 임베드(`a.png|300`)에 설명이 생기면 `a.png|새 설명` 으로 받는다. `a.png|새 설명|300` 은 사용자가
  쓴 적 없는 모양이다.
- pull 변환이 캡션 없는 미디어에 붙이는 자리 이름(`📎 file` · `📎 pdf` …)은 빈 캡션으로 본다. 이모지 없이
  `file` 이라고 적은 캡션은 사람이 쓴 것이다.

### 5. 되돌리지 못한 미디어 마커는 되살리지 않는다(S-19)

push 는 자리표시자의 마커(`%% im-nobsidian:local-image:… %%`)를 보존 마커로도 적어 둔다. pull 의 보존 마커
주입기는 받은 본문에 그 마커가 없고 push 때의 임베드(`![[대상]]`)도 그대로 없으면 «잃은 마커» 로 보고 노트에
다시 넣었다. 미디어를 제자리 블록으로 올린 뒤(R1, v0.3.2)로는 이 판정이 Notion 의 편집과 겹친다.

| Notion 에서                    | 받은 노트               | 주입기가 한 일              | 다음 push                        |
| ------------------------------ | ----------------------- | --------------------------- | -------------------------------- |
| 캡션을 고쳤다                  | `![[a.png\|새 설명]]`   | `%% …:local-image:a.png %%` | 옛 대상으로 한 번 더 올린다 — 둘 |
| 같은 이름의 다른 파일로 바꿨다 | `![[attachments/사본]]` | 같은 마커                   | 옛 파일을 다시 올린다 — 둘       |
| 블록을 지웠다                  | 임베드 없음             | 같은 마커                   | 지운 미디어가 되살아난다         |

E2E r2 에서 캡션을 고친 세 미디어가 두 번째 push 뒤 둘씩 됐다(M6 · M8). 메모리 왕복 시험은 노트를 부분만
견줘(`toContain`) 이 줄을 보지 못했다.

- 주입기는 미디어 마커를 넣지 않는다 — 표 정렬 마커처럼 전용 복원기 소관이다. 남은 자리표시자는
  `LocalImageRestorer` 가, 올린 미디어는 `restoreUploadedMedia` 가 되돌린다. 둘을 거치고도 없으면 Notion 에서
  고친 것이다.
- v0.3.2 가 노트에 이미 남긴 마커는 push 가 보내는 본문에서 뗀다(`EmbedResolver`). 임베드만 자리표시자가 된다.
  같은 줄 앞에 `📎` 가 있으면 자리표시자라 둔다. 코드 안의 마커(형식을 설명하는 글)도 둔다. 노트는 고치지 않는다
  — 다음에 원격이 바뀌어 받을 때 사라진다.

### 6. Notion 이 받지 않는 형식은 올리지 않는다(S-14)

Notion 의 업로드는 확장자 표에 없는 형식(`.ipynb` · `.hwp` · `.base` …)을 업로드를 만들 때 400 으로 거절한다.
거절된 파일은 등록되지 않으니 push 할 때마다 같은 요청이 같은 이유로 실패했다(실볼트 `.ipynb` 22개).

- 임베드: 올리지 않고 자리표시자로 둔다 — pull 이 자리표시자에서 임베드를 되살린다. 올리려 한 것이 없으면
  페이지가 바뀌지 않았으므로 보낸 본문의 지문을 그대로 쓴다.
- 폴더 첨부: 건너뛴다.
- 둘 다 push 마다 한 줄(`info`)로 알린다. 실패로 세지 않는다.

`.yaml` 처럼 표에 있는 형식은 파일 블록으로 올린다(E2E r2 Y1).

## 선택지

### 무엇으로 알아보나

|                       | 파일 id(선택)          | 블록 id                         | 파일 이름                   | 캡션(R1)    |
| --------------------- | ---------------------- | ------------------------------- | --------------------------- | ----------- |
| pull 본문에서 보이나  | 보인다 — URL 안        | 보이지 않는다(블록을 따로 순회) | 보인다                      | 보인다      |
| 캡션을 고치면         | 그대로                 | 그대로                          | 그대로                      | 잃는다      |
| 같은 이름 다른 파일로 | 바뀐다 — 사본을 받는다 | 그대로 — 옛 파일로 되돌린다     | 그대로 — 옛 파일로 되돌린다 | 캡션 따라   |
| Notion 에 보이는 것   | 없다                   | 없다                            | 없다                        | 경로 · 크기 |

블록 id 는 «같은 자리» 이고 파일 id 는 «같은 파일» 이다. Notion 에서 파일을 바꾼 것은 편집이다 — 받아야 한다.
블록 id 는 또 pull 이 쓰는 markdown API 에 나오지 않아, 쓰려면 미디어마다 블록 순회가 는다.

### 어디에 적나

|                  | sync_metadata 한 줄(선택)                                            | 새 표                                        |
| ---------------- | -------------------------------------------------------------------- | -------------------------------------------- |
| 스키마           | 그대로                                                               | 두 구현(better-sqlite3 · sql.js)에 이관 필요 |
| 선례             | 보존 마커(`preserve_markers:<경로>`)가 같은 방식                     | 없음                                         |
| 페이지 단위 교체 | 한 번 쓰기                                                           | 지우고 넣기                                  |
| 조회             | 페이지를 받을 때 한 번 읽는다 — 파일 id 로 찾는 일은 페이지 안뿐이다 | 색인이 있지만 쓸 곳이 없다                   |

## 비용

- push: 미디어마다 0 요청 — 붙인 응답에 파일 URL 이 있다(실측). 없으면 블록 조회 1회. 상태 DB 쓰기는 페이지당 1회.
- pull: 요청 0. 페이지당 상태 DB 읽기 1회, 적어 둔 미디어마다 볼트 파일 확인 1회. R1 은 캡션마다 볼트를 사다리로
  뒤졌다.
- 저장: 미디어가 있는 페이지마다 JSON 한 줄.

## 결과 · 한계

- 이 결정 이전에 올린 페이지는 기록이 없다. 캡션이 대상 전체(R1)라 예전처럼 되돌린다. 그 페이지를 한 번 더 push
  하면 캡션이 설명만으로 바뀌고 기록이 생긴다.
- v0.3.2 에서 이미 둘이 된 미디어는 두 갈래다. 노트에 마커만 남아 있으면 떼어 올리므로 다음 본문 push 에 하나로
  돌아온다(본문 push 는 미디어 블록을 모두 새로 만든다). 그 사이에 다시 받아 둘째 블록이 임베드로 돌아왔으면
  (`![[a.png|새 설명]]` 과 `![[a.png]]`) 노트에 임베드가 둘이다 — 사용자가 쓴 임베드와 모양이 같아 가를 수 없으니
  사용자가 하나를 지운다.
- 기록은 상태 DB(`.im-nobsidian/sync.db`)에만 있다. 상태 DB 없이 받는 볼트는 R1 캡션도 없으니 사본을 받는다.
  상태 DB 를 잃으면 어차피 모든 페이지를 새로 맞춰야 한다.
- Notion 에서 파일을 바꾸면 사본을 받고, 볼트의 원래 파일은 두고 쓰지 않는다. 사용자가 고른 이름과 폴더를 덮어쓰지
  않는다.
- 본문 push 는 여전히 미디어를 모두 다시 올린다 — 기록이 있으니 바뀌지 않은 파일은 건너뛸 수 있다(Phase A 후보).
- pdf · 동영상 · 소리 임베드도 파일 블록으로 올린다 — 전용 블록은 별도 후보다.
