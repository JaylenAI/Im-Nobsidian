# ADR-054: 폴더 첨부 — 폴더 페이지에 «캡션 = 파일 이름» 으로 올리고, 같은 폴더에 같은 이름으로 받는다

> 상태: 승인
> 결정일: 2026-11-02
> 「Notion API 한계를 빼고 모두 동기화」 계획의 P13

## 맥락

노트에 붙이지 않고 폴더에 그냥 둔 파일(`proj/data.csv`)은 push 가 그 폴더의 Notion 페이지에 파일 블록으로 올렸다
(`sync.syncFiles`). 두 볼트로 왕복해 보니(2026-11-02, 탐침 `__p13_files_20261102__`) 그 길이 닫히지 않았다.

1. **받는 쪽이 파일 블록을 «본문» 으로 봤다** — 폴더 페이지에 글이 생겼다고 보고 폴더 노트(`proj/proj.md`)를 새로 쓴 뒤 파일을
   받은 그림 폴더에 사본(`attachments/옆.csv-<해시>.csv`)으로 받았다. 올린 볼트도 다시 받으면 제 파일의 사본 · 가짜 폴더 노트가 생겼다
2. **노트 없는 폴더의 파일은 올라가지 않았다** — 폴더 페이지가 없으면 디버그 로그만 남기고 건너뛰었다
3. **바뀐 파일은 블록이 하나씩 늘었다** — 새 블록을 붙이고 옛 블록을 두었다
4. **노트에 붙여 올린 파일도 바뀌면 폴더 페이지에 또 올라갔다** — 파일 기록의 페이지를 보지 않았다
5. **받은 파일 이름에 확장자가 둘이었다**(`보고서.pdf-<해시>.pdf`)
6. **이름만 적은 임베드 · 아이콘을 세 곳(노트 폴더 · 맨 위 · 첨부 폴더)에서만 찾았다** — 다른 폴더의 아이콘, Obsidian 설정
   「현재 폴더 아래 하위 폴더」 의 첨부는 올라가지 않았다

## 결정

1. **폴더 첨부는 폴더 레코드의 페이지에만 올린다** — push 가 만든 폴더 페이지 · 폴더로만 받은 페이지. 노트 없는 폴더면 push 가 폴더
   페이지를 만든다(`FolderPlacement.ensureFolderPage`). 폴더 노트가 있는 폴더 · DB 폴더 · 볼트 맨 위의 파일은 올리지 않고 경고로
   알린다 — 폴더 노트 페이지는 본문을 통째로 바꿔(replace_content) 덧붙인 파일 블록이 남지 않는다
2. **캡션에 파일 이름을 적는다** — 받는 쪽은 본문이 자식 · 빈 블록과 Notion 에 올린 파일뿐인 페이지를 폴더로 둔다. 자식이 없는
   페이지는 PDF 하나만 붙인 노트와 모양이 같아, 모든 파일의 캡션이 그 이름일 때만 폴더로 본다. 자식이 있으면 캡션을 보지 않는다 —
   이 표시 전(0.17)에 올린 폴더 첨부도 받는다
3. **받을 때는 그 폴더에 올린 이름 그대로 쓰고, Notion 이 저장한 파일 id 를 적는다**(sync_metadata `folder_files:<페이지>` — 스키마를
   바꾸지 않는다, `uploaded_media:` 와 같은 방식). 올린 볼트는 올린 블록의 응답에서 id 를 적는다. id 가 같으면 받지 않고, 다르면
   Notion 쪽에서 바뀐 것이다 — 볼트의 파일이 지난 동기화 그대로면 덮고, 볼트에서도 고쳤으면 두고 알린다(다음 push 가 올린다).
   id 를 적기 전에 받은 파일은 받지 않고 id 만 적는다
4. **바뀐 폴더 첨부는 새 블록을 붙이고 같은 이름의 옛 블록을 지운다**
5. **올리지 않는 것**: 받은 첨부 폴더(`paths.attachments`) · 점으로 시작하는 폴더 · 노트가 붙인 파일(`![[x]]` · `![](x)` ·
   frontmatter 의 `[[x]]` — 이름으로 본다) · 다른 페이지에 적힌 파일(노트 임베드로 올린 것)
6. **받은 파일 이름**은 `<이름>-<해시><확장자>` — 캡션의 확장자를 뗀다. 예전 이름으로 받아 둔 파일이 있으면 그것을 쓴다(이름에 내용
   해시가 있어 같은 내용이다)
7. **지운 폴더 첨부는 다른 쪽에서도 지운다**(`sync.deleteSync` 를 따른다) — push 는 폴더 페이지에 적힌 파일 가운데 볼트에 없는
   것의 블록을 지운다(포함 · 제외 패턴으로 빠진 파일은 볼트에 있어 지우지 않는다). pull 은 이 페이지에서 본 적 있는 파일이 본문에서
   사라졌으면 볼트에서 지운다 — 지난 동기화 그대로일 때만. 볼트에서 고쳤으면 두고 기록만 놓아 다음 push 가 다시 올린다. 잘린
   본문에서는 지우지 않는다
8. **이름만 적은 임베드는 세 곳에 없으면 볼트 어디서든 찾는다**(`VaultFileIndex`) — 경로 끝이 같은 파일 가운데 노트 폴더 안(얕은 것
   먼저) → 짧은 경로 → 가나다. 대소문자 · NFC/NFD 를 가리지 않는다. 목록은 한 push 안에서 같이 쓴다(5초)

## 결과

- 두 볼트가 같은 폴더에 같은 파일을 갖는다 — 가짜 폴더 노트 · 사본 없음. 한쪽에서 고치거나 더하거나 지운 파일이 다른 쪽에 간다
  (Notion 에서 지운 것도). 두 번째 push · pull 은 변화 0(실 Notion 탐침)
- push 요약에 올린 파일 수가 나온다(`N files`, `--json` 의 `files` · `churn`) — 파일만 올린 push 가 「no changes」 로 보였다

## 남은 한계

- **폴더 노트가 있는 폴더의 첨부는 올리지 않는다**(경고) — 노트에 붙이면 함께 올라간다
- **본문이 Notion 에 올린 파일뿐인 폴더 노트**는 폴더로 받는다 — 글을 한 줄 쓰면 폴더 노트가 된다
- 이름으로 찾는 임베드는 같은 이름이 여럿이면 가까운 것을 고른다 — Obsidian 과 다를 수 있다
