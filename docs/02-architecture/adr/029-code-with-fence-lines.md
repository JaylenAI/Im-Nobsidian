# ADR-029: 코드 속 펜스 줄 — push 는 자리표시를 보낸 뒤 블록으로 채우고, pull 은 Notion 규칙으로 코드 범위를 정한다

> 상태: 승인
> 결정일: 2026-10-04

## 맥락

코드에 ``` 로 시작하는 줄이 있는 코드 블록(마크다운 예시 · 블로그 원고를 담은 코드)이 Notion 과 왕복하지 못했다
(F-03 · S-22, 실볼트 1,271노트 중 3노트).

- **push.** Notion Markdown API(`pages.create` 의 markdown · `pages.updateMarkdown`)는 코드 속 ``` 줄에서 코드
  블록을 가른다. 바깥 펜스를 `` · `~~~` 로 넓혀도, 줄을 `\`` 로 막아도 같다 — 백슬래시는 글에 그대로 남는다
  (2026-10-04 실측, 프로브 페이지 `…9bb7`). 코드 블록 하나가 코드 블록 둘 · 문단으로 올라갔다.
- **pull.** Notion 은 내보낼 때 펜스를 넓히지 않는다(실측 F1 ~ F8).
  - 여는 줄은 ``` + Notion 언어 이름(`markdown` · `plain text`).
  - 닫는 줄은 여는 줄과 같은 탭 들여쓰기의 맨 ```.
  - 코드 줄은 컨테이너 깊이와 상관없이 열 0.
  - 그래서 코드 속 ``` 줄이 Obsidian 에서 코드 블록을 닫고, 코드 뒷부분이 본문으로 샜다.
- 블록 API(`blocks.update`)는 코드 블록의 글을 그대로 받고 그대로 돌려준다.

## 결정

1. **push 는 자리표시를 보내고, 본문을 쓴 뒤 블록으로 채운다.**
   - `CodeLanguageGuard` 가 그런 코드를 자리표시 한 줄(`%%im-nobsidian:deferred-code:N%%`)로 바꿔 보낸다.
     자리표시는 같은 컨테이너의 코드 줄 자리에 둔다. 코드는 `ConversionResult.deferredCode` 로 넘긴다.
   - 본문을 바꾸거나 페이지를 만든 뒤, `fillDeferredCode` 가 글이 자리표시인 코드 블록을 찾아
     `blocks.update` 로 코드를 채운다.
   - 콜아웃 · 토글 · 목록 · 칼럼 안까지 찾고, 다 찾으면 더 읽지 않는다. 자식 페이지 · DB · 표 · 다른 곳이 원본인
     동기화 블록에는 들어가지 않는다.
   - 코드 블록 하나의 rich text 한도(2,000자 × 100조각)를 넘는 코드는 예전처럼 넓은 펜스째 보낸다.
2. **채우다 멈추면 지금 원격을 «지난번에 본 원격» 으로 적고 실패로 남긴다.** 기록하는 것은 수정 시각 · 편집자 ·
   본문 지문이다. 원격은 이 도구가 막 쓴 본문이고, 레코드의 내용 해시는 그대로다. 그래서:
   - 다음 push(이번 실행의 재시도 포함)는 이 쓰기를 pull 하지 않은 Notion 편집으로 보지 않는다. 본문을 다시
     보내 채운다.
   - 그 사이의 pull 은 받을 것이 없다고 본다. 자리표시가 든 본문을 노트로 받거나 충돌로 올리지 않는다.
3. **pull 은 Notion 규칙으로 코드 범위를 정해 경계 펜스를 넓힌다.** 다른 변환보다 먼저 한다
   (`widenNestedCodeFences`).
   - 여는 줄 = 탭 들여쓰기 + `+ Notion 언어 이름. 닫는 줄 = 같은 들여쓰기의 맨`.
   - 펜스는 코드 속 가장 긴 백틱 줄보다 하나 길게 넓힌다.
   - **컨테이너 안 코드**는 가장 가까운 같은 들여쓰기의 닫는 줄이 닫는다. 코드 줄은 열 0 이라 그 사이에 같은
     들여쓰기 줄이 올 수 없다. 그 뒤가 규칙에 어긋나면 건너뛰지 않고 읽기를 그만둔다 — 건너뛰면 뒤 블록을 삼킨다.
   - **맨 위 코드**는 모호할 수 있다. 코드 속 `python 줄은 여는 줄로, 맨 ` 줄은 닫는 줄로 보인다. 그래서
     닫는 줄을 건너뛸 수 있게 두고, 문서 끝까지 규칙에 맞게 가르는 방법을 동적 계획으로 찾는다.
   - 맨 위 코드 범위 안에 같은 들여쓰기 펜스 줄이 있을 때만 그 페이지의 코드 블록 글을 블록 API 로 읽는다
     (`getCodeBlockTexts`). 그 글과 같아지는 닫는 줄을 고른다.
   - 규칙에 맞게 가를 수 없으면 예전처럼 그대로 둔다.
4. **블록 폴백 pull**(notion-to-md)도 같다 — 코드에 ``` 줄이 있으면 그보다 긴 펜스로 감싼다.

## 선택지

| 선택지                                        | 판단                                                                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Markdown API 에 다른 펜스 · 이스케이프로 보냄 | 실측: 넓은 펜스 · `~~~` · 백슬래시 모두 그 줄에서 가른다 — 불가                                                        |
| 줄머리를 보이지 않는 글자로 바꿔 보냄         | Notion 의 코드 글이 바뀐다 — 복사해 쓰면 다르게 동작한다                                                               |
| 본문 전체를 블록 API 로                       | 콜아웃 · 토글 · 멘션 · 표를 블록 변환기로 다시 해야 하고, 그 경로는 이미 충실도가 낮다                                 |
| **자리표시 + `blocks.update`**                | 본문은 그대로 Markdown API 로, 코드 글만 블록 API 로 — **고른 것**                                                     |
| pull 에서 코드가 둘 이상인 페이지마다 글 읽기 | 남은 한계(아래)까지 막지만 실볼트 44노트가 받을 때마다 블록 트리를 읽는다 — 버림. 범위 안에 펜스 줄이 있을 때만 읽는다 |

## 남은 한계

- 맨 위 코드의 글에 **맨 `줄이 있고 그 뒤에 닫히지 않은`<Notion 언어> 줄**이 있으면 코드 둘로 읽는다. 가장
  가까운 닫는 줄로 가른 범위 안에 펜스 줄이 없어 블록 글을 읽지 않기 때문이다(`nested-code-fence.test.ts` 의
  `twoReadings`). 실볼트에는 이런 코드가 없다.
- 본문을 바꾼 뒤 채우기 전에 프로세스가 죽으면 Notion 에 자리표시 글이 남는다. 레코드는 옛 관측 그대로다.
  - 노트를 로컬에서도 고쳤으면 다음 pull 이 충돌로 올리고, 원격 쪽에 자리표시가 보인다.
  - 로컬을 고르면 다시 보내 채운다.
- 채우기가 끝나기 전(요청 몇 개 사이)에는 Notion 에 자리표시가 보인다.

## 트레이드오프

- **요청이 는다.** 이런 코드가 있는 페이지만 해당한다.
  - push: 코드마다 `blocks.update` 1번, 자리표시를 찾을 때까지 블록 목록을 컨테이너마다 1번 더 읽는다.
    실측: 코드 8개 → `PATCH blocks` 8 · `GET children` 5.
  - pull: 모호한 페이지만 블록 트리를 한 번 읽는다.
- **채우기 실패는 그 항목의 실패다.** 본문은 이미 바뀌었으므로 되돌리지 않고, 다음 push 가 마저 채운다.
- **원래 펜스 표기는 로컬 노트에서 되살린다**(S-20 의 `CodeLanguageRestorer`). 새 기기에서 처음 받으면 Notion
  이름 · 넓힌 백틱 펜스로 받는다 — 코드 글은 같다.
