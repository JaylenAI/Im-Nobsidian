# ADR-012: 폴더 노트가 폴더의 페이지다 — 새 폴더 노트를 먼저 만들고, push 가 만든 폴더 페이지는 폴더 노트가 이어받는다

> 상태: 승인
> 결정일: 2026-09-27

## 맥락

pull 은 Notion 페이지 P 와 그 하위 페이지를 폴더 `P/` 와 폴더 노트 `P/P.md` 로 받는다 —
폴더 노트가 곧 그 폴더의 페이지다. push 는 이 규칙과 어긋나게 폴더를 다뤘다(S-15).

| 경우                                        | v0.3.x · S-04 이후                                                                                                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 새 폴더와 그 폴더 노트를 한 push 에 만듦    | 풀 전에 조상 폴더를 모두 폴더 페이지로 만들었다(`ensureFolderPage`). 폴더 노트는 그 «아래» 에 같은 제목의 자식으로 생겼다 — Notion 에 같은 이름의 페이지가 두 겹  |
| 같은 폴더의 형제 노트                       | 풀 순서에 따라 두 부모로 갈렸다. 폴더 노트보다 먼저 처리된 형제는 폴더 페이지 아래, 뒤에 처리된 형제는 폴더 노트 아래(`folderContainer` 가 폴더 노트를 먼저 본다) |
| 다음 push                                   | 시작의 `repairFolderRecords` 와 `ensureFolderPage` 가 «폴더 노트가 페이지를 가진 폴더» 의 폴더 레코드를 지웠다. Notion 의 폴더 페이지는 그대로인데 추적만 놓았다  |
| 그다음 pull                                 | 추적하지 않는 폴더 페이지를 새 페이지로 보고 `P/P (id).md` 로 받았다                                                                                              |
| push 가 만든 폴더 페이지에 폴더 노트를 추가 | 위와 같은 두 겹 — 폴더 노트가 폴더 페이지의 자식으로 생겼다                                                                                                       |
| 폴더 하나의 자리를 못 만듦                  | 첫 차례의 `ensureFolderPage` 가 던지면 push 전체가 멈췄다 — 무관한 폴더의 노트까지                                                                                |
| 부모 폴더의 자리를 못 찾음                  | 폴더 페이지를 루트에 만들었다 — 볼트와 다른 자리                                                                                                                  |

실측(프로브, 빌드 `f9ec6c1` + S-11 브랜치): 새 폴더 `S-11 프로브 (v0.4)` 와 폴더 노트를 한
push 에 만들자 폴더 페이지 `…691b` 아래에 폴더 노트 `…0a2b` 가 생기고 형제 넷이 둘씩 갈렸다.
다음 push 가 폴더 레코드를 지웠고, 그다음 pull 이 `…691b` 를 `S-11 프로브 (v0.4) (3e813b18).md`
로 받았다.

## 결정

1. **새 폴더 노트가 폴더의 자리다** (`prepareFolders`). push 는 폴더의 자리를 풀보다 먼저
   마련한다 — 얕은 폴더부터. 자리가 없는 폴더에 이번 push 의 새 폴더 노트가 있으면 폴더 페이지를
   따로 만들지 않고 **폴더 노트를 먼저 올린다**. 폴더 노트는 폴더가 설 자리(폴더의 부모 폴더의
   자리, 맨 위면 루트)에 생긴다(`resolveNotionParent`). 같은 폴더의 노트와 하위 폴더는 그 아래로
   간다. 폴더 노트가 없는 폴더만 폴더 페이지(폴더 레코드)로 만든다.
2. **push 가 만든 폴더 페이지는 폴더 노트가 이어받는다** (`adoptFolderPage`). 폴더 레코드 `F`
   에 새 폴더 노트 `F/F.md` 가 생기면, 폴더 레코드의 경로를 `F/F.md` 로 옮겨 적는다. 그러면
   `pushCreate` 가 새 페이지를 만들지 않고 그 페이지의 갱신으로 넘어간다 — 본문은
   `replacePageBody`(ADR-009, 하위 페이지를 지우지 않는다)로 채우고, 제목은 frontmatter `title`
   이 있을 때만 보낸다. 페이지 id · 하위 페이지 · 댓글이 그대로다. 범위 push(`-p`)로 폴더 노트
   없이 먼저 올라간 폴더도 다음 push 가 이렇게 이어받는다.
3. **이어받을 수 없으면 만들지도 않는다.** 폴더 레코드에 끝나지 않은 이동 WAL 이 있거나, 폴더
   노트에 끝나지 않은 생성 WAL(생성 요청이 적용됐는지 모름)이 있으면 이번 push 는 그 폴더 노트를
   이유와 함께 실패로 남긴다. 새 페이지를 만들면 같은 이름의 두 겹이 다시 생긴다. WAL 이 풀리면
   다음 push 가 이어받는다.
4. **자리를 못 만든 폴더는 그 폴더 안만 실패한다** (`unpreparedFolders` · `folderNotReady`).
   폴더의 자리를 마련하다 실패하면 이유를 적어 두고 다음 폴더로 간다. 그 안의 노트 · 하위
   폴더(조상의 이유를 물려받는다)는 «폴더 페이지가 아직 없다» 가 아니라 **그 이유**와 함께
   실패로 남는다. 첫 차례에 새로 생긴 자리(새 행 · 폴더 노트)를 쓰도록 재시도 전에 폴더를 다시
   본다. 부모 폴더의 자리가 없으면 루트에 만들지 않고 이유와 함께 실패한다.
5. **폴더 레코드는 지우지 않는다** (`repairFolderRecords`). 지우는 것은 587b405 이전 push 가 남긴
   «루트 페이지를 맨 위 폴더의 페이지로 적은» 레코드뿐이다 — 루트는 어느 폴더의 페이지도 아니다.
   더 깊은 폴더는 그 부모 페이지를 다른 레코드가 이미 가리켜(`idx_sync_state_notion` 고유 색인)
   그런 레코드가 생길 수 없었다. dry-run 은 이것도 고치지 않는다.
6. **DB 모드(`parentMode: database`)는 이 규칙 밖이다.** 모든 노트가 루트 DB 의 행이라 폴더 노트가
   폴더의 자리가 아니다 — 폴더 페이지만 본다(예전과 같음).

## 이유

- **pull 과 같은 모양이다.** push 로 만든 트리를 pull 해도, pull 로 받은 트리를 push 해도 폴더
  노트 = 폴더 페이지다. 같은 이름의 두 겹과 `(id)` 파일이 구조적으로 생기지 않는다.
- **요청이 적다.** 폴더 노트가 있는 새 폴더는 폴더 페이지 생성 1 + 부모 목록 조회 1 이 빠진다.
  이어받기는 새 페이지 없이 본문 교체 1 이다.
- **이어받기는 되돌리기 쉽고 잃는 것이 없다.** Notion 에서 바뀌는 것은 본문뿐이다(빈 폴더
  페이지에 폴더 노트 본문). 하위 페이지는 `replacePageBody` 가 자리를 지킨다.
- **실패가 좁고 이유가 남는다.** 폴더 하나의 실패가 다른 폴더를 멈추지 않고, 사용자는 무엇을
  고쳐야 하는지(폴더 노트의 실패 사유)를 본다.

## 트레이드오프

- **이미 두 겹으로 생긴 데이터는 고치지 않는다.** v0.3.x · v0.4 개발 빌드가 만든 두 겹(폴더 페이지
  아래 같은 이름의 폴더 노트)과 `(id)` 파일은 그대로 둔다 — 어느 쪽을 지울지는 사람이 정한다.
  폴더 레코드가 남아 있으면 둘 다 추적하고, 새 노트는 폴더 노트 아래로 간다. 릴리스 노트에
  찾는 법과 정리법을 적는다.
- **옮겨 온 폴더 노트는 이어받지 않는다.** 폴더 레코드가 있는 폴더 F 로 노트를 옮기며 이름을
  `F.md` 로 바꾸면(이동은 기존 페이지를 옮긴다, ADR-011) 폴더 페이지와 폴더 노트 페이지가 형제로
  남는다. 드문 경우라 이동 규칙을 복잡하게 만들지 않았다.
- 이어받은 폴더 노트는 CLI 진행 표시에 `created` 로 보인다(새 파일이므로). Notion 에서는 새
  페이지가 아니다 — 로그에 「폴더 페이지를 폴더 노트의 페이지로 삼음」 이 남는다.
- 이어받을 때 폴더 페이지의 제목은 폴더 이름 그대로다. 폴더 노트 파일 이름이 폴더 이름과 같으니
  같은 제목이다. frontmatter `title` 이 있으면 그것으로 바꾼다.
- 새 폴더 노트는 풀에서 함께 가지 않고 풀보다 먼저 폴더마다 차례로 올린다 — 예전의 폴더 페이지
  생성(목록 조회 + 생성)이 차례로 가던 자리다. 새 폴더가 많은 push 에서는 폴더 노트끼리 병렬로
  가지 않는다.
