# ADR-017: 원격이 바뀌었는지는 수정 시각 · 편집자 · 본 때로 가르고, 못 가르면 내용으로 확인한다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

Notion 은 `last_edited_time` 을 분 단위로 자른다 — 초 · 밀리초가 늘 0 이다(실측, 2026-09-27).
v0.3 은 페이지마다 이 시각 하나만 적고, 원격이 바뀌었는지를 «시각이 같은가» 로만 봤다. 우리가 본
«뒤» 같은 분 안에 고친 것은 시각이 그대로라 보이지 않았다(N-05).

| 어디                | v0.3                                                   | 결과                                                                         |
| ------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------- |
| pull (`--force` 도) | 시각이 같으면 건너뛴다                                 | 같은 분 안의 Notion 편집을 받지 않는다 — 다음 편집이 분을 넘길 때까지 숨는다 |
| push (페이지)       | 원격을 보지 않고 본문을 바꾼다                         | pull 하지 않은 Notion 편집을 덮어쓴다                                        |
| push (DB 행)        | 원격 시각이 바뀐 것을 알고도 본문을 통째로 바꾼다      | 같다                                                                         |
| pull 충돌 판정      | `remote-first` 가 «원격이 바뀌었나» 확인보다 먼저 온다 | 원격이 그대로여도(수정 시각만 바뀐 페이지) 로컬 편집을 지난 사본으로 덮는다  |

시각을 초 단위로 받을 길은 없다. 페이지 객체 · 검색 결과 · DB 조회 결과 모두 같은 값을 준다.

## 결정

### 1. 원격을 볼 때 넷을 적는다 (상태 DB 스키마 4)

| 칸                        | 무엇                                                       |
| ------------------------- | ---------------------------------------------------------- |
| `notion_last_edited`      | 수정 시각(있던 칸)                                         |
| `notion_last_edited_by`   | 마지막 편집자 id                                           |
| `notion_seen_at`          | 이 동기화가 시작한 시각 — 실제로 본 시각보다 이르거나 같다 |
| `notion_body_fingerprint` | 원격 본문(Notion markdown)의 지문. 모르면 null             |

### 2. 먼저 시각 · 편집자 · 본 때로 가른다 (`compareRemote`)

- 시각이나 편집자가 다르면 **바뀌었다**.
- 그 분이 끝나고 시계 오차(60초)만큼 더 지난 뒤에 봤으면 **그대로다**(«가라앉음») — 그 분의 편집은
  모두 본 것이다. 뒤에 고치면 시각이 다음 분으로 넘어간다.
- 우리(이 토큰의 봇)가 마지막으로 썼고 지금도 편집자가 봇이면 **그대로다** — 그 뒤에 사람이 고치지
  않았다.
- 나머지는 **확인 안 됨** 이다. 내용으로 확인한다.

### 3. 내용은 본문 지문과 본문 밖으로 확인한다 (`remoteDrift`)

- **본문** — 지문(`remoteBodyFingerprint`)으로 견준다. 자식 페이지 · 자식 DB 태그는 뺀다: 자식은
  따로 추적하는 페이지고, 이 도구가 폴더에 노트를 만들면 부모 본문에 태그가 생기지만 부모의 본문은
  그대로다. Notion 이 호스팅하는 파일 URL 의 쿼리(서명, 약 1시간 만료)와 빈 줄 · 줄 끝 공백도 뺀다.
- **본문 밖** — pull 이 노트에 적는 것 중 본문이 아닌 것을 지난 동기화 사본(frontmatter)과 견준다.
  페이지는 제목, 행은 제목과 보낼 수 있는 속성, 행 렌더러로 받는 행(`db-row`)은 아이콘 · 커버까지.
  읽기 전용 속성(수식 · 롤업 · 수정 시각)은 보지 않는다 — 로컬에서 고칠 수 없고 push 가 보내지 않는다.
- 결과는 넷이다: `none`(그대로) · `outside-body`(본문 밖만 바뀜) · `body`(본문이 바뀜) · `unknown`
  (지문을 모름).

### 4. push 는 pull 하지 않은 원격 본문을 덮어쓰지 않는다

| 판정           | push                                                                                    |
| -------------- | --------------------------------------------------------------------------------------- |
| `none`         | 올리고, 쓴 뒤의 원격을 받은 것으로 적는다                                               |
| `outside-body` | 본문만 올린다. 받은 것으로 적지 않는다(지문만 새로) — 다음 pull 이 제목 · 속성을 받는다 |
| `body`         | 올리지 않는다 — «pull 로 먼저 받은 뒤 다시 push 하세요». pull 하면 충돌로 보인다        |
| `unknown`      | 같다                                                                                    |

확인하지 않고 덮어쓰는 경우: 충돌 해소 결과를 보낼 때 · 입양한 행을 맞출 때 · `local-first` ·
push 전용 방향 · 이 노트가 만든 페이지를 한 번도 맞추지 못했을 때(만들다 끊긴 페이지).

### 5. pull 도 같은 규칙을 쓴다

- «확인 안 됨» 인 페이지는 받아서 견준다. 원격이 그대로면(지문 · 본문 밖) 파일을 쓰지 않고 본 것만
  적는다 — 받은 것으로 세지 않는다.
- 충돌 판정기(`resolvePullConflict`)에 호출측이 확인한 «원격 그대로» 를 넘긴다. 렌더한 글이 지난
  사본과 달라도(이 도구가 만든 자식 페이지의 링크 · 왕복한 본문) 로컬 편집을 충돌로 올리지 않는다.
- 파일 끝 개행만 다른 글은 같은 글이다(`sameNoteContent`) — frontmatter 가 없는 노트는 pull 렌더에
  끝 개행이 없다(실측 G1). 그것만 다른 파일은 다시 쓰지 않고, 로컬을 사본으로 적는다.
- 전략(`remote-first` · `local-first`)은 «양쪽이 모두 바뀌었을 때» 무엇이 이기는지다. 원격이
  그대로인지 먼저 본다.
- `status` · `pull --dry-run` 은 «확인 안 됨» 을 내용으로 걸러, 그대로인 페이지를 원격 변경으로 세지 않는다.

### 6. 올릴 때 지문은 응답으로 얻는다

본문을 바꾼 응답(`pages.updateMarkdown`)의 markdown 은 다시 읽은 markdown 과 같다(실측, 2026-09-27,
자식이 있는 페이지). 한 번 더 읽지 않는다. 응답이 잘렸거나(`truncated` · `unknown_block_ids`) 첨부를
올리며 본문을 다시 고쳤으면 다시 읽는다. 블록 방식(`preferMarkdownApi: false`)으로 보냈으면 지문을
모른다(null) — 지문은 Markdown API 의 본문으로만 견준다.

### 7. 마이그레이션은 기존 레코드를 «지금 본 것» 으로 적는다

편집자 · 지문은 비운다. 비워 두면 첫 pull 이 모든 페이지를 내용으로 다시 확인한다(1,000 쪽이면
전체 pull 과 같은 비용). 대신 v0.3 이 놓친 같은 분 편집은 되찾지 않는다.

## 이유

- **초 단위 시각을 받을 길이 없다.** 시각 하나로는 같은 분을 가를 수 없다 — 편집자와 본 때를 더해야
  대부분의 페이지를 본문을 읽지 않고 가른다. 가라앉은 페이지 · 우리가 마지막으로 쓴 페이지는 본문을
  읽지 않는다.
- **본문 밖까지 견줘야 수렴한다.** 본문만 같다고 받은 것으로 적지 않으면, 다음 pull 이 방금 올린 본문을
  다시 받아 지난 사본과 견준다. 왕복한 본문은 글자로 같지 않아(끝 개행) 로컬을 다시 썼고, 그 사이 로컬을
  더 고쳤으면 충돌이었다(실측 r1 · r2).
- **push 와 pull 이 같은 규칙이어야 한다.** 한쪽만 지문을 보면, push 가 «그대로» 라며 올린 페이지를
  pull 이 «바뀜» 으로 받는다.

## 트레이드오프 · 알려진 한계

- **같은 토큰을 쓰는 다른 기기의 쓰기는 가리지 못한다.** 편집자가 같은 봇이다.
- **사람이 고친 직후 같은 분 안에 우리가 쓰면 가리지 못한다.** 예: 사람이 부모 페이지를 고친 분에 이
  도구가 그 아래 페이지를 만든다 — 편집자가 봇으로 바뀐다.
- **확인하고 쓰기까지 약 1초 사이의 Notion 편집은 덮어쓸 수 있다.** Notion 에 조건부 쓰기가 없다.
- **push `--dry-run` 은 원격을 묻지 않는다** — 거절은 실제 push 에서만 보인다.
- **지문을 모르는 페이지는 pull 전까지 push 를 거절할 수 있다.** 원격이 바뀐 것으로 보일 때만이다.
  - 충돌을 «원격 유지» 로 푼 페이지(언제 받았는지 모른다)
  - 이 도구가 만든 페이지(폴더 노트 말고는 지문 없이 적는다 — 편집자가 봇이면 지문이 필요 없다)
  - 업그레이드 전 레코드
  - `sync` 는 pull 을 먼저 하므로 걸리지 않는다
- **업그레이드 전 폴더 노트는 한 번 충돌하거나 다시 쓰일 수 있다.** v0.3 이 그 아래 페이지를 만들어
  수정 시각이 올랐는데 지문이 없다 — 글로만 가른다.
- **v0.3 이 놓친 같은 분 편집은 되찾지 않는다**(결정 7). 그 페이지가 다시 바뀌면 받는다.
- **거절된 push 는 한 번 더 시도된다** — 재시도 루프가 실패를 다시 부른다. 확인도 두 번 한다.
- **`local-first` 는 확인하지 않고 올리고 받은 것으로 적는다** — 같은 분 안의 원격 제목 변경도 가린다.
  설정이 로컬이 이긴다고 정했다.
- **Notion 에 올린 아이콘 · 커버 · 파일 속성은 있는지만 견준다** — 읽을 때마다 주소가 바뀐다(서명).
  같은 자리의 다른 파일로 바꾼 것은 보이지 않는다.
- **원격이 그대로인데 로컬을 고쳤으면, 자식 페이지 링크 · 읽기 전용 속성 값은 다음에 원격이 바뀔 때
  받는다.** 사람이 Notion 에서 부모에 자식을 더하거나 옮긴 것만 있으면 본문은 그대로다. 그 뒤 로컬
  push 는 링크가 없는 자식을 본문 끝에 둔다(ADR-009).
- **증분 pull 은 몇 초 전에 만들거나 고친 페이지를 못 볼 수 있다** — Notion 검색 색인이 늦다. `pull
--force` 가 받고, 증분 pull 도 15분 겹침 창에서 다음에 받는다(ADR-010).
