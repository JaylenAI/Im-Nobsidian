# ADR-057: 남은 파일 자리 — 행 이름의 폴더 · 볼트 맨 위 · 블록 방식 · 토글 안

> 상태: 승인
> 결정일: 2026-11-02
> ADR-056 의 「남은 한계」 가운데 Notion API 한계가 아닌 넷을 없앤다. 미리 보기의 새 페이지 상한도 함께 없앤다

## 맥락

ADR-056 은 폴더 노트 · 노트 이름의 폴더의 파일을 노트 페이지 끝에 「📁 이름」 으로 왕복시켰다. 다음은 남았다.

1. **DB 행 이름의 폴더**(`DB/행/`)의 파일 — 경고만 냈다. «행의 본문은 행의 것» 이라 실을 곳이 없다고 봤다
2. **볼트 맨 위** 파일 — 경고만 냈다. 맨 위의 Notion 자리(루트 페이지)는 기록이 없어 쓰지 않았다
3. **블록 방식 push**(`preferMarkdownApi: false` · Markdown API 실패)는 본문 블록을 모두 지우고 새로 붙여, 노트를 고칠 때마다 폴더
   첨부를 다시 올렸다
4. Notion 에서 폴더 첨부 블록을 **토글 · 콜아웃 안으로 옮기면** 들여 쓴 줄이라 노트의 임베드로 받아 받은 그림 폴더에 사본이 생겼다
5. 미리 보기는 새 페이지의 본문을 **100개까지만** 읽어, 그보다 많은 새 페이지 안의 DB 행을 세지 못하고 알리기만 했다

DB 폴더 바로 아래의 파일은 남긴다 — Notion 의 DB 에는 본문이 없어 실을 블록 자리가 없다(API 구조).

## 결정

1. **행은 노트와 같다** — 행도 본문이 있는 페이지다. 행 이름의 폴더(`DB/행/`)의 파일을 그 행 페이지 끝에 싣고, 행을 받을 때(DB 의 행
   받기 · 페이지 변경으로 받는 행 모두) 노트에서 떼어 그 폴더에 받는다. 행을 고쳐 올릴 때는 노트처럼 폴더 첨부 줄을 끝에 되싣는다.
   행이 충돌로 남거나 로컬을 지켜도 파일은 제 규칙대로 받는다. Notion 의 이름 바꾸기를 따르면 파일만 든 행 폴더도 행과 함께 옮긴다
2. **볼트 맨 위는 루트 페이지** — 페이지 모드의 루트(`notion.rootPageId`) 끝에 싣는다. 루트는 사용자의 페이지라 **노트 페이지처럼**
   이 도구가 적어 둔 폴더 첨부(파일 id) · 표시를 단 캡션의 블록만 고치고 지운다 — 사용자가 루트에 붙인 같은 이름의 파일은 받지도
   지우지도 않는다. 받기는 **루트가 바뀐 pull 에서만**(증분 search 에 루트가 들거나 전체 대조) 루트 본문을 한 번 읽는다. 파일을 올리거나
   지우면 루트의 수정 시각이 바뀌므로 다른 볼트의 다음 pull 이 읽는다. Markdown API 로 읽지 못하면 맨 위 블록에서 찾되 빠진 파일을
   지운 것으로 보지 않는다. DB 모드의 루트는 DB 라 여전히 경고
3. **블록 방식은 폴더 첨부 블록을 둔다** — 맨 위 블록 가운데 폴더 첨부(적어 둔 파일 id · 표시를 단 캡션)는 지우지 않고, 새 본문을
   **맨 앞에** 넣는다(`appendBlockTree` 의 `atStart` — 첫 묶음은 `position: start`, 다음 묶음은 앞 묶음의 마지막 블록 뒤). 맨 위에 없는
   폴더 첨부(토글 안으로 옮긴 것)는 그 토글과 함께 지워지므로 기록을 놓아 이어지는 첨부 push 가 끝에 다시 올린다
4. **들여 쓴 줄도 폴더 첨부면 뗀다** — 줄 하나가 통째로 파일 하나이고 표시 · 적어 둔 id 이면 들여쓰기와 상관없이 그 폴더의 파일이다.
   되실을 줄은 들여쓰기를 빼서 다음 노트 push 가 페이지 끝으로 되돌린다(토글에는 요약만 남는다). 코드 펜스 판정은 들여 쓴 펜스(토글
   속 코드)도 본다. 고치거나 지울 때 맨 위에서 옛 블록을 찾지 못하면 블록 트리에서 찾는다(드문 길이라 그때만 읽는다)
5. **미리 보기는 새 페이지를 모두 읽는다** — 미리 보기는 사용자가 부르고 멈출 수 있어 읽는 수를 묶지 않는다. 실제 pull 과 같은
   차례로 읽는다 — Markdown API, 실패하거나 블록 방식이면 블록 트리. 둘 다 읽지 못한 새 페이지만 알린다(문구 「Notion 에 새로 생긴
   페이지 가운데 본문을 읽지 못한 것이 있어 그 안의 DB 행은 미리 세지 않았습니다 — 받으면서 찾습니다」). 그 DB 의 폴더는 새 페이지가
   받힐 자리(부모의 자리 + 제목 — 실제 pull 의 `resolveParentPath`) 옆으로 짚는다. 예전에는 자리를 몰라 `databases/` 아래로 보였다(실측
   에서 찾음). 같은 이름이 있어 실제 pull 이 접미사를 붙이는 경우는 짚지 못한다

## 결과

- 볼트의 파일은 DB 폴더 바로 아래 · 받은 그림 폴더 · 숨김 파일 · Notion 이 받지 않는 형식을 빼고 모두 Notion 에 자리가 있다
- 업그레이드한 볼트의 첫 push 는 그동안 경고로 남던 행 폴더 · 볼트 맨 위 파일을 올린다 — 루트 페이지에 파일 블록이 더해진다
- 루트가 바뀐 pull 마다 루트 본문을 한 번 더 읽는다(요청 1회)

## 남은 한계

- DB 폴더 바로 아래 파일은 경고 — Notion 의 DB 는 본문이 없다
- 블록 방식에서 토글 안으로 옮긴 폴더 첨부는 노트를 고칠 때 한 번 다시 올린다(블록 API 는 블록을 옮길 수 없다 — 토글과 함께
  지워진다)
- Notion API 는 블록을 옮기지 못해, Notion 화면에서 토글 안으로 옮기는 것을 그대로 실측하지 못했다 — 토글 안에 새로 붙인 폴더 첨부로
  대신 봤다
