# ADR-026: 상태 DB 는 한 번에 한 곳만 연다 — 세션 잠금과 쓰기 전 확인

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

CLI 와 플러그인은 같은 상태 DB 파일(`.im-nobsidian/sync.db`)을 다른 방식으로 쓴다.

- CLI(better-sqlite3): 파일을 직접 열고 WAL 모드로 쓴다. 쓰는 동안 기록은 옆 `sync.db-wal` 에 쌓이고, 닫을 때
  본 파일로 합쳐진다.
- 플러그인(sql.js): 파일을 메모리 사본으로 읽고, 바뀌면 5초 뒤 사본을 파일째 갈아 끼운다.

둘을 한 볼트에서 함께 돌리면 어떻게 되는지는 ADR-024 가 트레이드오프로만 적었다(재지 않았다). 코드와 작업대로 본
것:

- CLI 가 도는 동안 플러그인이 열면 본 파일에 최근 기록이 없다. 체크포인트 전이면 표도 없는 4,096 B 파일이라,
  플러그인은 「동기화 기록이 없음」 과 파일을 치우라는 안내를 보였다. 안내대로 하면 기록을 잃는다.
- 플러그인은 CLI 가 쓴 기록을 모르는 사본을 파일째 써서 그 기록을 지운다. 기록을 잃은 노트는 다음 push 가 페이지를
  또 만든다.
- 플러그인이 파일을 갈아 끼우면 CLI 의 WAL 이 다른 파일에 붙는다.
- 끝나지 않고 죽은 CLI 는 기록을 WAL 에만 남긴다. 플러그인은 WAL 을 읽지 못한다.

Obsidian 을 켜 둔 채 터미널에서 `nobsi status` · `push` 를 부르는 것은 흔한 흐름이다.

## 결정

1. **한 볼트의 상태 DB 는 한 곳만 연다 — 세션 잠금.** 여는 쪽이 옆 `sync.db.lock` 을 `wx`(있으면 실패)로 만들고,
   닫을 때 지운다. CLI 는 `StateDB.open` · `close` 에서, 플러그인은 초기화 · 닫기에서 잡고 푼다. 막히면 쓰는 곳과 할
   일을 알린다(`StateDbLockedError`).
   - 잠금 파일에 주인을 적는다: 도구(cli · plugin) · 이름 · PID · PID 공간 · 실행 환경 · 시작 시각 · 표.
   - 쥔 동안 30초마다 잠금 파일의 수정 시각을 새로 적는다 — 살아 있다는 신호다.
   - 푸는 것은 내 표가 적힌 잠금일 때만이다. 넘겨받힌 잠금은 지우지 않는다.
2. **끝나지 않고 죽은 주인의 잠금은 넘겨받는다.** 넘겨받으면 경고 로그를 한 줄 남긴다.

   | 잠금 주인                                                                | 죽은 것으로 보는 때                                                                                |
   | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
   | 같은 PID 공간 · 다른 PID                                                 | 그 PID 가 없다                                                                                     |
   | 같은 PID · 다른 실행 환경                                                | 곧바로 — Obsidian 창을 새로 불러오면(Ctrl+R) 프로세스는 그대로이고, 옛 창의 플러그인은 풀지 못한다 |
   | 같은 PID · 같은 실행 환경                                                | 넘겨받지 않는다 — 플러그인만 다시 불러왔다. 새 인스턴스는 옛 인스턴스가 닫고 풀기를 기다린다       |
   | 다른 PID 공간(다른 컴퓨터 · 컨테이너 · flatpak · WSL) · 주인을 읽지 못함 | 신호가 2분(신호 간격의 네 배) 넘게 끊겼다                                                          |
   - PID 공간은 호스트 이름 · 플랫폼 · 리눅스 PID 네임스페이스로 가른다. 실행 환경은 JS 전역마다 새로 만드는 표다.
   - 치우는 것은 본 그대로일 때만이다. 보는 사이 다른 곳이 새로 잡았으면 두고 다시 본다. 엇갈림이 다섯 번
     거듭되면 멈춘다.

3. **플러그인은 WAL 에 기록이 남았으면 열지 않는다.** 잠금을 잡은 뒤 `sync.db-wal` 이 비어 있지 않으면, 끝나지 않고
   죽은 CLI(또는 잠금을 모르는 옛 CLI)의 기록이다. 잠금을 풀고, CLI 명령 하나로 합친 뒤 다시 하라고
   알린다(`PendingWalError`).
4. **플러그인은 쓰기 전에 파일이 읽은 그대로인지 본다**(`StateDbFile`). 잠금이 막지 못하는 곳이 있다 — 잠금을 모르는
   옛 CLI, 멈춘 줄 알고 넘겨받은 다른 PID 공간, 파일을 사본으로 되돌린 사용자 · 클라우드 동기화.
   - 쓰지 않는 때: 잠금이 내 것이 아니다 · WAL 에 기록이 있다 · 파일의 inode · 크기 · 수정 시각이 이 창이
     마지막으로 읽거나 쓴 것과 다르다. 파일 표는 읽기 «전» 에 적는다 — 적은 뒤 읽기 전에 바뀌어도 놓치지 않는다.
   - 쓰지 않았으면 사본을 버리고 파일에서 다시 연다. 낡은 사본으로 이어 가면 다른 곳이 받아 온 노트를 새 노트로
     보고 또 올린다. 버린 변경이 있으면 무엇을 잃었는지 알리고, 그 알림은 사용자가 닫을 때까지 남는다.
5. **화면은 까닭의 종류만 본다.** 사용자가 풀 수 있는 실패(`StateDbUnavailableError`)는 저마다 할 일(`guidance`)을
   싣는다 — 파일이 깨짐 · 다른 곳이 쓰는 중 · WAL 에만 남은 기록. CLI 는 「명령을 다시 실행하세요」, 플러그인은
   「동기화 사이드바에서 새로고침을 누르세요」 만 넘긴다.

## 선택지 — 두 도구가 같은 볼트를 쓸 때

| 선택지                                  | 판단                                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 두지 않음(예전)                         | 서로의 기록을 덮고, 플러그인이 틀린 안내(파일을 치우라)를 보인다                                                         |
| 작업마다 잠금(쓸 때만 잡음)             | 플러그인은 사본을 쥔 채 오래 산다. 작업 사이에 CLI 가 쓰면 사본이 낡는다 — 쓸 때마다 파일과 사본을 행 단위로 합쳐야 한다 |
| SQLite 파일 잠금에 맡김                 | 플러그인(sql.js)은 메모리에서 열어 파일 잠금을 보지 않는다                                                               |
| 플러그인도 better-sqlite3               | 네이티브 모듈이라 Obsidian 의 Electron 버전마다 다시 빌드해야 한다                                                       |
| **세션 잠금 + 플러그인의 쓰기 전 확인** | 흔한 흐름(Obsidian 을 켜 둔 채 CLI)을 막고 할 일을 알린다. 잠금이 못 보는 곳은 쓰기 전 확인이 잡는다 — **고른 것**       |

## 트레이드오프

- **함께 돌릴 수 없다.** Obsidian 을 켜 둔 채 같은 볼트에서 CLI 를 부르면 막힌다 — Obsidian 을 닫거나 그 볼트의
  플러그인을 끈 뒤 부른다. CLI `watch` 가 도는 동안에는 플러그인이 열리지 않는다.
- **옛 플러그인 + 새 CLI 는 막지 못한다.** 옛 플러그인은 잠금을 잡지도 보지도 않는다. 두 도구를 함께 올려야 한다.
- **옛 CLI + 새 플러그인** 은 플러그인의 쓰기 전 확인이 잡는다(WAL · 파일 변화). 그 사이 이 창의 사본에만 있던
  기록은 버려진다 — 알림으로 알린다.
- **알아보기 전에 sync 한 번이 낡은 사본으로 돌 수 있다.** 확인은 쓸 때(바뀐 뒤 5초) 한다.
- **다른 PID 공간은 2분을 기다린다.** 그쪽 주인이 죽으면 신호가 끊긴 지 2분 뒤에 넘겨받는다. 거꾸로 그쪽의 산
  주인이 2분 넘게 신호를 못 보내면(잠든 컴퓨터) 넘겨받힌다. 플러그인은 쓰기 전에 잃은 것을 알아보지만, CLI 는 쓰기
  전에 보지 않는다.
- **PID 재사용.** 같은 PID 공간에서 죽은 주인의 PID 를 다른 프로세스가 물려받으면 산 것으로 보고 막는다. 안내가
  잠금 파일을 지우라고 한다.
- **실행 환경 가정.** 한 프로세스에서 상태 DB 를 여는 JS 환경은 하나라고 본다. 워커 스레드에서 열면 이 가정이
  깨진다 — 지금은 열지 않는다.
- Obsidian 을 끝낼 때 닫기가 끝나지 않으면 잠금이 남는다. 같은 컴퓨터에서 다음에 여는 곳이 곧바로 넘겨받는다(그
  PID 가 없다).
- 잠금은 이 도구들끼리의 약속이다. `sqlite3` 셸 · 백업 프로그램은 보지 않는다.
