# ADR-055: 제목 링크 — 같은 push 의 새 노트 · 중첩 블록까지 찾고, 못 푼 까닭을 마커에 적는다

> 상태: 승인
> 결정일: 2026-11-02
> 「Notion API 한계를 빼고 모두 동기화」 계획의 P14 · ADR-048 을 잇는다

## 맥락

ADR-048 은 `[[노트#제목]]` · `[[노트#^블록]]` · `[[#제목]]` 을 Notion 블록 링크로 보낸다. push 는 대상 페이지의 **맨 위 블록**만
읽었고, 대상을 찾지 못한 링크는 위키링크 보존 마커로 남겨 Notion 에는 글자(`[[나#제목]]`)로 갔다. 실측(2026-11-02, 탐침
`__p14_links_20261102__`)에서 두 가지가 링크가 되지 않았다.

1. **같은 push 에서 뒤에 만든 노트 · 새 노트 자신의 제목** — push 할 때 그 페이지가 아직 없거나 블록이 비어 있다. 다음에 그 노트를
   고쳐 올릴 때까지 글자로 남았다
2. **콜아웃 · 목록 · 토글 속 제목과 `^블록`** — 맨 위 블록만 찾아 끝내 링크가 되지 않았다

push 뒤 패스(`push-link-pass`)는 풀 수 있게 된 위키링크가 있는 노트를 다시 보내는데, 제목 링크는 «대상 노트가 있다» 만 보고 골라
없는 제목으로 가는 링크를 push 마다 다시 보냈다.

## 결정

1. **맨 위에서 못 찾으면 블록 나무 전체에서 찾는다** — 맨 위 블록을 먼저 읽고(대부분 여기서 끝난다) 하나라도 없으면
   `getBlockTree` 로 중첩 블록까지 편다(`flattenBlockTree`). 나무를 읽지 못하면 맨 위 블록만으로 푼다
2. **못 푼 까닭을 마커에 적는다**(`anchor`) — `page` 는 대상 페이지가 아직 없음(같은 push 의 새 노트 · 자기 노트), `block` 은 페이지는
   있는데 그 제목 · 블록이 없음
3. **push 뒤 패스는 까닭으로 고른다** — `page` 는 이제 페이지가 있으면 다시 보낸다. `block` 은 이번 push 에서 대상 노트를 올렸을 때만
   (제목이 새로 생겼을 수 있다). 까닭이 없는 옛 마커는 한 번 다시 보내 까닭을 적는다

## 결과

- 한 번의 push 로 같은 push 의 새 노트 · 자기 제목 · 콜아웃 속 제목 · 목록 속 블록 id 가 모두 Notion 블록 링크가 된다. 두 번째 push 는
  변화 0. 다른 볼트가 받으면 같은 `[[노트#제목]]` 으로 돌아온다(실 Notion 두 볼트)
- 없는 제목으로 가는 링크는 대상 노트가 바뀌지 않는 한 다시 보내지 않는다

## Notion 에서만 제목을 고치면 (2026-11-02 실측)

- 볼트의 링크는 블록 id 를 따라간다 — 다음 pull 에서 `[[X#옛 제목]]` 이 `[[X#새 제목|X > 옛 제목]]` 이 된다. 링크는 깨지지 않고, 보이는
  글은 옛 제목으로 남는다. Notion 의 블록 링크 글자도 옛 제목 그대로 남으므로 그것을 따른다
