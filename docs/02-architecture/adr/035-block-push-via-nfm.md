# ADR-035: 블록 방식 push 는 Markdown API 경로와 같은 NFM 을 Notion 의 가져오기 규칙대로 블록으로 만든다

> 상태: 승인
> 결정일: 2026-10-20
> 바꾼 것: 블록 방식 push 의 martian 변환(`BlockConverter.markdownToNotionBlocks`) — 따로 정한 ADR 은 없었다

## 맥락

push 는 Markdown API 로 본문을 보낸다. `conversion.preferMarkdownApi: false` 이면 블록 API 로 보낸다(블록 방식).
블록 방식은 볼트 마크다운을 martian 으로 블록으로 바꿨다. Markdown API 경로가 쓰는 NFM 변환은 거치지 않았다.

같은 노트가 보내는 길에 따라 다른 페이지가 됐다. 같은 노트를 두 변환에 넣어 견줬다(2026-10-20).

| 볼트                   | Markdown API 경로   | 예전 블록 방식                      |
| ---------------------- | ------------------- | ----------------------------------- |
| `> [!tip] 제목` 콜아웃 | 콜아웃(제목 · 자식) | 인용 — 글에 `[!tip] 제목` 이 남는다 |
| `[[콜아웃]]` 위키링크  | 페이지 멘션         | 링크 없는 글                        |
| 5단계 목록             | 5단계 그대로        | 3단계로 평탄화                      |
| 150행 표               | 표 하나             | 100행 이하 표 여럿으로 쪼갬         |

두 변환이 같은 볼트 모양을 따로 구현하는 한 다시 갈라진다. ADR-034 가 pull 쪽에서 같은 이유로 길을 하나로
모았다.

## 실측 — Notion 이 NFM 을 블록으로 만드는 규칙

탐침 페이지에 NFM 을 Markdown API 로 보내고, Notion 이 만든 블록 트리를 받았다(20장,
`tests/fixtures/nfm/notion-import/`). 규칙은 `converter/nfm-to-blocks.ts` 머리말에 적었다. 그중 짐작과 달랐던 것:

- `####` ~ `######` 는 모두 제목 4 다. `1)` 은 번호 목록이 아니다.
- GFM 표는 맨 앞 `|` 와 구분 줄이 있어야 표다. 첫 행이 머리 행이 되고, 정렬은 버리고, 너비는 가장 긴 행이다.
- `> > x` 는 글이 `> x` 인 인용 하나다. 줄 끝 공백 둘 · `\` 는 글자로 남는다.
- 펜스의 들여쓰기는 몸통 줄이 모두 그 들여쓰기로 시작할 때만 걷는다.

블록 API 의 한도도 쟀다(2026-10-12 · 2026-10-20).

- 요청 하나에 자식은 두 단계까지, 배열 하나에 100 개, 블록 1000 개 · 500KB 까지 받는다.
- 칼럼 묶음은 칼럼이 둘 이상이어야 한다. 빈 인라인 수식과 `icon: null` 콜아웃은 거부한다.
- 색을 뺀 목차는 회색이 된다. `color: "default"` 를 보내면 기본색이다.

## 결정

블록 방식도 Markdown API 경로와 같은 NFM 을 만든다(`obsidianToNotionEnhanced`). 그 NFM 을 Notion 의 가져오기와
같은 블록으로 옮겨(`nfmToBlocks`) 블록 API 로 보낸다(`NotionClient.appendBlockTree`).

- 블록은 깊이 제한 없이 만든다. `appendBlockTree` 가 요청 한도 안으로 나눈다. 넘는 자식은 부모를 만든 뒤 그
  아래에 마저 붙인다. 목록 · 표 · 칼럼이 볼트의 모양 그대로 남는다.
- 북마크는 Notion 의 블록을 가리키는 자리 태그로는 만들 수 없다. 볼트의 링크 쌍(`vaultBookmarks`)에서 주소와
  캡션을 받아 새 북마크로 만든다.
- Notion 이 내용을 잃는 곳만 일부러 다르게 만든다. 픽스처의 `ours` · `why` 가 그곳이다.
  - 콜아웃 첫 줄 아래 더 깊은 줄은 자식으로 남긴다.
  - 칸 수가 다른 표는 가장 긴 행으로 맞춘다.
  - 표 칸 속 `\|` 는 칸을 가르지 않는다.
  - 백틱 넷 이상 펜스는 여는 길이 이상의 줄에서만 닫는다.
- 블록 API 가 거부하는 모양은 바꿔 보낸다. 칼럼 하나짜리 묶음은 그 칼럼의 블록을 그 자리에 둔다. 빈 인라인
  수식(`$$`)은 글자로 둔다.

받아들이는 기준은 둘이다. 픽스처 20장에서 일부러 다르게 만든 곳 말고는 Notion 의 블록 트리와 같다. 실 Notion
에서 만든 블록을 다시 읽으면 보낸 것과 같다(아래 한계 빼고).

## 블록 API 로 만들 수 없는 것

| 무엇                                      | 결과                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------- |
| 아이콘 없는 콜아웃                        | Notion 이 💡 를 단다 — 아이콘 없이 만들 수 없다                       |
| 동기화 원본(`<synced_block url>`)         | 새 원본이 된다 — 다른 페이지의 그 원본 참조는 이어지지 않는다         |
| 자식 페이지 · DB(`<page>` · `<database>`) | 보내지 않는다 — 다른 페이지를 옮기지 않는다                           |
| 바로가기 · 모르는 블록(`<unknown>`)       | 버린다 — 경로(breadcrumb)는 새로 만든다                               |
| 주소를 모르는 북마크                      | 버린다 — 볼트 링크가 Notion 자리 주소뿐이면(`🔖 Bookmark`)            |
| 표의 열 너비 · 행 색                      | 기본값이 된다                                                         |
| 각주 `[^1]`                               | 글자로 둔다 — Notion 은 주소 `1` 링크로 만들지만 블록 API 는 거부한다 |
| 시간 있는 날짜 멘션                       | 같은 순간을 오프셋 붙인 시각으로 돌려준다 — Markdown API 경로도 같다  |

## 트레이드오프

- Notion 의 가져오기 규칙을 우리가 다시 구현한다. Notion 이 규칙을 바꾸면 블록 방식만 옛 모양을 낸다. 픽스처가
  그때 다시 잴 근거다.
- 블록 방식은 갱신 때 본문을 통째로 다시 만든다(예전과 같다). 블록 id 는 남지 않는다 — 블록 id 를 지키려면
  Markdown API 경로를 쓴다.
- martian 의 push 쪽(`BlockConverter.markdownToNotionBlocks`)은 제품 경로에서 쓰이지 않게 됐다. v0.4.0 에서
  지웠다(`refactor/remove-legacy-converters`). martian 은 글 조각의 rich text(`nfm-inline`)에만 남는다.
