# ADR-014: 새 페이지 · 행은 만든 직후 맨 앞 `# H1` 을 되살린다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

Notion 은 markdown 으로 페이지를 만들 때(`pages.create` 의 `markdown`) 맨 앞 `# H1` 을 버린다.
push 는 새 노트를 이 요청 하나로 만들었다 — `# 제목` 으로 시작하는 노트는 Notion 본문에 그 제목이
없었다. 로컬 노트는 그대로라 아무도 몰랐고, Notion 에서 그 페이지를 고치면 pull 이 제목 없는 본문을
받아 로컬 노트의 제목까지 지웠다.

실측(프로브 루트 아래, 2026-09-27 · 행은 2026-09-28):

| 만든 방법                                | 보낸 본문                 | Notion 블록                    |
| ---------------------------------------- | ------------------------- | ------------------------------ |
| `pages.create` + `markdown`              | `# H1` · 본문             | 문단만 — **H1 이 사라짐**      |
| 〃                                       | 본문 · `# 가운데 H1` · 끝 | 문단 · heading_1 · 문단 — 남음 |
| 〃                                       | `## 맨 앞 H2` · 본문      | heading_2 · 문단 — 남음        |
| `pages.create` + `children`(블록)        | heading_1 블록 · 문단     | heading_1 · 문단 — 남음        |
| `pages.updateMarkdown` `replace_content` | `# 바꾼 H1` · 본문        | heading_1 · 문단 — 남음        |
| DB 행 `pages.create` + `markdown`        | `# 행 맨 앞 H1` · 본문    | 문단만 — **H1 이 사라짐**      |

## 결정

1. **만든 직후 한 번 되살린다.** 본문으로 보낸 markdown 이 `# H1` 으로 시작할 때만 같은 markdown 으로
   본문을 한 번 바꾼다(`NotionClient.restoreLeadingHeading`). 판정은 `startsWithHeading1` — 앞의 빈
   줄은 건너뛰고, 세 칸까지 들여쓴 `#` 도 제목이며, `#태그` 처럼 `#` 뒤에 공백이 없으면 제목이 아니다.
   나머지 노트는 요청을 더하지 않는다.
2. **매핑을 먼저 적고 부른다.** 생성 직후 적는 전이 레코드(pending · 해시 빈 값) 다음이다. 되살리기가
   실패하면 그 항목만 실패한다 — 같은 push 의 재시도나 다음 push 가 새로 만들지 않고 갱신으로 본문을
   다시 보낸다. 갱신(`replace_content`)은 맨 앞 H1 을 남긴다.
3. **첨부를 올리기 전에 부른다.** 첨부 업로드는 본문의 자리표시자를 이미지 · 파일 블록으로 바꾼다 —
   뒤에서 교체하면 자리표시자가 되돌아온다.
4. **되살렸으면 수정 시각을 다시 받아 적는다**(`getPage`, I5). 만들 때의 시각을 적으면 다음 pull 이
   이 교체를 원격 수정으로 보고 그 페이지를 다시 읽는다.
5. **블록 방식(`preferMarkdownApi: false`)은 부르지 않는다** — 블록은 보낸 그대로 생긴다(위 표).
6. **설정 DB 의 행도 같다**(`DatabaseSyncer.pushDatabaseRow`). 실패하면 매핑은 적되 해시를 비우고
   `failed` 로 돌려준다 — 다음 push 가 갱신 경로로 본문을 다시 보낸다.

## 이유

- **만드는 요청만으로는 제목을 지킬 방법이 없다.** 맨 앞에 빈 블록을 끼우면 Notion 에 빈 줄이 생기고
  pull 이 그것을 로컬에 가져온다. H1 으로 시작하는 노트만 블록 방식으로 만들면 변환 경로가 둘로
  갈린다 — markdown 경로가 싣는 Notion 확장 문법(색 · 멘션 · 콜아웃)이 그 노트에서만 달라진다.
- **드는 요청이 적다.** 만들 때는 속성만 보내고 본문을 늘 따로 보내면 모든 새 노트가 요청 하나를 더
  쓴다. 되살리기는 H1 으로 시작하는 노트에만 든다 — 지정 볼트 1,271 노트 중 23개(frontmatter 없는
  8 · frontmatter 뒤 15). 페이지 모드에서 frontmatter 가 있는 노트는 속성 블록이 먼저 가므로 H1 이 맨
  앞이 아니다.
- **실패해도 중복이 없다.** 매핑이 먼저 있으므로 다시 시도하는 쪽은 언제나 갱신이다(I12 WAL 과 같은
  원리).

## 트레이드오프

- H1 으로 시작하는 새 노트는 요청이 둘 더 든다(본문 교체 · 수정 시각 조회).
- 만든 순간부터 되살릴 때까지 Notion 에는 제목 없는 본문이 잠깐 있다. 되살리기가 두 번 다 실패하면
  다음 push 까지 그대로다 — 그 항목은 실패로 보인다.
- Notion 이 이 동작을 바꿔 맨 앞 H1 을 남기게 되면 교체는 같은 본문을 한 번 더 보내는 헛요청이 된다.
  결과는 같다.
- **이미 만들어진 페이지는 고치지 않는다.** v0.3.x 이하가 만든 페이지는 Notion 에 그 제목이 없다.
  로컬 노트를 한 번 고쳐 push 하면 갱신이 본문을 통째로 보내 되살아난다. 그 전에 Notion 에서 고치고
  pull 하면 로컬 제목이 지워진다 — 릴리스 노트에 적는다.

## 영향

- 수정: `notion/client.ts`(`startsWithHeading1` · `restoreLeadingHeading`), `sync/orchestrator.ts`
  (`pushCreatePage` 가 보낸 markdown 도 돌려줌 · `restoreCreatedHeading` · 페이지와 자동 발견 DB 행의
  생성 경로), `sync/database-syncer.ts`(설정 DB 행의 생성 경로)
- 시험 하니스: 메모리 Notion 이 markdown 으로 만들 때 맨 앞 `# H1` 을 버린다. 되살릴지는 제품 코드가
  정한다 — 메모리는 전송만 흉내 낸다
- 공개 API · 상태 DB 스키마 · 설정: 변경 없음
