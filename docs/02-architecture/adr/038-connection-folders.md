# ADR-038: 볼트 하나에 Notion 연결 여럿 — 연결 폴더

> 상태: 승인
> 결정일: 2026-10-23

## 맥락

설정 · 상태 DB 는 볼트 맨 위 `.im-nobsidian/` 하나뿐이었다. 토큰 하나 · 루트 페이지 하나라서, 회사 워크스페이스와 개인
워크스페이스를 한 볼트에 두려면 볼트를 둘로 나눠야 했다.

## 선택지

| 안                                                             | 장점                                                                    | 단점                                                                                                                                       |
| -------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| A. 한 상태 DB 에 연결 칸을 더한다                              | DB 가 하나                                                              | 레코드 · 메타(발견 DB · 마지막 전체 대조 · 이름 변경 힌트)를 모두 연결별로 나눠야 한다. 엔진 곳곳이 바뀐다                                 |
| **B. 연결마다 볼트 안 폴더 하나 · 그 폴더의 `.im-nobsidian/`** | 엔진은 그대로 — 연결 폴더를 볼트처럼 본다. CLI 는 그 폴더에서 돌리면 끝 | 한 노트는 한 연결에만 속한다. 연결 사이의 위키링크는 Notion 링크가 되지 않는다                                                             |
| C. 경로 규칙(include)으로 연결마다 맡을 노트를 고른다          | 폴더에 묶이지 않는다                                                    | 규칙이 겹치면 한 노트를 두 연결이 올린다. 지금 `paths.include` 는 목록만 거르고 pull 의 쓰기는 거르지 않는다 — 다른 연결의 노트를 덮어쓴다 |

## 결정

**B.**

1. **연결 폴더** 는 자기 `.im-nobsidian/`(설정 · `sync.db` · 보기 설정)를 둔 볼트 안의 폴더다. 볼트 맨 위도 연결 폴더(`""`)다 —
   예전의 단일 연결이 그대로 그것이다.
2. 엔진은 연결 폴더를 `ScopedVaultFS` 로 본다. 경로는 그 폴더 기준이다.
   - 목록: 그 폴더 안 · **안쪽 연결 폴더 밖** 의 파일만. 이 연결의 내부 폴더는 뺀다.
   - 쓰기 · 지우기 · 옮기기: 폴더를 벗어나거나 안쪽 연결 폴더에 닿으면 `ConnectionBoundaryError` 로 거절한다.
     바깥 연결의 Notion 에 안쪽 폴더와 같은 자리의 페이지가 있으면 pull 이 그 페이지를 실패로 알린다 — 덮어쓰지 않는다.
   - 읽기: 볼트 안이면 폴더 밖도 된다. Obsidian 설정(`types.json`)은 볼트 맨 위에 하나다.
3. 🔴 **이미 동기화하던 폴더는 따로 연결하지 않는다.**
   - 바깥 연결의 상태 DB 가 그 폴더의 노트를 추적하고 있으면, 바깥 연결은 그 노트들을 목록에서 못 찾아 「볼트에서 지움」 으로
     본다. `deleteSync` 면 Notion 페이지를 지우고, 아니면 되살리려고 그 폴더에 쓴다.
   - 그래서 `init` 이 거절하고(바깥 연결의 DB 를 열어 그 폴더의 레코드를 센다), 엔진은 그런 레코드가 있으면 push · pull ·
     status 를 시작하지 않고 `ConnectionScopeError` 로 멈춘다(설정 폴더를 손으로 복사한 경우).
   - 이미 올린 노트를 Notion 의 다른 워크스페이스로 옮기는 길은 API 에 없다(워크스페이스 사이 이동 없음).
4. CLI: 연결 폴더에서 돌린다(`cd Work && nobsi sync`). 맨 위에서 돌리면 안쪽 연결 폴더를 비켜 가고 `status` 가 그 폴더를
   알린다. `prepare-db` 는 위로 올라가 `.obsidian` 을 찾는다.
5. 플러그인: 설정의 `connections` 에 폴더 연결(폴더 · 키체인 토큰 이름 · 루트 페이지)을 둔다. 볼트 맨 위 연결은 예전
   설정 그대로다. 연결마다 `ConnectionEngine`(상태 DB · 잠금 · 컨트롤러)을 하나씩 돌리고, 볼트 이벤트는 경로로 그 연결에
   보낸다. 명령은 준비된 연결마다 차례로 돈다. 변경 패널은 연결 하나를 고르게 한다. 설정의 폴더 고르개는 그 폴더를 맡은
   연결이 노트를 동기화하는 폴더를 보이지 않는다(3 의 거절을 미리 막는다).

## 트레이드오프

- 연결 사이 위키링크(`[[Work/회의]]` 를 개인 노트에서)는 Notion 링크가 아니라 글자로 남는다 — 페이지가 다른 워크스페이스에
  있으면 Notion 은 링크를 걸 수 없다(멘션도 같은 워크스페이스만).
- 한 노트를 두 워크스페이스에 함께 올리지 않는다.
- 연결 폴더를 옮기거나 이름을 바꾸면 그 안의 경로는 그대로라 그 연결에는 변경이 없다. 바깥 연결이 보기에는 연결 폴더가
  목록에 없던 그대로다.
