# ADR-049: 상태 DB 를 잃은 볼트 다시 잇기

> 상태: 승인
> 결정일: 2026-10-31
> 「Notion API 한계를 빼고 모두 동기화」 계획의 P7(신뢰성)의 마지막 항목. ADR-019(중단 복구)와 같은 자리에 선다

## 맥락

상태 DB(`.im-nobsidian/state.db` · 플러그인 `data` 의 sql.js)는 노트와 Notion 페이지를 잇는 유일한 기록이다. 그것을 잃으면
(파일을 지움 · 볼트만 다른 기기로 옮김 · 플러그인을 다시 설치) 볼트에는 받은 노트가 그대로 있는데 아무것도 이어져 있지 않다.

실측(메모리 Notion, 2026-10-31): 올리고 받은 볼트에서 상태 DB 만 지운 뒤

- `pull` — 모든 페이지 · 행을 남의 노트가 있는 자리로 보고 id 를 붙인 이름(`A (1a2b3c4d).md`)으로 **한 벌 더** 받았다
- `push` — 모든 노트를 새 노트로 보고 Notion 에 **한 벌 더** 만들었다(페이지 4 → 8)
- `sync` — pull 이 먼저 두 벌을 만들고 push 가 그 두 벌을 지켰다

어느 쪽도 오류를 내지 않았다. 사용자는 두 벌이 된 뒤에야 알고, 되돌리려면 Notion 과 볼트에서 손으로 지워야 한다.

라이브(2026-10-31, 탐침 `__p7_relink_20261031__` — 노트 6 · 폴더 2 · 행 2, 외부 그림 · 볼트가 올린 그림 · 서로 가리키는 링크)에서
다시 잇기를 처음 붙였을 때 남은 것이 셋이었다 — 아래 「견주기」 로 고쳤다.

- 볼트가 올린 그림이 든 노트가 충돌이 되고 `attachments/` 에 같은 그림이 한 벌 더 생겼다 — 올린 미디어 기록도 함께 잃었다
- 서로 가리키는 노트(`[[b]]`)가 충돌이 됐다 — 링크 대상이 아직 이어지지 않아 받은 글의 링크가 `[[notion:<id>]]` 로 남았다
- 폴더 노트 없는 폴더 페이지 둘을 «생성 2» 로 셌다 — 폴더는 이미 있었다

## 선택지

1. 상태 DB 를 볼트 밖에 백업한다 — 잃는 까닭(볼트만 옮김 · 재설치)에서 백업도 함께 잃는다
2. 노트 frontmatter 에 페이지 id 를 적는다 — 모든 노트의 글을 바꾸고, 사용자가 지우거나 복사하면 두 노트가 한 페이지를 가리킨다
3. **pull 이 같은 자리의 노트를 다시 잇고, push 는 비어 있는 상태로 올리기 전에 멈춘다**

## 결정

3 을 택한다.

**pull — 다시 잇기.** 상태 기록에 없는 노트가 그 페이지 · 행이 놓일 자리에 이미 있으면 받은 글과 견준다. 자리는 이 페이지
id 를 단 이름(`이름 (id8|id16|id32).md` — 지난번 이 페이지를 받은 이름)을 먼저, 그 다음 자연 이름(`이름.md`)을 본다.

| 노트                      | 이은 노트가 있는 볼트                        | 이은 노트가 없는 볼트(상태 DB 를 잃음) |
| ------------------------- | -------------------------------------------- | -------------------------------------- |
| 같은 글(끝 개행만 달라도) | 잇는다 — 쓰지 않는다                         | 잇는다 — 쓰지 않는다                   |
| 다른 글 · id 를 단 이름   | 전략을 따라 잇는다                           | 전략을 따라 잇는다                     |
| 다른 글 · 자연 이름       | **잇지 않는다** — 예전처럼 id 를 붙여 받는다 | **충돌로** 잇는다(전략과 상관없이)     |

전략: remote-first 는 받은 글로 덮고 · local-first 는 노트를 두어 이어지는 push 가 같은 페이지를 고치고 · manual · merge ·
duplicate 는 충돌로 남긴다(지난 사본이 없어 merge 도 합칠 수 없다 — `baseContent: null`). 자연 이름의 다른 글은 정말 그
페이지의 노트인지 모른다 — 처음 연결하는 볼트의 `Inbox.md` 가 Notion 의 다른 `Inbox` 와 이름만 같을 수 있다. 전략대로 덮거나
올리면 어느 한쪽을 잃으므로 늘 충돌로 남겨 고르게 한다. 이은 것은 `PullResult.relinkedPaths` 로 알리고 `created` 에 세지 않는다.

**견주기.** 받은 글과 노트를 견줄 때 둘을 더 본다.

- 미디어 — 받은 미디어의 올라간 이름이 노트의 임베드 파일 이름과 같고 그 볼트 파일과 바이트(sha256)가 같으면 사본을 받지 않고
  노트의 임베드로 되살리고 받은 미디어로 적는다(`ImageHandler.adoptLocalEmbed`). 이름만 같고 바이트가 다르면(Notion 에서 바꾼
  그림) 사본을 받는다 — 노트와 달라 충돌이 된다
- 링크 — 아직 풀지 못한 링크 자리(`[[notion:<id>|별칭]]` · frontmatter relation 의 원시 id)는 노트의 같은 자리 위키링크 ·
  마크다운 링크와 같다고 본다. 별칭이 있으면 노트 링크의 대상이나 별칭이 그것이어야 한다(`sameAsPendingLinks`). 이은 노트는
  쓰지 않으므로 노트의 링크가 그대로 남는다

폴더로만 받는 페이지의 폴더가 이미 있으면 그 폴더를 잇고 생성으로 세지 않는다.

**push — 멈추기.** 상태 기록이 비어 있고(끊긴 첫 push 의 자리표시 · 끝나지 않은 작업도 없음) 새로 만들 노트의 페이지가 놓일
자리에 Notion 이 같은 이름을 이미 들고 있으면 `UnlinkedVaultError` 로 멈추고 겹친 노트를 알린다 — 「먼저 pull(또는 sync)」.
자리는 Notion 을 이름으로 따라 내려가 본다:

- 폴더 → 같은 이름의 하위 페이지 · DB(push 도 폴더 페이지는 제목으로 찾아 쓰므로 같은 이름의 빈 폴더 페이지만 있으면 겹치지 않는다)
- 노트 → 그 아래의 같은 이름 페이지 · 행. 폴더 노트(`X/X.md`)는 폴더 페이지 자신
- 설정한 DB 폴더의 노트 → 그 DB 의 행 제목 · DB 모드 → 루트 DB 의 행 제목

Notion 을 읽지 못한 노트는 그 노트만 이유와 함께 실패로 남기고 올리지 않는다(읽지 못함 ≠ 없음). push 만 하는 연결
(`direction: push`)은 받을 수 없어 막지 않는다. 같은 `sync` 의 dry-run 은 pull 이 먼저 잇는다고 미리 보므로 막지 않는다.

**dry-run.** 노트 글을 받아 견주지 않으므로(부모가 아직 이어지지 않아 자식의 자리도 모른다) 이을 노트를 하나하나 보이지 않고
`relinkPending` 으로 「받으면 다시 잇는다 — 미리 보기는 그 노트들도 생성으로 센다」고 알린다.

## 이유

- 같은 자리 · 같은 글은 같은 페이지라고 볼 근거가 충분하다. 다른 글이어도 상태 DB 를 잃은 볼트에서는 같은 자리의 노트가
  그 페이지일 가능성이 압도적이다 — 두 벌로 받는 것보다 충돌로 남겨 사용자가 고르게 하는 편이 되돌리기 쉽다
- 이은 노트가 있는 볼트에서 자연 이름의 다른 글은 그 볼트가 아직 올리지 않은 새 노트일 수 있다 — 잇고 덮으면 노트를 잃는다
- push 를 멈추는 것은 되돌릴 수 없는 일(Notion 에 두 벌)을 막는 가장 싼 자리다. 처음 올리는 볼트(겹침 없음)는 그대로 지나간다

## 트레이드오프

- 잃은 것은 다시 세우지 못한다: 지난 사본(merge 의 공통 조상) · `file_registry`(올린 첨부) · 보존 마커. `uploaded_media` 는
  바이트가 같은 미디어만 되살린다. 그래서 보존 마커가 있던 노트 · 바이트가 달라진 그림이 든 노트는 충돌이 될 수 있다 —
  사용자가 「로컬」을 고르면 같은 페이지를 고친다
- 볼트가 올린 미디어를 이을 때 그 미디어를 한 번 내려받아 견준다(이름이 같은 임베드가 있을 때만)
- 링크 자리는 별칭이 없으면 어느 링크든 같다고 본다 — 링크 대상만 다른 노트는 같은 노트로 잇는다(다음 push 가 노트의 링크로 고친다)
- 이름을 바꿔 둔 노트(자리가 다른 노트)는 잇지 못한다 — 예전처럼 id 를 붙여 받는다
- push 가 멈추는 판정은 이름만 본다 — 같은 자리에 같은 이름이 있으면 글이 달라도 멈춘다(pull 이 충돌로 잇는다)
- 상태 기록이 빈 볼트의 push 는 만들 노트의 폴더마다 하위 목록을 한 번 읽는다(같은 폴더는 다시 읽지 않는다)
- dry-run 은 다시 이을 노트를 생성으로 센다(위)
