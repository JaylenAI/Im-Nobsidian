# ADR-013: pull 은 push 가 만든 폴더 페이지를 폴더로 받는다 — 아래 페이지는 그 폴더에, 본문이 생기면 폴더 노트로

> 상태: 승인
> 결정일: 2026-09-27

## 맥락

폴더 노트 없이 올린 폴더는 push 가 폴더 페이지를 만들고 폴더 경로 자체(`A/B`)로 추적한다 —
폴더 레코드(ADR-012). pull 은 이 레코드를 폴더 노트 파일(`A/B/B.md`)처럼 다뤘다. pull 이 만드는
폴더 레코드는 늘 `.md` 경로라 맞고, push 의 폴더 레코드만 틀렸다.

| 경우                                                | v0.3.x · ADR-012 까지                                                                                                                        |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 폴더 페이지 아래에 Notion 에서 페이지를 만듦 (S-16) | 폴더 경로에서 폴더 이름을 떼어 한 층 위(`A/`)에 받았다                                                                                       |
| 폴더 페이지의 수정 시각이 바뀜 (S-17)               | 폴더 경로를 파일로 읽어 «빈 로컬 파일» 과 원격 본문(자식 위키링크)의 충돌로 남겼다. 그 아래에 페이지를 만들어도 Notion 이 수정 시각을 올린다 |
| 로컬에서 폴더를 지움 (S-17)                         | 되살리기가 폴더 경로에 확장자 없는 파일을 썼다                                                                                               |
| Notion 에서 폴더 페이지를 지움, deleteSync (S-17)   | 폴더 경로를 파일처럼 지웠다. 플러그인은 deleteSync 를 늘 켜고(`main.ts`), 그 어댑터는 폴더도 휴지통에 넣어 올리지 않은 노트까지 함께 갔다    |

실측(프로브, 2026-09-27): 폴더 페이지 `…de59` 아래에 페이지를 만들자 `…de59` 의 수정 시각이
14:33 → 15:01 로 올랐다.

## 결정

1. **폴더 레코드의 아래 페이지는 그 폴더에 받는다** (`resolveParentPath`). 예외는 v0.3 이 DB 폴더
   자리에 만든 폴더 페이지다 — 그 폴더는 DB 라 행만 든다. 예전 자리(한 층 위)에 받는다.
2. **폴더 레코드의 원격 수정은 본문으로 가른다** (`pullFolderRecord`). Notion markdown 에서 자식
   페이지 · 자식 DB 태그와 빈 블록을 뺀 나머지가 없으면 받을 것이 없다 — 수정 시각만 맞춰 다음
   pull 이 다시 읽지 않게 한다(`hasBodyBesidesChildren`).
3. **본문이 생긴 폴더 페이지는 폴더 노트다.** 레코드를 폴더 노트 경로(`A/B/B.md`)로 옮겨 적고
   보통 노트처럼 받는다 — ADR-012 의 이어받기를 pull 쪽에서 한다. 페이지 id · 하위 페이지가 그대로다.
   올리지 않은 로컬 폴더 노트가 있으면 그 노트의 충돌이 되고, 충돌은 push 에서 빠진다.
4. **받을 수 없으면 이유와 함께 실패한다** — 기준 시각이 이 변경 앞에 묶여 다음 pull 이 다시 본다.
   폴더의 이동을 Notion 에 아직 반영하지 않았을 때(이동 WAL), 폴더 노트가 다른 페이지일 때(S-15
   이전 push 가 만든 두 겹).
5. **폴더 노트를 둘 자리가 없으면 본문은 Notion 에만 둔다** — 수정 시각을 맞추고 경고를 남긴다.
   DB 모드(노트가 행), v0.3 이 DB 폴더 자리에 만든 폴더 페이지.
6. **폴더 레코드는 파일로 되살리지도 지우지도 않는다.** 되살리기는 안의 노트만 한다. 원격 삭제는
   폴더 레코드의 추적만 놓는다 — 안의 노트는 각자의 레코드가 지운다.

## 이유

- **push 와 같은 모델이다.** 폴더 노트가 폴더의 페이지이고(ADR-012), 폴더 페이지는 폴더다. 폴더
  레코드는 파일이 아니다.
- **잃는 것이 없다.** 원격 본문은 폴더 노트로 받거나 Notion 에 남기고, 로컬 노트는 충돌로 지키고,
  원격 삭제가 올리지 않은 노트를 지우지 않는다.
- **받지 못한 것은 이유가 남는다.** 두 겹 · 이동 대기는 실패로, 자리 없음은 경고로 보인다.

## 트레이드오프

- **새 자식은 검색 색인을 기다린다.** 부모 폴더 페이지의 수정은 바로 보여도 새 페이지는 search
  색인에 늦게 들어와, 그 pull 이 아니라 다음 pull 이 받는다(안전창 15분, F20). 부모의 변경으로 자식을
  바로 찾는 것은 `feature/fast-change-detection` 에서 다룬다.
- **본문 판정에 요청 1회가 든다.** 수정된 폴더 레코드마다 markdown 을 한 번 읽는다. 폴더 페이지는
  자식이 생길 때마다 수정되므로, 이 읽기가 없으면 매번 충돌이었다.
- 시각만 맞춘 폴더도 CLI 진행 줄에는 `~ updated` 로 보인다(요약은 `no changes`) — 받은 것이 없는
  보통 페이지와 같은 선존재 표시다. 변경 목록 API(`feature/sync-status-api`)에서 고친다.
- DB 폴더 자리의 v0.3 페이지 아래 페이지는 볼트에 옳은 자리가 없어 한 층 위에 둔다. 그 페이지의
  본문은 Notion 에만 있다 — 릴리스 노트에 찾는 법과 정리법을 적는다.
- Notion 에서 지운 폴더 페이지의 볼트 폴더는 남는다 — 안의 노트가 모두 지워지면 빈 폴더가 남는다.
