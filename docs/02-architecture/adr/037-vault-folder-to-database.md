# ADR-037: 볼트에서 만든 노트 폴더를 Notion DB 로 — 사이드카를 써 두는 준비 단계

> 상태: 승인
> 결정일: 2026-10-23
> 이어 받는 것: [ADR-036](036-push-creates-databases.md) — 사이드카가 있는 폴더는 push 가 DB 로 만든다

## 맥락

#75 「인라인 DB ↔ Bases」 의 Notion → 볼트 → Notion 은 ADR-036 으로 닫혔다. pull 이 쓴 사이드카가 있으면 push 가
DB · 행 · 보기를 다시 만든다.

남은 빈틈은 **사용자가 볼트에서 만든 폴더**다. frontmatter 를 맞춘 노트 묶음에 Obsidian Bases(`.base`) 로 표를 그려
쓰는 볼트가 흔하다. 이 폴더에는 사이드카가 없으므로 push 는 폴더를 «폴더 페이지», 노트를 «일반 페이지» 로 올리고
속성은 본문의 YAML 이 된다. Notion 에서 표 · 정렬 · 필터를 쓸 수 없다.

## 선택지

| 안                                                          | 장점                                                                            | 단점                                                                                                                     |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| A. push 가 `.base` 가 있는 폴더를 알아서 DB 로              | 손이 안 간다                                                                    | 지금 페이지로 올리던 폴더의 동작이 말없이 바뀐다. 추정한 타입을 고칠 틈이 없다 — DB 를 만든 뒤 타입을 바꾸면 값이 깨진다 |
| **B. 준비 명령이 사이드카를 써 두고, push 는 ADR-036 대로** | 사용자가 고른 폴더만. 사이드카를 고친 뒤 push 할 수 있다. Notion 에 쓰지 않는다 | 한 단계가 더 있다                                                                                                        |
| C. 준비 명령이 Notion 에 DB 를 바로 만든다                  | 한 번에 끝난다                                                                  | 행 · 부모 페이지 · 상태 기록을 push 와 따로 짜야 한다 — 같은 일을 두 벌로 하게 된다                                      |

## 결정

**B.** `prepareFolderDatabase(folder)` (CLI `prepare-db <folder>` · 플러그인 폴더 메뉴 「Notion DB 로 올릴 준비」) 가
`<폴더>/<DB 제목>.notion.json` 을 쓴다. 다음 push 는 이 폴더를 ADR-036 의 «새 DB 폴더» 로 보고 DB 를 만든다.

1. **행** 은 폴더 **바로 아래** 노트다. 하위 폴더는 행이 아니다 — pull 이 쓰는 DB 폴더와 같은 모양이다.
2. **속성 타입** 의 근거는 차례대로 둘이다.
   - Obsidian 이 정해 둔 타입(`<설정 폴더>/types.json`): number · checkbox · date/datetime → date · multitext/tags → multi_select.
     aliases 타입은 속성으로 만들지 않는다.
   - 없으면 노트들의 값: 모두 불리언 → checkbox, 모두 수 → number, 모두 날짜 → date, 목록 → multi_select,
     모두 URL · 메일 → url · email. 되풀이되는 짧은 값(가짓수 25 이하 · 50자 이하 · 쉼표 없음) → select.
     그 밖은 rich_text. 쉼표가 든 값은 select/multi_select 옵션이 될 수 없어 rich_text 로 둔다.
   - 무엇을 근거로 정했는지 보고에 싣는다 — 사용자는 사이드카를 고친 뒤 push 할 수 있다.
3. **속성으로 만들지 않는 키:** title · aliases · cssclasses · icon · cover(Obsidian · 이 도구가 다른 뜻으로 쓴다),
   기간의 끝 키 `X_end`(날짜 속성 X 의 일부), 제목 속성(`Name`)과 같은 이름.
4. **보기** 는 폴더의 `.base` 가 **하나** 일 때 옮긴다. 그 파일 이름이 DB 제목이다.
   - table → table · cards → gallery · list → list. 그 밖(map 등)은 옮기지 않는다.
   - 열(`order`)과 정렬(`sort`)을 속성 id 로 옮긴다. `file.name` 은 제목 속성이다.
   - Bases 식으로 쓴 필터 · `formula.*` 열은 Notion 필터 · 속성으로 바꿀 수 없어 옮기지 않고 보고한다.
5. **거절:** 볼트 맨 위, 바로 아래 노트가 없는 폴더, 이미 사이드카가 있는 폴더, **노트 하나라도 이미 Notion 페이지로
   올라간 폴더.** 마지막은 페이지를 DB 행으로 옮길 수 없어서다 — 지금 API 에는 페이지를 data source 아래로 옮기는
   길이 없다(확인하지 못했다. 있다면 v0.7 이후 후보). 그 폴더는 지금처럼 페이지로 남는다.
6. 🔴 사이드카의 `databaseId` 는 지어낸 UUID 다. ADR-036 결정 3 대로 push 는 그 id 에 쓰지 않고 언제나 새 DB 를 만든다.
7. 사용자가 만든 `.base` 는 pull 이 덮어쓰거나 지우지 않는다(`# Auto-generated by Im-Nobsidian` 머리말로 가린다).
   Notion 보기는 그 `.base` 로 내려오지 않는다 — 이 자리를 알리는 로그는 경고가 아니라 info 다(늘 이 상태라서).

## 실측 (2026-10-23, 탐침 루트 `__fdb_bases__`)

볼트 A: `서재.md`(`![[Books/Books.base]]` 임베드) + `Books/` 노트 3개 + `Books.base`(표 「전체」 · 카드 「표지」) + `types.json`.

| 단계                       | 결과                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| prepare-db Books           | 사이드카 · 행 3 · 속성 8(select 2 · number · checkbox · multi_select · rich_text · date · url) · 보기 2 |
| 다시 prepare-db            | 거절(이미 사이드카)                                                                                     |
| A push                     | DB 1 · 페이지 4(행 3 + 서재) · 실패 0 · 다시 push 0                                                     |
| 새 볼트 B pull · 다시 pull | 4 생성 · 0. 값 · 보기 이름 · 열 · 정렬이 같다                                                           |
| A 에서 값 바꾸기 · 새 노트 | push 갱신 1 · 생성 1(새 옵션 「대하소설」 은 Notion 이 더함) → B pull 갱신 1 · 생성 1                   |

B 에서 DB 폴더는 `databases/Books/` 로 받는다(부모가 루트 페이지인 DB 의 기존 자리). `서재.md` 의
`![[Books/Books.base]]` 는 Obsidian 이 경로 끝맞춤으로 `databases/Books/Books.base` 를 찾는다(격리 Obsidian 1.12.4 실측).

## 트레이드오프

- 준비 명령이 한 단계 더 있다. 대신 동작이 바뀌는 폴더는 사용자가 고른 것뿐이다.
- 값으로 정한 타입은 틀릴 수 있다(예: 수만 적은 글 칸). 보고와 고칠 수 있는 사이드카로 막는다.
- 이미 올린 폴더는 DB 로 바꾸지 않는다.
