# ADR-022: 목록 안 코드 블록은 받을 때 코드 줄을 펜스 깊이로 맞추고 목록 줄처럼 4칸으로 편다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

Notion 의 목록 항목(글머리표 · 번호 · 할 일)은 자식으로 코드 블록을 가질 수 있다. Markdown API 는 이 코드
블록을 콜아웃 · 토글 안처럼 **경계 펜스만 탭으로 들여쓰고 코드 줄은 열 0 에** 둔 채 내보낸다(비대칭
들여쓰기). 실측(2026-09-28, 프로브 페이지 19장 · 실데이터 E2E s24a 의 export):

````text
- 설치
	```bash
npm install s24a
	```
- 설정
	- 중첩
		```json
{ "run": "s24a" }
		```
````

콜아웃 · 토글의 코드는 `dedentContainerBody` 가 맞췄지만 목록 항목은 빠졌다. 그대로 쓰면 Obsidian
(CommonMark)은 항목 내용 폭보다 얕은 열 0 의 코드 줄에서 목록과 코드 블록을 끝낸다 — 목록 안에는 빈
코드 블록이, 목록 밖에는 코드가 문단으로 보인다. 실볼트 12파일 · 37곳이 이 모양이었다(S-24).
BlockSpacer 는 목록 자식 펜스를 새 블록으로 떼어 앞뒤에 빈 줄을 넣어, 목록 전체를 느슨한 목록으로
만들었다. 렌더 감사 ⑤ 는 목록 자식 펜스를 결함으로 세고, 목록 밖으로 샌 코드는 잡지 못했다.

Notion 이 올린 markdown 을 어떻게 읽는지(프로브, 코드 블록이 붙은 부모를 블록 API 로 확인):

| 보낸 모양                                           | Notion 구조                              |
| --------------------------------------------------- | ---------------------------------------- |
| 목록 줄 · 펜스 · 코드 줄 모두 탭(대칭)              | 항목의 자식 코드 블록                    |
| 목록 줄 4칸 · 펜스 · 코드 줄 4칸(붙거나 빈 줄 사이) | 항목의 자식 코드 블록                    |
| 2칸 들여쓰기                                        | 항목의 자식 코드 블록                    |
| Notion 이 내보낸 비대칭 모양                        | 항목의 자식 코드 블록                    |
| 목록 줄은 4칸 · 펜스와 코드 줄은 탭(두 단계 중첩)   | **한 단계 위 항목에** 붙는다             |
| 코드 속에 백틱 세 개 줄이 있는 코드(어떤 펜스로든)  | 그 줄에서 블록이 갈린다(S-22, 따로 다룸) |

## 결정

1. **변환기가 코드 줄을 펜스 깊이로 맞춘다**(`alignNestedCodeBodies`, `container-indent`). 부모가 목록
   항목인 코드 블록만 — 들여쓰기가 더 얕은 가장 가까운 앞 줄(빈 줄 · 다른 코드 블록 안쪽 제외)이 목록
   항목이면 그 항목의 자식이다. 코드 줄마다 여는 펜스와 같은 탭을 입힌다. CommonMark 는 그 폭만큼 떼고
   읽으므로 코드는 그대로다(코드 속 탭도 그대로).
   - 코드 속에 펜스 모양 줄이 있으면 경계 펜스를 그보다 길게 넓힌다 — 들여쓰기가 같아지면 닫는 줄과
     가를 근거가 사라진다.
   - 닫는 펜스의 들여쓰기가 여는 펜스와 다르면 · 공백으로 들여썼으면(NFM 이 아니다) · 문단 · 인용의
     자식이면 둔다.
   - 원시 export 에 한 번만 쓴다(`clampCalloutIndent` 앞) — 멱등이 아니다.
2. **BlockSpacer 가 목록 자식 코드 블록을 항목에 붙이고 구조 탭을 4칸으로 편다.** 목록 줄의 탭을
   4칸으로 펴는 D4 와 같은 폭이다. 코드 줄까지 펜스 깊이로 맞춰진 블록의 구조 탭만 펴고, 코드 속 탭 ·
   닫히지 않은 블록 · 맞춰지지 않은 블록은 둔다.
3. **push 는 바꾸지 않는다.** 받은 4칸 모양을 그대로 보내면 Notion 이 같은 구조로 읽는다(위 표).
4. **렌더 감사가 이 결함을 잡는다.** ⑤(4칸 펜스)는 목록 항목의 자식(항목 내용 폭에서 3칸 안)을 정상으로
   보도록 문맥 규칙으로 옮기고, ⑱ 「목록 안 코드가 목록 밖으로 샘」 — 목록 자식 펜스의 코드 줄이 항목
   내용 폭보다 얕음 — 을 더했다. 렌더 게이트 코퍼스에 목록 안 코드(09)를 더했다.

## 선택지 — 받은 노트의 들여쓰기

| 선택지                            | 판단                                                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 탭 그대로(펜스 · 코드 줄 모두 탭) | Obsidian 에서는 맞게 보인다. 하지만 목록 줄은 D4 로 4칸이 되어 한 목록에 공백과 탭이 섞이고, 두 단계에서 Notion 이 코드를 다른 항목에 붙인다 |
| 2칸                               | 번호 항목(`1. `)은 내용 폭이 3칸이라 모자란다. 목록 줄(4칸)과도 폭이 다르다                                                                  |
| **4칸(목록 줄과 같은 폭)**        | 한 목록이 한 가지 들여쓰기다. Notion 이 붙은 모양 · 빈 줄 사이 모양 모두 같은 구조로 읽는다 — **고른 것**                                    |
| 코드 블록을 목록 밖으로 꺼내기    | Notion 의 구조(항목의 자식)를 잃는다. 다시 올리면 항목에서 떨어진다                                                                          |

## 트레이드오프

- **로컬에서 2칸으로 쓴 목록 코드는 원격 편집 뒤 처음 받을 때 4칸 · 붙은 모양이 된다.** 공백만 다르다 —
  2칸으로 쓴 중첩 목록 줄이 4칸이 되는 D4 와 같다.
- **문단 · 인용의 자식 코드는 그대로다.** Obsidian 에는 문단 아래로 들여쓸 자리가 없다(따로 다룬다).
- **코드 속에 백틱 세 개 줄이 있는 목록 코드**는 받을 때는 넓힌 펜스로 제대로 보이지만, 노트를 고쳐
  올리면 Notion 이 그 줄에서 블록을 가른다(S-22).
- `RENDER_LINE_RULES`(공개 상수)에서 ⑤ 가 빠진다 — 한 줄만 보고는 판정할 수 없게 되었다.
  `lintRenderedMarkdown` 은 ⑤ 를 그대로 낸다(목록 자식은 빼고).
