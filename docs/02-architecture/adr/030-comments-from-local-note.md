# ADR-030: 주석 — push 는 Obsidian 이 그리는 모양대로 지우고, pull 은 받기 직전의 로컬 노트에서 되살린다

> 상태: 승인
> 결정일: 2026-10-04

## 맥락

Obsidian 주석(`%%…%%`)과 HTML 주석(`<!--…-->`)은 Notion 에 올리지 않는 로컬 글이다(F26). 예전에는 push 가 주석
글만 지우고 보존 마커에 앵커(같은 줄의 앞 글 · 앞 줄)를 적어 두었다. pull 은 앵커 줄 다음 줄에 주석을 따로
끼웠다. 그래서 주석이 왕복에서 자리를 잃었다(S-29). 파이프라인 하니스로 잰 주석 배치 10가지 중 7가지가 달라졌다.

- 문단 사이 주석은 앞 빈 줄을 잃었다. 문장 속 주석은 줄 밖으로 빠졌다.
- 이웃한 주석 둘이면, 둘째의 앵커가 첫째 주석을 품고 있어 찾지 못했다.
- 콜아웃 속 주석 줄은 글만 지워 `>` 만 남은 줄이 Notion 에서 콜아웃 문단을 갈랐다. 받으면 `>` 없이 되살려
  콜아웃을 끊었다.
- 목록 항목 속 주석은 목록을 둘로 갈랐다.
- 인라인 코드 속 주석 표기(`` `<!-- 이렇게 -->` ``)까지 지웠다(실볼트 Blog.md 3곳).

앵커는 «어느 줄 다음» 만 담는다. 줄 속 위치 · 콜아웃 깊이 · 목록 구조 · 빈 줄은 담지 못한다. 그것을 모두 담은
글은 로컬 노트 자체다.

## 결정

1. **push 는 Obsidian 이 그리는 모양대로 지운다**(`cutComments` · `CommentStripper`). 주석이 없던 노트와 같은
   글을 보낸다.
   - 주석은 코드 펜스 · 인라인 코드 · 브랜드 마커 밖에서 찾는다(`findComments`). 인라인 코드와 겹치면 먼저
     시작한 쪽이 이긴다 — CommonMark 에서 코드 스팬과 HTML 은 순위가 같다.
   - 주석만 있는 줄은 줄째 지운다(줄머리의 `>` · 들여쓰기 포함). 앞뒤가 모두 빈 줄이면 빈 줄 하나도 함께
     지운다.
   - 줄 속 주석은 주석과 옆 공백 하나를 지운다.
   - 보존 마커는 예전처럼 남긴다 — 로컬 노트가 없을 때 쓴다(3).
2. **pull 은 받기 직전의 로컬 노트에서 되살린다**(`restoreComments` · `CommentRestorer`, order 120 — 간격 정규화
   `BlockSpacer` 뒤). 로컬 노트는 S-20 의 코드 펜스 표기와 같은 길(`localContent`)로 온다.
   - 받은 글이 로컬 노트에서 주석을 지운 글과 같으면 로컬 노트 그대로다.
   - 다르면 두 글의 줄을 맞춘다(`alignNoteLines`).
     1. 글이 있는 같은 줄끼리. 빈 줄은 어디에나 있어, 함께 맞추면 주석이 엉뚱한 문단으로 간다.
     2. 그 사이에서 비슷한 줄(글자 쌍 유사도 0.5 이상)을 Notion 에서 고친 줄로.
     3. 나머지 빈 줄.
   - 주석마다 받은 글의 자리를 정한다.
     - 이웃이 로컬과 같은 자리에는 지운 글을 그대로 끼운다.
     - 고친 줄 속 주석은 글자 단위로 맞춰 같은 글 뒤에 둔다(`mapOffset`).
     - 이웃이 사라진 주석은 가까운 자리에 주석 줄로 둔다. 인용 깊이는 앞 줄에 맞춘다. 코드 블록 안에는
       두지 않는다.
     - 본문이 비면(원격에서 모두 지움 · 주석뿐인 본문) frontmatter 뒤에 둔다.
   - **push 가 보낼 글이 받은 글과 같은 배치**를 고른다(`sentView`). 그래서 되살린 노트를 다시 올려도
     Notion 의 글은 그대로다.
     1. 모든 자리에 지운 글을 그대로 끼운다.
     2. 안 맞으면 이웃이 로컬과 다른 자리(고친 줄 · 사라진 이웃 · 코드 안)를 모두 이웃에 맞춘 주석 줄로
        바꾼다. 맞으면 그 자리를 하나씩 지운 글 그대로 되돌려 보고, 보낼 글이 같으면 되돌린 채 둔다(50자리까지).
        한 자리가 어긋났다고 고친 문장 속 주석까지 줄 밖으로 빼지 않는다 — Notion 은 콜아웃 속 빈 `>` 줄을
        내보내지 않아, 콜아웃 속 문단 사이의 주석 하나만으로 1 이 어긋난다(실측).
     3. 그래도 안 맞으면 본문 끝에, 그다음은 본문 머리에 주석 줄로 모은다. 본문 머리는 코드 · frontmatter
        밖이라 주석을 버리지 않는다.
   - push 의 눈은 frontmatter 와, 주석을 지우고 빈 줄을 줄인 본문이다. 본문 끝의 공백 · 머리의 빈 줄은 Notion 에
     남지 않아 견주지 않는다. 머리 줄의 들여쓰기는 견준다 — push 는 본문을 다듬은 뒤에 주석을 지워, 본문 머리
     주석 뒤 줄의 들여쓰기를 그대로 보낸다. 깨진 YAML 은 frontmatter 째 본문 글로 가므로 따로 가른다.
3. **보존 마커는 로컬 노트가 없을 때만 쓴다.** `PreserveMarkerInjector` 는 `localContent` 가 있으면 comment
   마커를 끼우지 않는다. 처음 받는 노트 · 로컬 노트를 읽지 못한 pull 은 예전처럼 앵커 줄 다음에 끼운다.

## 선택지

| 선택지                                   | 판단                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 앵커를 넓힘(뒤 글 · 줄 번호 · 깊이)      | 원격 편집이 앵커 글을 지우면 같은 문제다. 목록 · 콜아웃 구조와 빈 줄까지 적으면 노트를 또 적는 꼴 |
| 주석을 Notion 에 숨겨 올림(빈 색 · 토글) | F26 — 사적 메모가 Notion 에 남고 공유 페이지에서 보인다                                           |
| 주석을 노트별로 상태 DB 에 저장          | 로컬 노트에 이미 있다 — 두 벌이 갈린다                                                            |
| **받기 직전의 로컬 노트에서 되살림**     | 로컬 노트가 주석의 정본이다. 코드 펜스 표기(S-20) · 코드 속 빈 줄(S-27)과 같은 길 — **고른 것**   |

## 남은 한계

- 로컬 노트가 없으면(새 기기에서 처음 받기 · 읽기 실패) 보존 마커로 앵커 줄 다음에 끼운다 — 예전 모양이다.
- Notion 에서 주석의 이웃을 크게 고치면 주석은 가까운 자리로 간다. 빈 줄이 둘 남거나 주석 줄이 이웃 줄에 붙을
  수 있다. push 가 보낼 글과 주석 수는 그대로다(무작위 시험).
- 모든 배치가 push 가 보낼 글을 바꾸면 본문 머리에 모은 글을 쓴다. 무작위 시험에서는 한 번도 없었다.
- CRLF 노트는 받으면 LF 로 쓰인다. 닫히지 않은 `%%` · `<!--` 는 주석이 아니다(D-COMMENT-PAIR). 둘 다 예전과 같다.
- Notion 은 콜아웃 속 줄을 줄마다 문단 블록으로 두고 압축형으로 내보낸다(실측). 원격 편집 뒤에 받으면 콜아웃 속
  문단 경계(`>` 빈 줄)를 잃는다. 주석과 무관한 간격 복원의 한계이고(주석이 없는 노트도 같다), 주석은 콜아웃
  안에 남는다(`comment-roundtrip.test.ts`).
- 주석 속 하이라이트 · 밑줄은 서식 보존(`InlineAnnotationPreserver`, order 5)이 주석 제거(order 11)보다 먼저 돌아
  Notion 으로 샌다 — 다음 브랜치에서 고친다.

## 트레이드오프

- **pull 이 로컬 노트를 한 번 더 훑는다.** 주석이 없는 노트는 찾기만 하고 끝난다. 주석이 있는 노트도 받은 글이
  그대로면 줄 맞춤을 하지 않는다. 줄 맞춤은 `lineDiff` 와 같은 diff 상한을 쓴다 — 넘게 바뀐 두 글은 줄을
  맞추지 않고 주석을 본문 끝에 모은다.
- **지우는 모양이 바뀌어 한 번은 다시 올린다.** 주석 줄 · `>` 만 남던 줄 · 주석 자리 빈 줄이 Notion 에서
  사라진다. 주석이 있는 노트는 이 버전의 첫 push 에서 본문이 한 번 바뀐다.
- 고친 줄을 찾는 비슷한 줄 비교는 구간마다 옛 줄 수 × 새 줄 수 400 까지만 한다. 넘으면 비율로 옮긴다.
