# ADR-033: 본문 push 는 바뀌지 않은 미디어를 다시 올리지 않는다

> 상태: 승인
> 결정일: 2026-10-12
> 고친 결정: ADR-020 의 한계 「본문 push 는 여전히 미디어를 모두 다시 올린다」

## 맥락

본문 push 는 노트의 임베드를 자리표시자(`> 📎 이름 %% im-nobsidian:local-image:… %%`)로 바꿔 본문을 통째로
교체한다(`replace_content`). 교체가 끝나면 자리표시자를 하나씩 올려 이미지 · 파일 블록으로 바꾼다(R1).

그래서 글 한 줄만 고쳐도 그 페이지의 미디어를 모두 다시 올렸다.

- 미디어마다 요청이 다섯이다 — 업로드 만들기 · 보내기 · 블록 붙이기 · 자리표시자 지우기 · 블록 조회.
  미디어 4개짜리 노트의 글 한 줄 push 가 요청 24번이었다(2026-10-12 실측).
- Notion 의 블록 id · 파일이 매번 바뀐다. 그 블록에 단 댓글 · 링크가 끊긴다.
- Notion 에서 올린 캡션 없는 파일은 받을 때 올라간 이름을 별칭으로 적는다. 그 노트를 push 하면 다시 올리면서
  별칭이 캡션으로 붙고, 파일 이름은 볼트에 저장한 이름(`이름-해시.ext`)이 된다.

ADR-020 은 올린 미디어를 페이지마다 적어 두었다(파일 id · 임베드 대상 · 볼트 파일). 그 기록으로 「이 파일은
이미 Notion 에 있다」 는 알 수 있었지만, 교체가 블록을 지우므로 쓸 데가 없었다.

## 실측 — 받은 미디어 URL 을 그대로 실어 교체하면

탐침 페이지 셋(`__p5_media_a/b/c`, 2026-10-12)에서 markdown API 로 받은 본문을 고쳐 다시 보냈다.

| 보낸 것                                      | 블록 id | 파일 id | 캡션        |
| -------------------------------------------- | ------- | ------- | ----------- |
| 받은 본문 그대로(글만 고침)                  | 같음    | 같음    | 같음        |
| 서명(쿼리)을 뗀 URL                          | 같음    | 같음    | 같음        |
| 미디어 줄을 콜아웃 안으로 옮김               | 같음    | 같음    | 같음        |
| 캡션 글을 바꿈 · 비움 · 빈 캡션에 글을 붙임  | 같음    | 같음    | 보낸 글로   |
| 파일 블록의 `name`(Notion 이 보여 주는 이름) | —       | —       | 바뀌지 않음 |

- 이미지는 `![캡션](서명 URL)`, 파일은 `<file src="서명 URL">캡션</file>` 로 온다.
- URL 의 경로 끝 둘이 파일 id 와 올라간 이름이다(`notionFileIdOf`).

## 결정

본문을 보내기 «전» 에 자리표시자 가운데 다시 올릴 까닭이 없는 것을 Notion 에 이미 있는 그 파일로 바꾼다
(`ImageHandler.keepUploadedMedia`).

1. 그 페이지의 미디어 기록에 지문(`fileHash`, 전체 sha256)이 있는 것이 하나도 없으면 아무것도 하지 않는다.
   Notion 에 묻지도 않는다.
2. 받은 본문을 한 번 읽는다(`GET pages/:id/markdown`). 미디어마다 파일 id 로 기록을 찾아, 임베드 경로별로 본문
   차례대로 줄을 세운다.
3. 코드 밖 자리표시자 줄마다 같은 경로의 첫 미디어를 꺼내 다섯을 본다.
   - 종류가 같다(이미지 ↔ `![`, 파일 ↔ `<file`)
   - 캡션에 markdown 서식으로 읽힐 글자가 없다(`[]()<>&*_` 와 백틱 · `~$=#|\` · 줄바꿈)
   - URL 이 `https://` 이고 괄호 · 따옴표 · 꺾쇠 · 공백이 없다(서명은 뗀다)
   - 볼트에서 찾은 파일이 기록한 그 경로다
   - 그 파일의 sha256 이 기록한 지문과 같다
4. 다섯이 맞으면 그 줄을 들여쓰기를 지킨 채 미디어 한 줄로 바꾼다. 하나라도 어긋나면 자리표시자를 두어 예전처럼
   올린다.
5. 본문을 보낸 뒤, 남은 자리표시자만 블록으로 바꾼다. 그대로 둔 미디어는 새로 올린 것과 함께 기록에 다시 적는다
   (임베드 대상은 노트의 지금 것으로).

캡션은 노트의 설명이다. 다만 Notion 에 캡션이 없고 노트의 별칭이 올라간 이름이면 캡션을 비운 채 둔다 — 받을 때
그 이름을 별칭으로 적었을 뿐이다.

pull 이 받은 미디어도 기록한다(`rememberReceivedMedia` — 적어 둔 것에 더하고, 같은 파일 id 면 바꾼다). 그래야
받은 노트를 고쳐 push 할 때 Notion 의 원래 블록이 남는다. 다시 받을 때 캡션 없는 파일의 별칭(올라간 이름)을
지우지 않는다(`embedTargetFromCaption`).

## 선택지

| 선택지                                 | 판단                                                                         |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| 본문 push 를 블록 단위 diff 로 바꾼다  | 버림 — 이 도구의 push 는 markdown 교체 하나에 기대고 있다(ADR-008 · 009)     |
| `file_upload` id 를 다시 쓴다          | 불가 — 붙이고 나면 쓸 수 없다(1회용)                                         |
| 지문 없이 경로만 같으면 둔다           | 버림 — 같은 이름에 다른 그림을 넣은 편집을 잃는다                            |
| 받은 미디어 URL 을 그대로 싣는다(채택) | 교체가 블록을 둔다(실측). 읽기 한 번이 미디어마다 요청 다섯을 대신한다       |
| 캡션도 서식째 싣는다                   | 버림 — 올릴 때는 캡션을 글자 그대로 싣는다. markdown 으로 실으면 서식이 된다 |

## 남은 한계

- 블록 방식 push(`preferMarkdownApi: false`)는 블록을 모두 지우고 붙이므로 예전처럼 모두 다시 올린다.
- 지문 없이 적은 옛 기록(이 결정 이전)의 미디어는 한 번 더 올리고, 그때 지문을 적는다.
- 내부 참조(`file://…attachment:…`)로 온 파일은 그대로 실을 수 없어 다시 올린다. 2026-10-12 실측에서는 통합이
  올린 파일이 모두 서명 URL 로 왔다.
- 캡션에 서식 글자가 있는 미디어는 다시 올린다.
- 본문을 읽지 못하면 사유를 경고로 남기고 예전처럼 올린다 — 잃는 것은 없다.
- 본문을 읽고 보내는 사이에 Notion 에서 그 미디어를 지우면, 보낸 줄이 가리키는 파일로 Notion 이 무엇을 하는지는
  재지 않았다. 이 창은 drift 확인 바로 뒤 몇백 ms 다.
