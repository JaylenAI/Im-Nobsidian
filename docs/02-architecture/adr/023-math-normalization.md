# ADR-023: 인라인 수식은 노트 그대로 보내고 블록 수식은 줄머리째 제 줄에 세운다

> 상태: 승인
> 결정일: 2026-09-28

## 맥락

push 전처리 `MathNormalizer` 는 본문 전체에 정규식 둘을 걸었다. 인라인 `$…$` 는 안쪽 공백을 자르고, 블록
`$$…$$` 는 `$$` · 식 · `$$` 세 줄로 다시 썼다. 코드도 가리지 않았다. 실볼트(노트 1271장, `$` 가 든 노트 31장)에서
9장의 push 본문을 바꿨고 모두 손상이었다(S-21).

- 수식이 아닌 달러가 수식이 됐다 — `$ x $` 는 `$x$` 로, `$5 and $10` 은 `$5 and$10`(Notion 수식 「5 and」)으로,
  「집 $5/월」 은 「집$5/월」 로 바뀌었다.
- 코드가 바뀌었다 — 인라인 코드 `$ # https://…` 의 공백이 빠지고, 코드 속 템플릿 리터럴 `${…}` 앞 공백이 빠졌다. 셸의
  `$$`(PID)는 코드 밖 수식의 `$$` 와 짝지어져 그 사이 본문까지 옮겼다.
- 콜아웃 안 블록 수식의 닫는 `$$` 를 줄머리(`> `) 없이 세워 콜아웃 밖으로 꺼냈다. Notion 은 그 `$$` 부터 뒤 문단을
  수식으로 삼킨다(프로브). Notion 에서 받은 「첫 자식이 수식인 콜아웃」 노트 4장이 이 모양이다.

Notion 이 올린 markdown 을 읽는 방식(프로브 `__qa_probe_s21_math` · `__qa_probe_s21b_*`, 블록 API 로 확인):

| 보낸 모양                                                             | Notion                               |
| --------------------------------------------------------------------- | ------------------------------------ |
| `$E = mc^2$`                                                          | 인라인 수식                          |
| `$ x $` · `$ x$` · `$x $` · `$5 and $10` · `$1,000 ~ $2,000` · `$x$1` | 글                                   |
| 글 사이 `$$x$$`                                                       | 인라인 수식                          |
| `$$` · 식 · `$$` 저마다 제 줄(식 앞뒤 빈 줄 포함)                     | 수식 블록(식 앞뒤 공백은 잘라 저장)  |
| 한 줄 `$$ x^2 $$` · 식이 `$$` 줄에 붙은 `$$ a` … `b $$`               | 빈 인라인 수식과 글                  |
| 콜아웃(`<callout>`) 안 탭 · 목록 항목 아래 4칸의 `$$` · 식 · `$$`     | 그 콜아웃 · 항목의 자식 수식 블록    |
| 인용(`>`) 안 `$$` · 식 · `$$`                                         | 인용 블록 셋(빈 수식 · 글 · 빈 수식) |

Obsidian 1.13.7 의 토크나이저(앱 번들)도 인라인 수식을 같은 규칙으로 가린다 — 여는 `$` 뒤 · 닫는 `$` 앞이
공백 · 탭이거나 닫는 `$` 뒤가 숫자면 수식이 아니다. `$$` 는 안쪽 공백을 허용한다.

Notion 은 수식을 ``$`식`$`` 로, 글의 `$` · `~` 를 `\$` · `\~` 로 내보내고 코드는 그대로 둔다. 목록 자식 수식은
`$$` · 식 줄 모두 탭으로 내보낸다. pull 은 이것을 맞게 되돌렸다 — 손상은 push 쪽뿐이었다.

## 결정

1. **인라인 수식은 건드리지 않는다.** 노트 그대로 보내면 Obsidian 과 Notion 이 같은 곳을 수식으로 본다.
2. **코드 펜스 · 인라인 코드 안은 보지 않는다**(`mapOutsideCode`).
3. **블록 수식은 두 `$$` 가 줄의 처음(인용 표시 · 들여쓰기 뒤)과 끝일 때만 `$$` · 식 · `$$` 줄로 편다.** 새 줄에도
   여는 줄의 줄머리를 단다. 식 앞뒤 공백 · 빈 줄은 자른다 — Notion 도 자른다.
   - 글 사이의 `$$x$$` 는 둔다. Notion 이 인라인 수식으로 읽는데, 가르면 빈 수식과 글이 된다.
   - 식의 줄이 여는 줄의 줄머리를 달지 않았으면(짝이 인용 · 목록 밖으로 넘어감) · 식이 비었으면 둔다.
4. **받을 때 목록 자식 수식을 항목에 붙이고 구조 탭을 4칸으로 편다**(BlockSpacer). ADR-022 의 목록 자식 코드
   블록과 같다. 예전에는 떼어 앞에 빈 줄을 끼워, 목록이 느슨한 목록이 되고 탭이 남았다.

## 선택지 — 인라인 수식

| 선택지                                            | 판단                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------- |
| 안쪽 공백을 잘라 보냄(예전)                       | `$ x $` · 통화가 Notion 에서 수식이 된다. Obsidian 에서는 글이다 |
| Obsidian 규칙으로 가려 수식이 아닌 `$` 를 `\$` 로 | 결과가 같다 — Notion 이 이미 같은 규칙으로 읽어 코드만 늘어난다  |
| **노트 그대로 보냄**                              | 두 쪽이 같은 규칙이다 — **고른 것**                              |

## 선택지 — 콜아웃 · 목록 안 블록 수식

| 선택지                                      | 판단                                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------- |
| 최상위 블록 수식만 정규화                   | 목록 자식 한 줄 수식(`    $$ x $$`)이 빈 수식이 된다                                |
| **줄머리를 떼고 편 뒤 새 줄마다 다시 단다** | 콜아웃 · 목록 · 중첩 인용이 한 규칙이다 — **고른 것**                               |
| 콜아웃 변환 뒤에 정규화                     | 경로마다 정규화를 따로 둬야 한다 — 블록 경로(martian)는 콜아웃 변환을 거치지 않는다 |

## 트레이드오프

- **인용(`>`) 안 블록 수식은 Notion 에서 인용 블록 셋으로 갈린다.** markdown 으로는 인용 안 수식 블록을 만들 수 없다
  (프로브). 실볼트 0곳 — 수식이 든 인용 4곳은 모두 콜아웃이다.
- **글 사이 `$$x$$` 는 Notion 에서 인라인 수식이다.** 받으면 `$x$` 가 된다 — Obsidian 에서는 디스플레이 수식이었다.
- 목록 표시 줄에서 여는 수식(`- $$ x $$`)은 둔다 — Notion 이 어떻게 읽는지 재지 않았다.
- 블록 경로(`preferMarkdownApi: false`)의 martian 은 여전히 `$ x $` · 통화를 수식으로 읽는다.
- 인용 안 코드 펜스는 코드 가드가 보지 않는다(`openCodeFence`, S-23) — 콜아웃 안 코드 속 한 줄 `$$ x $$` 는 수식처럼
  세워진다.
- 짝이 맞지 않는 `$$` 는 문단을 건너 뒤의 `$$` 와 짝지어진다. Obsidian 이 같은 곳을 짝짓는지는 재지 않았다.
