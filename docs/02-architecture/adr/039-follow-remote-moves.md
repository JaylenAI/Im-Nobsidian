# ADR-039: Notion 에서 옮긴 페이지를 볼트에서도 옮긴다

> 상태: 승인
> 결정일: 2026-10-25

## 맥락

볼트에서 옮긴 노트는 push 가 Notion 에 옮겨 반영한다(ADR-011). 반대 방향은 없었다 — Notion 에서 페이지를 다른 부모 아래로
옮겨도 볼트의 노트는 옛 폴더에 남았다.

- `pages.move` 는 페이지의 `last_edited_time` 을 바꾸지 않는다(2026-09-27 · 10-25 실측). 증분 감지는 수정 시각만 보므로
  옮긴 것이 변경으로 보이지 않는다. 전체 대조도 「바뀐 것 없음」 이었다
- pull 은 받은 페이지의 레코드 경로를 바꾸지 않는다 — 본문이 바뀌어 받아도 옛 자리에 쓴다
- 그대로 두면 볼트와 Notion 의 트리가 어긋난 채 굳는다. 다음에 볼트에서 그 노트를 옮기면 push 가 옛 부모 기준으로 판단한다

## 선택지

| 안                                              | 장점                                     | 단점                                                                                                        |
| ----------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| A. 그대로 둔다 — 한계로 문서에 적는다           | 바뀌는 것 없음                           | 트리가 조용히 어긋난다                                                                                      |
| B. 받을 때 새 경로에 다시 쓰고 옛 파일을 지운다 | 받기 경로 하나로 끝                      | 바뀌지 않은 페이지는 받지 않는다(수정 시각 그대로). 볼트에서 고친 내용 · 파일 날짜 · 플러그인 링크가 끊긴다 |
| **C. 부모를 견주어 감지하고 파일을 옮긴다**     | 내용을 건드리지 않는다. 받기와 따로 돈다 | 전체 대조에서만 확실히 본다                                                                                 |

## 결정

**C.**

1. **감지** — 전체 대조는 루트 아래 모든 페이지의 부모를 이미 푼다(`extractParentId`, 폴더 판정용). 그 부모가 상태 DB 의
   `notion_parent_id` 와 다르면 옮긴 것이다. 증분 감지는 조회 창에 든 추적 페이지만 — 부모가 페이지면 요청 없이 견준다.
   대상은 노트 · 폴더 노트 · 폴더(`file` · `folder-note` · `folder-only`). DB 행은 DB 를 옮길 API 가 없고 행의 자리는 DB
   폴더가 정한다.
2. **자리** — 새 페이지를 받을 때와 같은 규칙 하나(`childFolderOf`)로 새 부모의 폴더를 정하고, 이름은 그대로 둔다. 이름이
   그대로라 다른 노트의 `[[이름]]` 은 끊기지 않는다.
3. **옮길 단위** — 노트는 파일 하나와 옆의 자식 폴더(`X.md` · `X/`, 있으면). 폴더 노트(`X/X.md`) · 폴더로 추적하는
   페이지는 폴더를 통째로. 그 아래 레코드 · 위키링크 · 보존 마커 · 첨부 기록의 경로를 한 트랜잭션으로 옮겨 적고
   `notion_parent_id` 를 새 부모로 적는다. push 이동 WAL 은 남기지 않는다 — Notion 은 이미 그 자리다.
4. **옮기지 않는 것** — 까닭을 결과(`moveSkipped`)와 로그로 낸다. 볼트에서 그 노트를 옮기면 다음 push 가 Notion 을 맞춘다.
   - 볼트에서 옮긴 것을 아직 올리지 않았다(이동 WAL) — 볼트가 먼저다
   - 새 부모가 볼트에 없다 · 노트가 볼트에 없다 · 옮길 자리에 같은 이름이 있다 · 옮길 자리가 동기화에서 빠진다
   - 폴더 안에 DB 폴더 · `.base` · 행이 있다 — `.base` 보기의 `file.inFolder("…")` 가 폴더 경로를 품는다
   - 폴더 안에 다른 연결 폴더가 있다(ADR-038)
5. 노트와 자식 폴더 중 하나를 옮기지 못하면 옮긴 것을 되돌린다 — 상태 DB 는 그때 아직 옛 경로다.
6. dry-run 은 옮길 것만 낸다. 경로를 좁힌 pull(`-p`)은 그 범위의 레코드만 옮긴다. 뺀 노트(이슈 #8)는 보지 않는다.
7. CLI 는 `from → to (moved)` 줄과 `moved` 수(JSON), 플러그인은 알림의 「이동 N」 으로 알린다.

## 트레이드오프

- 옮기기만 하고 고치지 않은 페이지는 **전체 대조**(한 시간에 한 번 · `pull --force`)에서 따라간다. 그 사이의 증분 pull 은
  옛 자리를 둔다.
- Notion 에서 제목을 바꾼 것은 여전히 파일 이름을 바꾸지 않는다(frontmatter `title:` 로 받는다) — 별도 결정.
- DB 를 품은 폴더는 따라가지 않는다. Obsidian 에서 옮기면 push 가 Notion 을 맞추고 `.base` 를 다시 쓴다.
