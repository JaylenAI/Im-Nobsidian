# ADR-007: 동기화 충실도 회복 — 전진 수정 vs v0.1.12 롤백

## 상태

승인 (2026-06-02)

## 컨텍스트

`/goal` 양방향 동기화 충실도 미션(무손실 + 멱등 + fixpoint 수렴) 진행 중,
HEAD(`fix/pull-resolution-fidelity` 분기점)에서 실데이터 fresh-user E2E pull 시
일부 회귀가 관측됐다. 마지막 정식 릴리스인 **v0.1.12** 와 비교해 "차라리 예전
버전으로 되돌리는 게 낫지 않냐"는 질문이 제기됐다.

결정의 핵심은 두 갈래다.

1. **롤백**: v0.1.12 로 되돌리고 거기서 다시 출발
2. **전진 수정**: 현재 HEAD에서 결함을 봉합하며 전진

## 결정

**전진 수정(fix-forward). 롤백하지 않는다.**

## 이유

git 고고학으로 두 버전의 실제 코드 상태를 비교한 결과:

1. **v0.1.12 는 더 위험하다.** v0.1.12 에는 이후 SYNC_FIDELITY 트랙에서 잡은
   **확정 데이터 손실 결함 4건**(결함5 frontmatter 유실 / 결함7 / 결함11 / 결함12)이
   그대로 살아 있다. 무손실 미션 기준에서 v0.1.12 는 "안전한 과거"가 아니라
   "치명적 손실이 미수정인 과거"다.

2. **관측된 회귀 3건 중 2건은 이미 HEAD에서 수정됨.** 롤백하면 이 수정도 함께
   잃는다. 남은 회귀(본 트랙의 M1~M5/cover-URL 등)는 국소적이고 봉합 가능한
   변환·후처리 결함이지, 구조적 붕괴가 아니다.

3. **롤백 비용이 과도하다.** v0.1.12 이후 누적된 **66 커밋 + 31개 테스트 파일**
   (디스커버리 비용상한, 토글/코드펜스 cascade 차단, 중첩 prefix 폭주 차단,
   링크드 DB graceful degrade, fixpoint 잠금 등)을 통째로 폐기하게 된다.

4. **전진 수정은 회귀를 영구 잠글 수 있다.** 결함마다 회귀 테스트를 추가하면
   같은 손실이 재발하지 않는다(측정 인프라 트랙). 롤백은 "지금 안 아픈 상태"로
   잠시 돌아갈 뿐, 손실 4건은 그대로 안고 간다.

## 대안 검토

### A: v0.1.12 전체 롤백

- 장점: 즉시 "관측 회귀 0" 상태로 복귀
- 단점: 데이터 손실 결함 4건 미수정 상태로 회귀, 66 커밋·31 테스트 폐기,
  이미 고친 회귀 2건 재유입 → **무손실 미션과 정면 배치**

### B: v0.1.12 에서 cherry-pick 으로 일부만 복원

- 장점: 회귀만 골라 되돌릴 수 있다는 발상
- 단점: 회귀의 원인이 단일 커밋이 아니라 변환 파이프라인 누적 개선의 상호작용 —
  cherry-pick 경계가 깨끗하지 않고, 결국 전진 수정과 같은 분석량을 요구

### C: 전진 수정 (채택)

- 장점: 손실 4건 유지 수정 + 회귀 영구 잠금 + 누적 자산 보존
- 단점: 결함별 근본원인 분석·테스트 작성 비용 (단, 1회성이며 회귀 방지로 회수)

## 트레이드오프

- 포기: "즉시 회귀 0" 의 단기 안도감
- 취득: 무손실/멱등/fixpoint 라는 목표 자체로의 수렴 경로, 회귀 재발 차단

## 영향

- 본 결정으로 충실도 회복을 **6-Phase 로드맵**으로 구조화(아래).
- Phase 1(Frontmatter/Relation 충실도)을 `fix/pull-resolution-fidelity` 분기에서 착수.
- 각 Phase는 결함 봉합 + 회귀 테스트를 한 묶음으로 커밋(GitHub Flow, dev 통합).

### 100% 완벽까지의 Phase 로드맵

| Phase | 범위                                                                 | 분기                                | 상태                      |
| ----- | -------------------------------------------------------------------- | ----------------------------------- | ------------------------- |
| 1     | Frontmatter/Relation 충실도 (M2/M3/M4 + cover-URL + relation 후처리) | `fix/pull-resolution-fidelity`      | 코드 완료·검증, 커밋 대기 |
| 2     | 본문 컨테이너 1급화 (#74 column/embed/button)                        | `feature/body-container-firstclass` | 대기                      |
| 3     | DB↔Bases 인라인 임베드 (#75)                                         | `feature/inline-db-bases`           | 대기                      |
| 4     | 충실도 측정 인프라 — 회귀 상시 잠금 (#77)                            | `feature/fidelity-metrics`          | 대기                      |
| 5     | 라이브 전수 검증 — fresh E2E (#66~68/70)                             | —                                   | 대기                      |
| 6     | dev→main 릴리스 + v0.2.0 태그 (#78)                                  | —                                   | 승인 대기                 |

"100% 완벽" 정의: 실데이터 복잡 코퍼스에서 Notion↔Obsidian 왕복이
**무손실 + 멱등(churn 0) + fixpoint 수렴**.
